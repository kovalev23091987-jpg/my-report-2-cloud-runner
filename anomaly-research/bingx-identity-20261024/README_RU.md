# BingX: идентичность, история и необходимые данные

Офлайн-предложение третьего исполнителя по прямому поручению владельца24.10.2026 через координатора. База: `373566cf2ce65f87d2e038da2407b60abb3578fb`. Рабочий чат: `01a14f2c-d037-7472-8f8f-76753a3a3bba`. Все изменения находятся в этой папке. Общий runtime не изменён; Node, imports, syntax checks, tests, provider HTTP, production SQL, CF, MAIN, Telegram и удаление данных — **0**.

## Что подготовлено

1. Три привязанных к точным исходникам предложения: существующие `market-contracts.mjs`, три выражения price/receipt и вызов истории в Worker, а также отказ старого читателя HTX при явной идентичности BingX. Полные предлагаемые тексты и точные diff лежат рядом. Это не новая база истории, не перенос старых строк и не внедрение.

3. `RETENTION_MATRIX_RU.md`: необходимые поля, окна, частота, срок пригодности факта и физическое хранение по действующим потребителям. Отдельно — защищённые доказательства и ограничения очистки.
4. `budget-model.json`: расчётные зависимости от неизвестного нового каталога, пределы упаковки и нужные измерения. Номинальный Paid и лимиты не объявляются свободным бюджетом.
5. **Один** callable `runBingxConsumerIdentityCase({repo_root})`, 18 контролируемых вариантов, **PREPARED_UNEXECUTED**. Он рассчитан на реальные применённые три target-файла с точными after pins. Автор его не импортировал и не запускал. Матрица хранения не получает отдельный тест.

## Передача интерфейса

Оригинал раннего SOURCE DTO сохранён побайтно в `SOURCE-interface.original.json.txt` (4567байт, SHA256 `8ddacaef39cc9cd5ed0b1b9d9bdef42172c9cc5ba9512c840f8ee9f7fd54dee1`). Его статус — OFFLINE_PROPOSAL_NOT_NATIVE_OR_MUTUAL_ACK. Официальные API проверяет SOURCE; этот пакет не делает независимого утверждения о фактическом каталоге или API.

Carrier ответа — `futures.data.instrument_identity`; независимое ожидаемое значение — `params.instrument_identity`. Обязателен явный `futures.data.venue='BINGX'`, даже при отсутствии DTO. Идентичность execution gate должна прийти от самого gate; копировать её из цены нельзя. Одинаковый тикер недостаточен. Семейства USDT_M/COIN_M разделены; размер/единица контракта, margin/settle, native ID и revision входят в корреляцию. `asset_binding` не превращается здесь в доказательство тождества токенов между биржами. После обычного чтения frozen SOURCE479d3990 принят финальный DTO4790байт/8daa2196; точная копия — `SOURCE-identity.final.original.json.txt`. Коррелятор требует CRYPTO_ASSET, отказывает PAXG/XAUT, сохраняет catalog payload hash и normalized token binding; canonical token epoch/scale входят в stable tuple. SOURCE модуль не импортировался и целиком не рецензировался. Revision обязан отражать изменение исходной квалифицированной связи, контракта или multiplier.

Нулевой `size` не становится единицей. Неизвестная quantity/contract-size допускает только цену в её исходной единице, но не подтверждение capacity. Нет подстановки received time вместо неизвестного source time. Результат корреляции явно содержит `native_identity_authenticated:false` и `cross_venue_equivalence_qualified:false`.

## Что остаётся координатору

SOURCE и THIRD одновременно предлагают разные участки Worker. Перед первым общим исполнением координатор должен собрать **один** окончательный Worker, сохранить прежние оригиналы и заменить after pins в согласованном callable на фактический общий текст. Несовпадение pin должно остановить исполнение; обходить его нельзя. Сам callable и его import closure также должны входить в frozen scope. Partial result сохраняется до последующего assert/следующего компонента; завершённые варианты не повторяются из-за поздней ошибки итоговых pins.

Нативные каталог, crypto eligibility (включая исключение золота и tokenized gold), units, source clocks, пригодность книги, прямой transport, generation/actor и реальные бюджеты квалифицирует координатор совместно с SOURCE. Сейчас неизвестно число пригодных BingX криптоперпетуалов и фактический охват. 105/122 — прежняя HTX конфигурация, не целевой размер BingX.

Guard `readMarketHistoryForContract` не закрывает другой читатель `readMarketHistoryTargets`, старый scan fallback, переезд таблиц/архива или strategy fact mapping. Прежний HTX execution gate не заменён и не может получить допуск только по новым метаданным. `owner-strategy-fact-mapping.mjs:40–42` всё ещё требует HTX. Guard отмены исходной задачи в `canonical-publication.mjs:102` относится к deferred ENTRY followup, а не ко всем новым публикациям.

Старая 16-cell anomaly/TG logging ждёт окончательного ТЗ владельца. ENTRY followup и физическая проверка хранения остаются отложенными. Стратегия, веса, формы, паузы, active pointers и общий main не изменены.
