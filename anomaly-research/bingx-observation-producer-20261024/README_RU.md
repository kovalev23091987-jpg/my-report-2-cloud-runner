# BingX: наблюдение, история и отдельные точки

Статус: текстовое предложение, PREPARED_UNEXECUTED. Основной runtime не изменён. Основа — пакет 636 (2561b720), Source assembler — bc5a4ea6. Пакет не подключает биржу и не разрешает торговые выводы.

bindBingxHistoryRegistry(ROOT_BINDING) создаёт закрытый контекст. resolveBingxExpectedHistoryRef({context,expected_identity}) выбирает текущий инструмент по полной независимо заданной identity. Координатор берёт её из собственного защищённого registry descriptor. produceBingxHistoryRow({observation,context,instrument_ref,processed_ts}) сверяет Source identity с этой привязкой и возвращает нормализованную строку. VERIFIED и хеш самого тела не заменяют независимую привязку. Контекст и ожидаемые значения нельзя принимать из публичного запроса.

Прежний packSnapshotShards получает source_observations:[{observation,instrument_ref}], history_context, processed_ts и исходные bucket/received_ts; rows при этом отсутствует. Сохраняются полный текущий cohort и прежняя упаковка. Путь готовых rows остаётся. Capture = max исходных component received_ts; часы цены — только last_price_source_ts. Текущее время не заменяет исходное. Обработка после границы исходного пятиминутного bucket помечается BACKFILLED_RESEARCH: это исследовательская метка, не новый срок годности или cadence. Время обработки отдельно; event_first_known_ts=NULL. Чтение с decision_ts раньше обработки отклоняется. Для повторного сохранения нужна та же неизменная строка: новый process clock в том же bucket может дать прежний IMMUTABLE_BUCKET_CONFLICT.

Source bc5a даёт last, OI с неизвестной единицей и funding с явными 8h. OI не переводится в contracts/base/USDT. Funding source_ts=NULL; native_update_time хранится отдельно и не становится часами цены или ставки. Turnover, BBO и свечи producer не выдумывает. Накопление, продажи и манипуляция не классифицируются. USDT_M — семейство API; quote/settle/margin раздельны, USDC не становится USDT.

readMarketHistoryTargets принимает history_reuse_key. Закрытая копия проверенных строк хранится в WeakMap. Публичные Map, JSON-копия, caller boolean и произвольный объект её не заменяют. readMarketHistoryForContract для BingX требует независимую identity/ROOT binding, тот же ключ, history_purpose:PRIMARY_MARKET_HISTORY и настоящий whole_history_result. Дополнительных SQL тогда нет. Без общего результата требуется allow_bounded_read:true; используется прежний bounded reader, максимум пять SELECT. Не давайте этот флаг всем монетам без общего чтения. Поддельный кеш не вызывает скрытый fallback.

Worker delta меняет только loadHistoryTargets и generic htxStage0History. ROOT передаёт уникальный ключ и отдельный env на текущую invocation: REPORT2_BINGX_HISTORY_READ_KEY, REPORT2_BINGX_HISTORY_BINDING, REPORT2_BINGX_CURRENT_HISTORY_RESULT. Разрешение отдельного SQL задаёт внутренний env REPORT2_BINGX_ALLOW_BOUNDED_HISTORY_READ. Общий env между запросами для кеша непригоден. Deep ещё содержит HTX-пути: ROOT добавляет ранний исследовательский BingX branch и NOT_CLOSED. ENTRY followup/recheck/TTL/native_task_readers пакет не подключает.

Индивидуальный ответ содержит до пяти target points (5m/15m/1h/4h/24h), исходные часы, bucket, gaps, cache_asof и возраст. В запросе 6h обычно четыре точки. Это не 20 закрытых свечей, не непрерывная шестичасовая история, не минутная глубина N05 и не доказательство NO_EVENT. Цена может быть пригодна при непригодном OI. complete_5m_window=false, native_billable_cost=NULL, first_known_ts=NULL; CONTROLLED case эти ограничения не меняет.

Расходы: общий проход <=5 логических SELECT; K индивидуальных ответов при reuse добавляют 0 SELECT вместо потенциальных 5K. Физические rows_read, план scan/index, wire bytes и цена D1 не доказаны. Прежний предел — 24 shard на target и 2 MiB суммарного полученного payload с остановкой ПОСЛЕ получения; это не гарантия памяти/сети до чтения. Закрытая копия добавляет второе представление payload и JS object/Map overhead. Фактический heap, CPU, пик concurrent runs и GC надо измерить ROOT до включения. Нового backend нет; WeakMap живёт в процессе, восстановление после рестарта — из прежнего хранилища. Свободный общий бюджет, резервы и Paid 48h/5/4/3.5GB доступными не объявляются.

Один новый callable описывает CONTROLLED assembler -> producer -> pack -> whole -> individual/reuse и два фактических Worker history regions. Фикстуры явно CONTROLLED; реальные котировки, каталог и документные тела в Git не добавлены. Внешний closure hash и writer даёт ROOT. В callable результат сохраняется до проверок и следующих зависимых шагов; при исключении сохраняется partial. Автор не запускал Node, import, syntax, тесты, provider, SQL, CF, MAIN или Telegram. Старые сценарии 636/Source повторно не вызываются. Central-bound COPY может перепривязать только closure к объединённому runtime; оригинал остаётся неизменным.

Сохранены формы основного отчёта и встроенный ликвидационный блок, девять пауз, стратегия/веса/70/лимиты/unknown/резервы и cursor710. Telegram/anomaly audit final TZ остаётся pending. Отложены ENTRY followup/recheck/TTL/anchors/native task readers и физические native storage tests. Подключение, доставка и внедрение не заявляются.
