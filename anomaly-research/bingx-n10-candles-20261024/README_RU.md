# N10: исходные object-candles BingX

PREPARED_UNEXECUTED. Пакет меняет только тексты предложений в собственном prefix. Действующий runtime, стратегия и формы не изменены.

Конкретный разрыв: buildHtxPrimaryTechnicalReceipt понимает HTX FULFILLED/MID и HTX channel/id, а ранняя ветвь BingX в buildDeepCheckInput возвращает раньше этого потребителя. Source bc5a уже умеет разбирать нативные object-candles, но его время ещё не квалифицировано как open-time. Простая замена имени биржи дала бы ложную полноту закрытых свечей.

Поправка добавляет BingX-ветвь в существующий primary technical receipt и реальный вызов в ранней ветви Deep. Используются прежний Source normalizeBingxCandles и закрытый контекст B04. Ожидаемая полная identity задаётся независимо от тела свечей. Разрешён только crypto perpetual с family USDT_M, quote/settle/margin USDT; USDC, COIN_M и UNKNOWN classification отклоняются. Это исполнение новой прямой команды владельца, которая уже старого текста AGENTS о двух семействах. Исторические возможности generic adapter не означают новый target.

ROOT передаёт две внутренние Map по точному instrument_ref: REPORT2_BINGX_N10_CAPTURE_BY_REF содержит полный raw_json и исходный receipt; REPORT2_BINGX_N10_EXPECTED_BY_REF — независимый pin original SHA, received_ts, endpoint, family, symbol, interval и window_start/end. Входы из публичных params не используются. Хеш вычисляется по полным исходным UTF8-байтам, затем проверяется receipt и вызывается существующий Source parser. Его usage_state/HTTP200 остаются метаданными; native admission из них не выводится. Предел 2MiB — только локальная остановка разбора входа, он не повышает provider/SQL/run limits.

Возвращаются полезные candidate OHLC/range, количество и непрерывность native grid, исходные native_time/десятичные объёмы и происхождение данных. derived candidate_end сохраняет условие IF_TIME_IS_OPEN_TIME. source_ts=NULL, first_known_ts=NULL, volume_unit=NULL; check_completed=false, evidence=[], all_candles_closed=false. Существующий N10 не получает score/entry или доказанного двадцатисвечного контекста. Ни шесть минутных строк, ни даже двадцать условных 4h строк не закрывают 80h без независимого доказательства значения time и фактической полноты закрытых окон. Поздняя обработка сохраняет original received_ts и явно отмечается research_backfill.

Новых reader-функций для сети, backend, схемы, SQL, cadence, хранения или ENTRY нет. Основной остаток Root Deep остаётся NOT_CLOSED. Старое HTX-тело primary receipt сохранено по байтам после входного venue-guard. Базовый Worker — ROOT647603B/4b066bbf из0c72; N10-модуль —33974B свежего main85e3. Один новый callable, десять вариантов, пока не запускался. Он использует настоящие Source и batch modules, извлекает точные тела существующего N10 export/локальной функции и реального Worker caller из pinned source. Полные Worker/technical module не импортируются; полной сборки/внедрения это не доказывает.
