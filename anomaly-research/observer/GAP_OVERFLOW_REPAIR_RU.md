Исправление ограничено существующим observer:

- Первые128 интервалов остаются без удаления, с прежними часами. Сам массив `gaps` не растёт сверх существующего `max_gap_spans`.
- После заполнения сохраняется дополнительная сводка из **шести полей**: schema, число не сохранённых подробно интервалов, первые/последние охватывающие часы, `exact_intervals_retained:false`, `bounds_scope:ENCLOSING_NOT_CONTIGUOUS`. Эти границы не означают один сплошной пропуск и не восстанавливают путь цены.
- Валидный текущий snapshot продвигает часы, next due и sampled extrema. Закрытая свеча может подтвердить текущий выход LONG либо SHORT по прежним правилам; transition остаётся `GAPPED_CURRENT_CONFIRMATION`, получает `gap_details_complete:false`, не разрешает вход и создаёт только прежний несетевой DRAFT.
- Результат операции явно помечает неполный журнал. Для каждого нового интервала вне capacity возвращается `unretained_gap`: точный интервал и `caller_owned_snapshot`. Это **не сохранённые моделью** подробности: `durable_ingress_required:true`, `native_ingress_qualified:false`. При подключении внешнего consumer понадобится его durable ingress с собственным admission/ACK. Пакет этого не реализует и не выдаёт временную переменную за постоянное хранение.
- Duplicate/conflicting/stale point обрабатывается до записи и не увеличивает overflow/count/outbox. Непрерывное наблюдение после overflow не создаёт искусственный новый пропуск. Невалидная свеча, часы или рынок не меняют входное состояние. Некорректную сводку нельзя молча обнулить.

Карточка, first_known_ts, evidence/discovery cohort, исходные proof refs, outcome links, второе событие, сохранённые интервалы и существующий outbox не переписываются. Формат полного состояния и checksum остаются прежними; новый optional watch field переживает serialize/restore. Сохранённый полный журнал без этого поля продолжает работу без миграции.
