# Изолированный прототип памяти и наблюдения

`observer.mjs` — чистый OFFLINE-модуль. Он не импортирует production, не читает сеть/БД/часы, не регистрирует задания и не отправляет Telegram. Его параметры ёмкости — ограничения исследовательского replay, не изменение лимитов проекта. Ни один основной файл не изменён.

На входе нужны предварительно проверенные exact instrument/native binding, рынок, upstream, контракт/multiplier/единицы, явный native UTC offset, closed OHLCV, raw-ref/hash и часы source-as-of/получения/первой осведомлённости. Модуль проверяет типы, сетку, геометрию, причинный порядок часов и полноту фона. Проверить, что hash действительно принадлежит provider body и binding независимо квалифицирован, обязан будущий источник: строка с хешем сама по себе этого не доказывает. Здесь нет provider adapter или доверенной production границы.

Детектор принимает15m/30m/1h/4h/1d/1w. По умолчанию нужен полный фон20свечей того же масштаба без разрывов. Используются объём/median/MAD, диапазон относительно фона, тело и обе тени. Эвристики3×/5×, body≤0.35/wick≥0.5 исследовательские и не калиброваны. Событие не получает торгового направления. Обе будущие гипотезы записаны заранее: закрытие выше high/ниже low исходной свечи, противоположное закрытие опровергает соответствующую гипотезу. Гипотеза после опровержения не переоткрывается задним числом. Это условия наблюдения, не основной ENTRY.

Карточка неизменяема по hash. event_id включает exact instrument/timeframe/native окно/rules; first_known_ts не меняется при повторе. Идентичный factual replay сохраняет исходную карточку; конфликт не перезаписывает её. `REPLAY` всегда BACKFILLED. `LIVE_CAPTURE` считается PROSPECTIVE только при явном классе PROSPECTIVE и лаге≤10минут; этот флаг нельзя принимать от недоверенного клиента без реального ingest ACK. Исторические/контролируемые данные не попадают в эмпирическую точность.

Очередь не знает MAIN top24/top2. Она пересматривает активные события от исходного anchor и хранит отдельные15m/1w события одной монеты. `dueEvents` сообщает deferred, oldest_due и отдельные prospective/historical lanes; нет удаления после7дней. Границы128active/512cards/128gaps прежние и относятся только к исследовательской памяти, не к native бюджету.

После доказанного backfill starvation `capture` по умолчанию записывает BACKFILLED карточку без активного наблюдения. Исторический card budget выводится из прежних пределов: max_cards−max_active, по умолчанию384, чтобы replay не занял все карточки раньше своевременных событий. PROSPECTIVE запрашивает watch сразу. Это разделение допуска модели, не новый алгоритм рыночного отбора или production admission. Историческое наблюдение возможно только явно через `{watch_mode:'HISTORICAL_REVIEW'}` либо `admitWatch(...,{mode:'HISTORICAL_REVIEW'})`; first_known/discovery/anchor не меняются и backfill не становится prospective. Когда active pool полон, но место для карточки есть, событие остаётся `RECORDED_WATCH_DEFERRED`; явный `PROSPECTIVE_RETRY` может занять освободившийся слот. Refuted watch не открывается заново.

Полный card space или backfill budget даёт `DEFERRED_CARD_CAPACITY`/`DEFERRED_BACKFILL_CARD_CAPACITY`, старое состояние не меняется. Ответ содержит **caller_owned_card**, исходные first_known/hash/raw-ref, `card_retained_by_model:false` и `durable_ingress_required:true`. Это не принятие в durable ingress: вызывающий обязан сохранить/повторить исходный payload, иначе он может потеряться. Модуль не хранит deferred payload вне пула, не вытесняет активные или защищённые карточки и не повышает лимиты. Pending watch внутри state также пока лишь память модели, не atomic native запись.

Пятиминутная цена обновляет только sampled extrema. Подтверждение требует отдельной закрытой свечи заранее выбранного timeframe с целиком пост-first_known окном. После пропуска сохраняется `GAPPED_CURRENT_CONFIRMATION`: текущее закрытие известно, своевременное наблюдение прошлого пути не доказано. Месяц без движения сохраняет активное событие. Проверка snapshot id/hash/монотонных исходных часов предотвращает повтор перехода на последнем снимке; более старые снимки не применяются. Input state не меняется при ошибке.

`serialize/restore` проверяет checksum и каждый card hash. Это доверенный model snapshot, не полная schema/authentication проверка и не доказательство crash-safe/атомарной записи D1. Старый snapshot восстанавливается без потерь, но новая обработка требует явного `upgradeLegacyMemory`: все прежние active historical/outbox/cards и caller outcome links остаются; overage/legacy active debt возвращаются явно. Старые активные события не очищаются для создания timely слота; при полном legacy пуле новое событие честно откладывается. При подключении нужны общая транзакция card+watch+transition+outbox, CAS revision, persistent readback, indexed due scan и crash/retry проверка. `protectedReferences` теперь консервативно защищает **все retained cards**, включая inactive backfill/pending watch/closed event с незакрытыми внешними исходами. Этот модуль не квалифицирует expiry; production retention hook не установлен. Поэтому насыщение остаётся реальным ограничением до отдельной полной квалификации хранения.

На каждый переход получается DRAFT outbox и короткий русский текст. Сеть всегда выключена; статусы/claim/ACK настоящей доставки не реализованы. Before-send crash и timeout-after-send требуют durable состояния UNKNOWN_SEND и сверки точного message_id; слепой повтор не гарантирует отсутствие дублей. Отправка и финальная форма отдельно принимаются координатором. Одно событие может дать разные transitions LONG/SHORT; группировку в одно короткое сообщение и pacing40мин должен квалифицировать renderer/outbox пакет.

Новые границы: `node --test anomaly-research/observer/backfill-admission.test.mjs`. Одиннадцать новых controls проверяют160event recipe, card budget, caller-owned defer, pending retry, explicit historical admission, immutable backfill, restart/outcome links, legacy debt и отсутствие неявного повышения лимитов при неполной legacy metadata.12 затронутых watch checks и один pending90d reference check проверены из-за изменения capture/protection; принятые detector suites и старые nonce6/protocol15 не повторялись. Детектор переиспользован в новом контрольном recipe, его код не менялся. Полный старый набор/retained CT/BR и исторический CPU benchmark не запускались повторно. Старые watch fixtures и benchmark теперь явно запрашивают HISTORICAL_REVIEW. Saved measured-scenarios остаётся прежним измерением старой памяти, а не измерением новой версии. Ни один положительный сценарий не выдаётся за predictive accuracy.

Статистика исходов/цензуры и модель ёмкости находятся в `../statistics`; их outcome formulas/anchors не изменены. Продолжительные реальные native candles/firstknown/полный postevent path остаются недостающими фактами; source acquisition делает только координатор.
