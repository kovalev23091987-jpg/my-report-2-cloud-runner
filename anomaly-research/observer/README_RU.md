# Изолированный прототип памяти и наблюдения

`observer.mjs` — чистый OFFLINE-модуль. Он не импортирует production, не читает сеть/БД/часы, не регистрирует задания и не отправляет Telegram. Его параметры ёмкости — ограничения исследовательского replay, не изменение лимитов проекта. Ни один основной файл не изменён.

На входе нужны предварительно проверенные exact instrument/native binding, рынок, upstream, контракт/multiplier/единицы, явный native UTC offset, closed OHLCV, raw-ref/hash и часы source-as-of/получения/первой осведомлённости. Модуль проверяет типы, сетку, геометрию, причинный порядок часов и полноту фона. Проверить, что hash действительно принадлежит provider body и binding независимо квалифицирован, обязан будущий источник: строка с хешем сама по себе этого не доказывает. Здесь нет provider adapter или доверенной production границы.

Детектор принимает15m/30m/1h/4h/1d/1w. По умолчанию нужен полный фон20свечей того же масштаба без разрывов. Используются объём/median/MAD, диапазон относительно фона, тело и обе тени. Эвристики3×/5×, body≤0.35/wick≥0.5 исследовательские и не калиброваны. Событие не получает торгового направления. Обе будущие гипотезы записаны заранее: закрытие выше high/ниже low исходной свечи, противоположное закрытие опровергает соответствующую гипотезу. Гипотеза после опровержения не переоткрывается задним числом. Это условия наблюдения, не основной ENTRY.

Карточка неизменяема по hash. event_id включает exact instrument/timeframe/native окно/rules; first_known_ts не меняется при повторе. Идентичный factual replay сохраняет исходную карточку; конфликт не перезаписывает её. `REPLAY` всегда BACKFILLED. `LIVE_CAPTURE` считается PROSPECTIVE только при явном классе PROSPECTIVE и лаге≤10минут; этот флаг нельзя принимать от недоверенного клиента без реального ingest ACK. Исторические/контролируемые данные не попадают в эмпирическую точность.

Очередь не знает MAIN top24/top2. Она пересматривает активные события от исходного anchor и хранит отдельные15m/1w события одной монеты. `dueEvents` сообщает deferred и oldest_due; нет удаления после7дней. При заполнении max_active/max_cards/gap_spans новый переход явно откладывается. Границы128active/512cards/128gaps — только выбранная вместимость памяти прототипа; реальная настройка требует нагрузки и admission. Непринятые новые задания должен сохранять внешний durable ingress, иначе deferral можно потерять. Сам модуль этого не делает.

Пятиминутная цена обновляет только sampled extrema. Подтверждение требует отдельной закрытой свечи заранее выбранного timeframe с целиком пост-first_known окном. После пропуска сохраняется `GAPPED_CURRENT_CONFIRMATION`: текущее закрытие известно, своевременное наблюдение прошлого пути не доказано. Месяц без движения сохраняет активное событие. Проверка snapshot id/hash/монотонных исходных часов предотвращает повтор перехода на последнем снимке; более старые снимки не применяются. Input state не меняется при ошибке.

`serialize/restore` проверяет checksum и каждый card hash. Это восстановление сериализованного OFFLINE-состояния, не доказательство crash-safe/атомарной записи D1. При подключении нужны общая транзакция card+watch+transition+outbox, CAS revision, persistent readback, indexed due scan и crash/retry проверка. `protectedReferences` выдаёт необходимые ссылки, но прямо помечает, что production retention hook ещё не установлен.

На каждый переход получается DRAFT outbox и короткий русский текст. Сеть всегда выключена; статусы/claim/ACK настоящей доставки не реализованы. Before-send crash и timeout-after-send требуют durable состояния UNKNOWN_SEND и сверки точного message_id; слепой повтор не гарантирует отсутствие дублей. Отправка и финальная форма отдельно принимаются координатором. Одно событие может дать разные transitions LONG/SHORT; группировку в одно короткое сообщение и pacing40мин должен квалифицировать renderer/outbox пакет.

Проверка: `node --test anomaly-research/observer/*.test.mjs`. Контролируемые случаи явно помечены:6масштабов, LONG/SHORT, red/green, future data, gaps, missing history/units, late/backfill, immutable firstknown, duplicate/conflict, несколько событий, defer/capacity, touch≠closed confirmation, delayed32d/90d, restart/outbox, retention references. Отдельные2теста на сохранённых оригиналах CT/BR проверяют новый отказ неполной карточки; accepted30x1m→3m/5m не повторяется. Ни один положительный сценарий не выдаётся за измеренную predictive accuracy.

Статистика исходов/цензуры, честное сравнение источников и обычная/пиковая ёмкость — следующий независимый пакет. Продолжительные реальные native candles/firstknown/полный postevent path остаются недостающими фактами; source acquisition делает только координатор.
