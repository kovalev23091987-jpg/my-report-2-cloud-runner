## Единственный путь

Существующий futuresTrajectory запрашивает HTX USDT-M history/kline period=1min. Существующий fetchJson фиксирует received_ts после headers, затем ожидает response.text(). После полного чтения он уже вызывает observeHtxAcquisitionAttempt. Этот observer хранит bounded requestReceipts.minutes; acquisitionClockDiagnostic передаёт attempt в raw_acquisition_diagnostic. Существующий buildHtxFlowClosureDiagnostic проецирует данные в source_diagnostic, затем существующие candidate-evidence-v2-runtime и block-decision-use-audit несут его в JSON отчёта. Нужны ровно три TEXT-цели: worker.js, htx-signed-tape.mjs, source-closure-diagnostics.mjs. Общие файлы автор не изменяет.

## Добавление

1. fetchJson фиксирует отдельный body_completed_ts непосредственно после успешного await response.text(), до JSON.parse. Поле не заменяет started_ts, received_ts, provider ts, parse-observed_ts, first_known_ts либо какое-либо время существующих фактов. При неоконченном/отказавшем чтении остаётся NULL.
2. Observer добавляет body_knowledge только к существующему точному HTX FUTURES 1min attempt. Старые metadata/trades и остальные маршруты сохраняются. Complete clock допустим только при safe integer started/header/complete и started <= header <= complete; legacy/плохой порядок не получают положительного знания.
3. SHA256 вычисляется существующим byteHash только по уже полученной строке, без новой загрузки/сохранения тела. Scope — SHA256_UTF8_RESPONSE_TEXT: это UTF-8 представление строки response.text(), не доказательство точных wire bytes, content-encoding или байтов до декодирования. Никакой canonical JSON reserialization. Размер нового хеширования <= 1048576 UTF-8 bytes; до вычисления byte length используется быстрый предел code units. Выход за предел оставляет digest/bytes NULL и явный status, не сокращает/изменяет тело для прежнего parser. Ошибка хеша не изменяет прежний исход fetchJson.
4. Память attempt содержит только clock, <=1048576 byte count, 64hex digest и фиксированные scope/status. Нет body, URL, headers, нового private payload, schema, helper, dispatcher или reader. Прежняя ёмкость eight-contract in-process map сохраняется; это не долговечная карточка события и не receipt с точным run/snapshot.
5. Существующий builder копирует лишь перечисленные типизированные поля в необязательный minute_body_knowledge; legacy/missing остаётся NULL. Future/неупорядоченный clock не получает валидный digest в carrier. Старый лимит diagnostic 2048 bytes не повышается. Если добавление не вмещается, опускается только новое поле; старый исход builder не превращается из объекта в NULL по причине добавления. Отсутствие поля — UNKNOWN, не успех. Исходный существующий oversized diagnostic по-прежнему NULL. Ручная форма и Telegram не меняются.
