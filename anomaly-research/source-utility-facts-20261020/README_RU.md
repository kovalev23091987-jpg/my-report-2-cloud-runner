# Полезность источника свечей: факты, доказательства и расходы

Подготовлен отдельный OFFLINE companion для оценки операционной полезности источника закрытых OHLCV. Существующий `sourceUtility`, основной runtime и веса остаются неизменными. Протокол зафиксирован коммитом `142bc4b7a9c5bda8611ba1aa84af09effec0d5fe` до реализации. Новый код и 17 связанных контролей локально не исполнялись. Пакет предназначен для одного следующего общего вызова координатором.

## Конкретные границы старого расчёта

Точный старый `sourceUtility` сохранён в `legacy-sourceUtility.before.txt`. Вход с неизвестным HTTP отбрасывается как invalid, потому что валидатор принимает только числовой целый расход. Стоимость непригодной по времени строки также исчезает из групп. Это не означает, что запрос был бесплатным.

Уникальный факт определяется сочетанием asset/role/raw_sha256. Поэтому новая служебная обёртка одной свечи может увеличить число фактов, а две разные свечи в одном ответе — схлопнуться в один факт. Повторное использование одной загрузки в двух ролях может дважды сложить её HTTP. Счётчики дублей и конфликтов одной attempt_id зависят от порядка `[A,A,B]` и `[A,B,A]`, поскольку после конфликта запись становится NULL. Это выводы по коду; вызываемый пример их ещё не исполнял.

Старый API не меняется: в нём есть принятые потребители и проверки. Companion отдельно проверяет эти новые случаи и не приписывает им нативный результат.

## Две независимые части учёта

Сначала строится журнал расходов по cohort/upstream/acquisition_id. Одна загрузка, обслуживающая несколько ролей или потребителей, учитывается один раз. Разные ссылки на доказательство сохраняются. Статусы MEASURED, UNKNOWN и NOT_ATTEMPTED описывают предоставленные утверждения об операции. Противоречащие утверждения одной загрузки дают конфликт стоимости. Расходы сохраняются и тогда, когда факт не проходит проверку инструмента, времени или чисел.

Отдельно группируются неизменяемые попытки по cohort/upstream/attempt_id. Идентичные повторы не увеличивают знаменатель. Несколько разных вариантов одной попытки дают один конфликт; счётчики повторов вычисляются по вариантам, поэтому порядок не должен менять результат. Ссылки конфликтующих попыток и хеши несвязанных утверждений стоимости возвращаются для сверки с исходным входом.

Уникальная экономическая единица — инструмент с явно указанной эпохой контракта и единицами плюс закрытое окно свечи. Роль и служебные поля ответа не создают ещё одну свечу. Цена и объём сравниваются по каноническим десятичным строкам, включая геометрию OHLC: без округления через IEEE Number. Поддерживаются ограниченные десятичные лексемы без экспоненты. Исходные доказательства и указатели строк сохраняются отдельно. Противоречащие OHLCV одной свечи цензурируются во всех её ролях; последний или наиболее выгодный вариант не выбирается.

## Когда факт пригоден

Нужны точные заявленные instrument/market/venue/upstream/contract/quote, price_unit, volume_unit, native_epoch и multiplier_decimal. SPOT и FUTURES с разными единицами не смешиваются. При неизвестной эпохе факт не допускается, но стоимость не удаляется. Это более строгий контракт для связанных фактов; он не ограничивает описательное исследование сохранённых рядов в PR577, где нативная эпоха заведомо неизвестна и карточки не создаются.

Сетка свечи задаётся явно: timeframe, alignment_offset_ms, start_ts/end_ts. Проверяется цепочка `end <= source_ts <= body_completed_ts <= available_at <= decision_ts`. Неизвестное время полного тела не заменяется заголовками или старым source_ts. Нужны связанное исходное доказательство/строка и заявленные exact_identity/fresh/numeric. Все эти декларации и самосогласованные хеши всё равно не аутентифицируют поставщика, инструмент, часы или нативный ACK.

## Что означают показатели

В каждой паре cohort/upstream возвращаются статусы попыток по ролям, отложенные admission, причины непригодности, объявленное и пригодное использование потребителем, разные связанные свечи, конфликты свечей и журнал загрузок. Число свечей между ролями не складывается; общий набор свечей и расходы пересчитываются отдельно. Распределение цены загрузки по ролям остаётся NULL.

Известные непротиворечащие расходы суммируются точно через BigInt и выдаются строкой `known_HTTP_lower_bound_decimal`. При UNKNOWN, конфликте, несвязанной записи стоимости или небезопасном преобразовании суммы в Number итоговый HTTP и отношение фактов к HTTP — NULL. При конфликте стоимости нижняя граница этой загрузки равна нулю, а не выбранному утверждению. Нулевая стоимость NOT_ATTEMPTED относится только к заявленному отказу до запроса. Она не доказывает свободный бюджет аккаунта. Цена повторного использования уже загруженного тела может быть нулевой только при явно переданном учёте загрузки.

CONTROLLED, RETAINED и DECLARED_PROSPECTIVE разделены. Глобальный итог между ними не вычисляется. Даже известный итог относится только к переданным утверждениям загрузок: полнота всех расходов провайдера, аккаунта и общего отчёта не доказана. Отношение свечей к HTTP — операционная плотность данных, может быть больше единицы и не является вероятностью успеха. Predictive accuracy, causal incremental value и независимое число наблюдений остаются NULL; разрешение активации и native authentication/ACK — false.

## Проверка координатором

Одна точка входа: `runSourceUtilityConnected({repo_root, legacy_root=repo_root})` из `connected.mjs`. Оба аргумента — полные checkout roots с `anomaly-research/**`. Перед импортом фиксируются SHA протокола, companion, старого sourceUtility, его префикса зависимостей и функции hash в observer. Точные старые helper/utility совпадают как в базе этой ветки, так и в frozen569. Изменения evaluator из569 не повторяются.

17 подготовленных групп проверяют: повтор доказательства/числовую нормализацию; общий запрос двух ролей; неизвестный расход; неизвестное время тела; отсутствие эпохи; поздний факт с сохранённой стоимостью; числовые ревизии; две свечи в одном теле; разные эпохи; spot/futures; порядок дублей/конфликтов; конфликт стоимости; несвязанное доказательство стоимости; отказ admission; разделение cohorts; точную геометрию больших десятичных чисел; переполнение числовой суммы HTTP. Все значения и доказательства генерируются как CONTROLLED. Даже пример с меткой RETAINED моделирует декларацию и не становится сохранённым рыночным наблюдением.

Вызов возвращает полный JSON-совместимый результат с новыми controlled свидетелями и старыми сравнительными выходами; файлы сам не пишет. Эти 17 групп не запускались и не считаются PASS. Координатор сохраняет результат одного нового общего случая. Старые принятые наборы, HTX37 квалификация/агрегация и BTC915 не повторяются.

Подготовка проверяется только по тексту, JSON, байтам и области файлов. Node/import/syntax/semantic/SQLite/provider HTTP/production SQL/MAIN/Telegram — 0. Реальное включение, native бюджет, веса, физическое хранение и отложенная владельцем ENTRY-цепочка этим пакетом не затрагиваются. Ограничение в 20000 входных строк не является измеренной границей CPU, heap или производительности native backend; передавать нужно компактные записи со ссылками на доказательства, не полные сырые тела.
