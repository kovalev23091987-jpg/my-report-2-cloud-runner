# Read-only review N12 provenance fix

Проверен **точный frozen head `290e5224a10652a8ab3a489752c06cefdee4e18e`**, base `03fafed3ef85e2e58f141b0fe6070fe3579a4490`. Проверяющий не менял shared-код.

Исправление закрывает обе потери из PR469: индивидуальная напечатанная внешняя N12-компонента сопоставляется с её исходной строкой, а EXTERNAL_N05_FLOW присутствует в supplemental accounting N12. `actuallyUsedIds` не расширен до любого отображения: для нулевого assessed факта остаётся требование existing assessment + isRendered. Отображение без assessment/review/score даёт rendered_fact_count, но used_fact_count остаётся0. Поддельного UNSCORED_DIAGNOSTIC не добавлено.

`contextComponentOrigins` получает **выбранные объекты строк**, а не все произвольные related IDs. Сохраняются provider/upstream/asset/contract/root/raw_hash и исходные source/observed/first_known/expiry. Отсутствующий window остаётся null/NOT_RETAINED; срок годности не выдан за конец полного торгового окна. `exactContextEvidence` применяет существующее ограничение source<=observed<=now также к присоединяемым строкам; чужие/непригодные/будущие строки не должны попасть в origin success. Конфликт представленных происхождений одного evidence ID помечен отдельно, его root не добавляется в exact roots.

`confirmedBlockContextFacts` по-прежнему заново строит факт из full canonical evidence и сверяет primary ID/root/label/value со stored supporting context. Additive поля не заставляют доверять сохранённым component метаданным. Старый compact APR/NEAR output не содержит таких исходных строк и не превращается в actual raw replay после исправления.

Manual и Telegram проверяются отдельно по существующему конечному тексту. Для plain Telegram удаление related ID при неизменном plain text исключает этот ID из представленности; direct/full fallback сохраняет все компоненты полной строки. Это консервативная проверка **зависимости существующего formatter output от компоненты**, а не новая модель влияния на рынок. Первичная evidence остаётся носителем строки. Существующие formatter функции не изменены; контроль single HTX + N05 4h показывает, что manual N05 не переносится в plain Telegram, который его не печатает. Payload не объявлен доставкой или message_id.

`matchesRendered` для N12 сверяет exact selected origin по ID/block/provider/upstream/asset/contract/metric, своим часам и root с текущей валидной строкой. Случайный related ID сам по себе не даёт отображение. `sourceRows` supplemental EXTERNAL_N05_FLOW дополнительно связывает captured source row с финальной N12 строкой по полям происхождения, raw_hash/value/coverage и root. N05-факт остаётся N05. Обязательный `all:['HTX_LARGE_TRADES']` не ослаблен. Planner/collectors не менялись; добавленный check — второе accounting представление уже существующего envelope, не дополнительные HTTP. Оригинальный shared attribution остаётся прежним.
