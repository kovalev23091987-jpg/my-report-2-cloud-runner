Новые контрпримеры выведены по коду и ещё не исполнены. Прежний registerRevision сравнивает только текущую свечу, единицы и multiplier. Изменение20 фоновых свечей может заметно изменить volume_ratio, но оставаться PROVENANCE_REVISION с conflicting_native_facts=false. Если сохранён прежний declared proof key, та же новая representation вообще считается DUPLICATE_REVISION. Это не найденная правка реального provider body: исходный BTC sample неизменен, изменения фона и новый declared body hash в callable явно CONTROLLED. Случай того же declared hash моделирует несогласованную интерпретацию, а не утверждает, что у настоящего hash изменились bytes.

Добавляется один приватный detectionBasis: timeframe/grid, текущие и фоновые start/end/OHLCV, price/volume units и multiplier. Он не включает receipt time, raw locator или first-known. Исследовательский rules_hash не превращается в новую native фактическую цену. Старый canonical_fact_hash не переписывается. Новые revision keys имеют версию PROOF_REFERENCE_V3_DETECTION_BASIS; новые metadata сохраняют basis hash. Canonical card, logical identity, canonical first-known и старые revision keys/refs остаются прежними. Разный материальный фон поднимает существующий признак конфликта, не создаёт независимое событие и не выбирает позднюю удобную статистику.

Legacy dedup учитывает полный исходный card hash либо basis, который можно вывести из полной canonical card. Для старой неканонической revision без basis частичного tuple недостаточно. Когда caller повторно предоставляет именно полный card с тем же сохранённым card_hash и proof/qualification refs, registerRevision может добавить к этой старой строке локальный detection_basis_hash без нового revision slot и без переписывания key/first-known. Статус LEGACY_BASIS_RETAINED не означает native qualification. Более поздний first-known или похожий факт не подменяют точное полное тело старой карточки.

При полном revision pool новая материальная коллизия больше не оставляет видимость согласия. Сохраняется только уже существующий latched conflict flag; revisions не расширяются и не вытесняются. Возвращаются caller_owned_card/qualification, revision_retained_by_model=false, durable_ingress_required=true, native_ingress_qualified=false. Детали должен удержать caller. Это не durable ingress, не запись в БД и не ACK. Полный pool при обычной новой provenance-ссылке с тем же материалом сохраняет прежнее поведение.

confirmationVerdict получает optional logical_event. Если он передан, проверяются logical native epoch key, точная canonical card, canonical first-known, существующий material hash и отсутствие неразобранного конфликта. Все revision basis должны быть известны из metadata или полного canonical card hash; иначе LEGACY_REVISION_BASIS_UNRESOLVED. Без аргумента остаётся прежний API и прежний результат; он не получает задним числом привязку к registry. logical_event_state_checked и registry_state_is_not_native_ACK обозначают локальную проверку модели. Они не являются proof token, аутентификацией, native grid/ingress/commit ACK или допуском к реальной торговле. Перед production потребитель должен получать доверенное полное состояние registry; caller flag и self-consistent JSON для этого недостаточны.

Registry сохраняет refs и hashes, а не полные тела всех последующих карточек. Новый basis hash не заменяет сохранение исходного body и полных derivation inputs внешним trusted ingress. Union старых proof refs и существующий конфликтный признак не объявляются полнотой native reference graph или разрешением очистки. Функция retentionDecision, физическое хранение и их проверки не меняются и не выполняются.
