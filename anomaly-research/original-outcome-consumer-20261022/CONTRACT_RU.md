# Фактические исходы исходного плана

Конечное поручение ROOT22Oct: заполнить только PENDING исходы существующего ORIGINAL_EVENT_END плана по уже имеющемуся полному закрытому окну. Файл runtime — только `src/anomaly-native-due-watch.mjs`. Kernel, runner, Worker, schema, assembler, caps и sender не меняются. Автор не выполняет Node/import/syntax/tests/SQL/SQLite/semantics/provider/native/MAIN/Telegram. Принятые61133 и старые компоненты не импортируются и не повторяются.

Окончательный согласованный API — `PER_CELL_V1_16`: SOURCE `capturedOriginalOutcomeWindows({origin,now_ts})`, export в том же файле. Outer status CAPTURED_ORIGINAL_OUTCOME_WINDOWS_V1; точные logical_event_id/revision/card_sha256/descriptor_sha256/plan_sha256/first_known_ts/now_ts; quote USDT, price_unit HTX_NATIVE_LINEAR_PRICE; body/source/received/completion/metadata clocks и SHA;16 cell windows с original key/direction/horizon/target. Complete cell содержит точные start=event_end/end=target, полный count минут, first_open/last_close/high/low и stable window_sha256. Deferred cell содержит причину и NULL факты/счётчики, не наблюдавшийся ноль. Максимум2000 capture rows/16384bytes DTO. Summary SHA связывает id/revision/три immutable SHA/windows/units. Provenance SHA хранится отдельно от экономического window SHA. SOURCE case проверяет projection; THIRD case проверяет фактическую интеграцию ORIGIN/COMMIT.

Anchor берётся только из неизменной card: `card.anchor.price === card.candle.close > 0`, `card.anchor.source_ts === card.event_end_ts`. Другой anchor не создаётся. Для A=anchor, C=last_close, H=high, L=low и знака s=+1 LONG / −1 SHORT: directional_price_return_pct=s*100*(C/A−1); MFE=max(0,s*100*(H/A−1),s*100*(L/A−1)); MAE=min(0,s*100*(H/A−1),s*100*(L/A−1)). Реальное неизменившееся значение может дать0; NULL не заменяется0. Не конечная/непредставимая арифметика откладывается. Это два направленных представления одной ценовой истории, не две независимые выборки и не торговый PnL.

Только mature target с полностью закрытой minute grid от ORIGINAL_EVENT_END до EXACT target может стать CLOSED_FACTUAL. Статус не означает SUCCESS/UNWORKED/FALSE/OPPOSITE, цену исполнения, прибыль, причинность или точность. Intrabar order всегда UNKNOWN. Исторический конец окна не переименовывается во время свежего ответа; доступность тела и исходное время факта различаются. Backfilled карточка не становится заранее обнаруженной.

Ранее CLOSED_FACTUAL/CENSORED_FINAL копируются без изменения. Смешанные или противоречащие уже сохранённому фактическому окну сведения не закрывают оставшийся PENDING. Pending closure обрабатывается до выхода для inactive watch; новая watch/уведомление не выдумывается. При новом factual knowledge выполняется та же одна ORIGIN→WRITE→READBACK операция с текущей revision; без новых фактов нет новой revision/opid. Watch по существующему observe может продвинуться независимо при своём подтверждённом входе. Исторический исход не меняет last_snapshot watch на старую цену.

next_check_ts — минимум remaining PENDING targets и действующего active watch due. Missing/stale/unbound/conflicting/truncated/uncovered остаются PENDING с typed DEFERRED; семь дней и заполнение не удаляют событие. State65536/revisions32/outbox32/request131072/defaultOFF/perIOparent/day/statistics/unknown/finalizer сохраняются; overflow сохраняет старую строку целиком. Нет новых HTTP/readers/cursor fairness/TTL/pending backend/sender. SOURCE and THIRD готовят только конкретные TEXT и один новый affected callable каждый; ROOT один выполняет новую общую проверку после exact pins и static peer.
