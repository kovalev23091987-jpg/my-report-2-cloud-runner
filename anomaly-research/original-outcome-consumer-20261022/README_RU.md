# Передача координатору: фактические исходы исходного события

Пакет предлагает заполнение существующих 16 ячеек ORIGINAL_EVENT_END по тому же завершённому HTX capture. Рынок — фьючерсы HTX linear USDT; спот не требуется. Полные закрытые минутные окна дают фактический направленный возврат цены, MFE и MAE от неизменной цены закрытия исходной свечи. Никакой исход не получает оценку успешности, прибыльности, точности или причинности. LONG и SHORT описывают одну историю цены.

Единственный runtime target — существующий `src/anomaly-native-due-watch.mjs`. `evaluator.proposed.txt` добавляет чистую оценку и отделённое продвижение действующего наблюдения; `prepare.proposed.txt` заменяет только существующий prepare. `consumer-without-source.proposed.mjs` — полная THIRD-only версия для сверки текста, ещё без согласованной функции SOURCE. `target-pins.json` задаёт точный состав общего файла с SOURCE `capturedOriginalOutcomeWindows`; никакой новый runtime module или assembler не создаётся.

Отсутствие окна, пробел, устаревший capture, несовпадение рынка или материала, неполный DTO, противоречивый якорь и непредставимая арифметика сохраняют PENDING. Уже окончательные ячейки сохраняются полностью; оставшийся направленный исход того же окна не закрывается по противоречащей или недоказанной прежней фактической записи. Неактивное наблюдение не мешает закрыть пригодный исход. При таком закрытии прежние last_snapshot и DRAFT не заменяются исторической ценой. Новая revision возникает только при новом факте исхода либо принятом существующей watch новом факте; повторное тело ответа само по себе не создаёт revision.

`next_check_ts` — минимум оставшихся PENDING целей и существующего due активной watch. Неактивная watch без PENDING может иметь NULL. Нет удаления, семидневного TTL события, сброса unknown, отказа от записи прежних фактов или повторной отправки. Пределы state/revisions/outbox/request, действующий admission на каждый I/O, отдельные дневные и HTTP бюджеты, default OFF и finalizer остаются прежними.

`connected.mjs` экспортирует один новый callable `runOriginalOutcomeConsumerConnected({runtime_root,baseline_runtime_root,repo_root})`. Он сначала связывает все 618 файлов двух фактически собранных деревьев, 617 неизменных файлов, полный новый target, точную функцию SOURCE, текущую production parent capability и реальные зависимости. Затем использует настоящие DUE/ORIGIN/COMMIT/READBACK SQL через текущий RemoteD1 adapter в контролируемую SQLite. Извлечение текущей функции parent — только зависимость проверки; прежние тестовые exports не импортируются и не вызываются. Все runtime импорты и SQLite выполняет только координатор при одной новой общей проверке.

Одиннадцать новых групп: старый inactive PENDING против нового factual COMMIT; наблюдавшийся ноль; четыре точных горизонта без подглядывания в следующий хвост; missing/gap/stale/material/truncated; подмена DTO; самосогласованный по хешу, но неверный якорь; сохранение окончательных исходов; восстановление и повтор тех же фактов; совместное продвижение watch и исходов в одной операции; пределы; неизвестный результат записи с сохранением той же effective prepared операции. Кратность отдельных вариантов указана в результате callable.

Автор выполнил только чтение и работу с текстом/хешами/Git. Node, импорт приложения, syntax check, SQL/SQLite, семантика, старые проверки, provider acquisition, native, MAIN, deploy и Telegram — 0. Это предложение и новая ещё не выполненная проверка. Не внедрение и не подтверждение наличия общего свободного бюджета. Семантические результаты вписывает координатор отдельно после общего запуска, не изменяя авторский frozen пакет.
