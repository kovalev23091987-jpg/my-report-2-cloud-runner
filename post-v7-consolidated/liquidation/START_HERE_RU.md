## Что подтверждено

Два повторных прогона из чисто скопированной переносимой папки: **204/204 проверки расширения и интеграции**, отдельно **33/33 сохранённые проверки публикации и доставки**; Node v24.21.0. Первоначальное исследование и негативные тесты до исправлений сохранены, не выданы за текущую успешную версию.

Проверена настоящая цепочка доставки в изолированной среде: сохранённые ответы источника → общий аналитический результат → SQLite-публикация → очередь → фактический код отправителя → локальный HTTP-приёмник. Ручной отчёт читает эту же публикацию. Условия сделки в этих тестах явно искусственные; рыночные ответы взяты из сохранённых реальных проверок. Это не подтверждение торговой идеи и не сообщение пользователю.

Код нового сбора теперь встраивается поверх точных worker и runner единого post-V7 candidate. Исходная запись `persistCanonicalSnapshot` сохранена: новые данные не ограничиваются отдельным журналом наблюдений. Источник, валюты, время и ограниченная полнота карты доходят до ручного отчёта и отправителя. Повторная отправка, устаревшие уровни, отсутствие сохранённой перепроверки, изменение снимка и неподтверждённая запись блокируются.

Дополнительные десять негативных проверок: пустая/устаревшая/ошибочная основная выборка не считается готовой картой; допускается отдельная разрешённая проверка резервного источника; сбой резервного источника не уничтожает уже полученные пригодные основные данные. Порог выбора кандидата не обходится.

На отдельной облачной тестовой D1 проверен SQL именно активного `d1-source-admission.mjs`: первая операция резервирования двух источников — 8 чтений и 8 записей с индексами; повтор идентичного записывающего пакета — 6 чтений и 0 записей. Это не измерение полного рабочего цикла и не изменение production-базы.

## Как повторить проверки без обращения к рынку и без отправки в Telegram

Из этой папки, Node 24:

```sh
node verify-handoff.mjs
cd liquidation-extension
npm ci --ignore-scripts --no-audit --no-fund
node verify-all.mjs
```

`verify-handoff.mjs` проверяет целостность исходного архива по хешам. Проверять его до запуска тестов: тестовые генераторы затем создают свои локальные результаты в `.verification`, `integration/proof` и `validation-runs`.

Повтор тестов не делает рыночных запросов и не пишет в облачную рабочую базу. Локальные HTTP-приёмники слушают только `127.0.0.1`.

Не запускать `probe*.mjs` автоматически. Последняя повторная попытка обновления живых источников была заблокирована ограничителем инструмента; она не выполнена и не засчитана как новое доказательство. Не обходить ограничение. Предыдущие подтверждённые исходные ответы и их времена сохранены.

Не применять `integration/patch-current-runtime.mjs` как финальную альтернативу: он сохранён как прежний исследовательский вариант поверх production, а не как текущий путь объединения. `apply-after-unified.mjs` откажется работать по старой production-базе или изменённым файлам.

Ни один скрипт этого архива не выполняет promotion, не обновляет main, не меняет расписание, получателей Telegram, веса анализа или торговые разрешения. Новый режим пока по умолчанию отключён. Его название SHADOW_ONLY не означает «навсегда только внутреннее наблюдение»: после разрешённого включения он поставляет контекст в общую публикацию, но не получает полномочий на автоматическую торговлю.

## Что ещё обязательно завершить перед рабочим включением

- Полный импорт всех модулей runtime и весь наследуемый CI, а не только восстановленных публичных модулей. В текущей исследовательской сборке есть не все зависимости зашифрованного runtime. Не менять hash guards для обхода этого условия.
- Общая проверка остатка бесплатных квот и конфигурация источников; пустые таблицы разрешений не дают права на запросы. Не считать локальные пилотные лимиты договорной квотой поставщика.
- Суммарные затраты рабочего цикла, сохранения публикации, downstream и нового сбора; только один планировщик существующей аналитики.
- Получение свежего авторизованного ByKaranteli ответа через существующий защищённый маршрут без чтения ключа; проверка схемы и пригодных уровней.
- Lighter/GMX: точность времени, покрытие и допуск в конечный потребитель ещё не закрыты. 0xArchive: самостоятельный ключ runner и стоимость именно нужного маршрута ещё не подтверждены.
- Нативные уровни другой площадки не становятся HTX-целями только по совпадению тикера. Проверить идентичность/множитель/валюту/ценовой базис; не изобретать торговые цели и не менять веса.
- Контрольный запуск без Telegram, затем изолированная проверка реального внешнего маршрута, управляемое включение и естественный плановый запуск с readback.

Полная карта всех позиций всего рынка не заявлена. Временное отсутствие пригодного источника остаётся отсутствием данных, а не «достоверно нет зон».
