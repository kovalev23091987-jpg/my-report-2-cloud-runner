Работа продолжает подготовленное бесплатное ликвидационное расширение, а не заменяет V7.

### 1. Исправлен разрыв раннего отображения

Фактический pump-liquidation-zones.mjs возвращал NOT_APPLICABLE при суточном росте ниже 20%. Реальные canonical-runtime-adapter и оба его formatter показывали ликвидационные секции только для пампа.

В staging-копии четырёх точных файлов добавлен отдельный scoped native liquidation context. На сохранённом native FIL-снимке и тестовом параметре суточного изменения +2% уровни проходят в настоящий canonical result и оба настоящих compact/manual formatter. +2% — параметр регрессионного теста, не заявление о текущем рынке FIL.

Подтверждены: один analytical_fingerprint для обеих форм; сохранение source time отдельно от конечного as_of; подпись Hyperliquid FIL и нативной единицы USDC; отсутствие пересчёта score, направления, Hard Gates, entry или targets. Без нового acquisition output полностью совпадает с прежним.

### 2. Acquisition вызывается до фиксации окончательного времени анализа

Подготовлен guarded hook в реальном worker.js перед существующим now = Date.now(), после основного сбора фактов и до Opportunity/canonical. Новый сборщик не запускается вторым планировщиком и не приклеивает более поздние уровни к старому снимку. Без внедрённого service binding hook ничего не делает.

### 3. Реализован прототип атомарного бюджета через интерфейс действующего D1-адаптера

Квота резервируется сразу по запуску и двум источникам. Одного разрешённого источника недостаточно, если второй лимит исчерпан. Повтор, в том числе с тем же nonce, не разрешает второй сетевой запуск. Потерянный ACK не превращается в разрешение повторно тратить лимит. Ошибка SQL откатывает весь batch.

Проверка использует неизменённый RemoteD1Database проекта и тестовый HTTP bridge к локальной SQLite. Это доказательство интерфейса и транзакционной логики, НЕ замер настоящих D1 rows_read/rows_written и НЕ production D1 proof.

Создана только candidate-миграция двух пустых таблиц. Она нигде в production не выполнялась. Пустые/просроченные/неподтверждённые квоты не разрешают запросы. Сервис требует внешнюю проверенную D1-cost admission; не расширяет лимиты сам.

### 4. Guarded patch

Проверяются точные SHA файлов и уникальные anchors; весь подготовленный JavaScript проходит syntax check до записи. При ошибке записи предусмотрен возврат backup. Повтор разрешён только при совпадении всех хешей уже изменённых и новых файлов. Смена базы или изменение staged-файлов приводит к отказу.
