# Мой отчёт 2 — усиление ликвидационных карт, 27.09.2026

Статус: **исследование расширено, новый сборщик и адаптеры проверены отдельно; к рабочему отчёту НЕ подключены; production НЕ изменён**.
Это продолжение текущей ликвидационной задачи, не новая версия проекта и не установщик V7.

## Реальный результат этого этапа

Добавлены исследовательские адаптеры Lighter, GMX и LiqFlow; проверены дополнительные прямые и on-chain пути. Подготовлен и фактически запущен новый бесплатный сборщик: LiqFlow обнаруживает публичные счета, Hyperliquid возвращает их собственные liquidationPx. Модельные цены LiqFlow не используются как нативные цены биржи.

Живой запуск FIL: 10 HTTP-запросов, включая справочник инструментов; 8 ответов аккаунтов; 7 положительных liquidationPx; 1 отсутствующая цена сохранена как неизвестная. Время работы именно сборщика после справочника — 1290 мс в исследовательской среде. Это единичное измерение, не обещание производительности. Выборка неполная, преимущественно крупных счетов; полная карта рынка не доказана. Большинство полученных Short-уровней далеко от рынка, поэтому наличие ответа не означает близкую торговую цель. Все уровни имеют нативную площадку, а не выдаются за уровни HTX.

Самостоятельный пакет: **87/87 тестов PASS на Node v24.21.0**. Это тесты данного расширения, не наследуемый полный CI проекта. Повторное воспроизведение сохранённых gTrade-ответов и локальная SQLite-запись/readback проверены. Настоящие D1, GitHub Actions и действующие manual/Telegram formatter/sender этими тестами НЕ проверены.

## Более сложные бесплатные пути

**Собственная выборка позиций вместо покупки готовой картинки.** Индексатор нужен для поиска адресов/индексов; окончательные уровни берутся у нативной площадки. Это уже реализовано и живьём проверено для LiqFlow → Hyperliquid. Для Lighter есть прямой доступ к счетам с нативными liquidation_price, для GMX — read-only позиции/Reader. Публичные сделки, индексы и позиции не являются пользовательским торговым аккаунтом; торговые вызовы в коде запрещены.

**Jupiter Perps через Solana RPC.** Разобраны документация и опубликованные примеры чтения Position-аккаунтов и fee-aware расчёта. getProgramAccounts может вернуть огромный массив, а закрытые счета остаются с sizeUsd=0. Нужны фильтры, актуальная IDL, custody/oracle, slot-binding и подтверждённая бесплатная RPC-квота. Живое получение полной карты не доказано; в рабочий запуск не добавлено.

**dYdX.** Документированы публичные account/subaccount/position API. Для полноценной карты нужен discovery счетов и учёт всей кросс-маржинальной структуры, а не только одной позиции. Новая карта по dYdX в данном пакете не реализована.

**Drift/Velocity.** Документация и программы менялись; новую программу нельзя молча считать старым Drift. Этот путь оставлен отдельной проверкой identity/program/state.

**Собственная полная нода/постоянный WebSocket-индексатор.** Может расширить покрытие, но бесплатный доступ к данным не делает сервер, диск и непрерывный сбор бесплатными. Тяжёлую ноду нельзя объявить бесплатной установкой на имеющемся Cloudflare. Requester-pays S3 также не включается в бесплатный маршрут. Непрерывный recorder имеет смысл только при подтверждённой инфраструктуре, а не через бесконечный GitHub job.

## Что удалось обнаружить и исправить в новых адаптерах

1. В LiqFlow найдено расхождение модели с последующим native account read. Времена отличаются, поэтому доказательства ошибки при одном и том же состоянии нет. Пока его собственные ценовые корзины имеют статус RESEARCH_MODEL_NATIVE_VERIFICATION_REQUIRED. Не усредняем их с официальными ценами.
2. На сыром API LiqFlow одна корзина 629999.02 совпала с размером позиции × mark = 629999.01696. Нельзя умножать эти цифры ещё на миллион из-за единиц, описанных для визуального интерфейса. Сохранён unit-proof; он не доказывает всю методику поставщика.
3. Нулевой liquidation_price Lighter и null Hyperliquid не превращаются в цену 0 и не заменяются формулой по плечу.
4. В GMX sizeInUsd и positionValueInUsd различаются: для экспозиции используется размер позиции, а не остаток стоимости/маржи.
5. В gTrade positionSizeToken × index сначала даёт величину в залоге. Для WETH нужен ещё перевод залога в USD. На это добавлен отдельный regression test.
6. Last transaction / increasedAtTime не выдаются за время снимка; отсутствующий source timestamp остаётся отсутствующим.
7. Разные валюты USD/USDC/USDC_REPORTED не превращаются молча в одну единицу. Готовое преобразование цены в HTX USDT не заявлено.
8. Повтор одного receipt не удваивает карту; провайдеры одной площадки не становятся независимыми голосами. Исчезновение корзины не является доказательством ликвидации.
9. Идентичность contract/direction/run/snapshot/as-of/fingerprint проверяется при записи и чтении. Zero-row dedup не объявляется новой успешной записью.

## Ограничения и план нагрузки

База планирования: существующие 120 запусков в сутки; для 31-дневного месяца один дополнительный запрос на каждом запуске = 3720 запросов. Это арифметика планирования, не измеренная будущая нагрузка. Источники опрашиваются только для отобранных кандидатов и поддерживаемых площадок, а не для каждой монеты и каждого плагина.

| Путь | Предлагаемая работа | Оценка для 31 дня / защитное условие |
|---|---|---|
| LiqFlow discovery | До одного запроса на отобранный deep-check; справочник кешируется | До 3720 таких вызовов; pilot-cap всего модуля 12000. Документированный free 50000 общий для сервисов, нужен учёт других потребителей |
| Native Hyperliquid | Обычно 4 счёта, максимум 8 при наличии бюджета | 14880 чтений при 4 счетах на каждом запуске; pilot-cap 30000. Не обещается перепись всех кошельков |
| Lighter | 2–4 счёта и ограниченный discovery | До примерно 18600 вызовов при 5/запуск; pilot-cap 24000 и не более 20/мин, ниже Standard 60/мин |
| GMX | Discovery кешируется; максимум 2 счёта; частота ограничена | Pilot-cap 8000; пакет из 3 вызовов через запуск даёт 5580. Другие сети пока не включены |
| gTrade | Одна общая цепочная загрузка на все нужные монеты; только по необходимости | 3 запроса на пакет; pilot-cap 4000. Это лимит исследования, не тариф поставщика. Старый пакет не выдаётся за свежий; перед решением требуется новая загрузка |
| HyperPerps | Общий BTC/ETH/SOL контекст + адресные свежие проверки | Pilot-cap 6000; лишнее повторение той же площадки не считается подтверждением |
| 0xArchive | Адресный резерв, без регулярного запуска до проверки стоимости | Pilot-cap 5000 кредитов, точная стоимость запроса пока unknown → автоматический вызов запрещён |

Лимит расширения — до 24 новых запросов за весь существующий запуск, одновременно не более двух, до 45 секунд на живую проверку. Это не новая квота проекта и не разрешение автоматически расширить старый общий бюджет: включение требует сверки с оставшимся ресурсом runner. Функции проверки бюджета и атомарное резервирование продемонстрированы в **локальной SQLite**, а не уже введены в production D1.

Лимиты не суммируются как обещание использовать все источники одновременно. При нехватке квоты откладывается некритичная проверка; старые данные не освежаются искусственно. HTTP429 сохраняет Retry-After. Неизвестная premium-стоимость и несверенный остаток общего аккаунта блокируют автоматическую загрузку. Автопокупки и обходы ограничений отсутствуют.

## Хранение и вычисления

Cloudflare D1 фактически прочитан только через GET метаданных 27.09.2026 07:03:30Z: 199995392 байт, production, изменений нет. Free D1 ограничивает одну базу 500 MB, хотя общий лимит аккаунта 5 GB. Поэтому сырые многомегабайтные снимки кошельков не должны попадать туда на каждом цикле.

Подготовлен компактный контракт до 8 KiB. Проверенный live FIL контекст занял 2018 байт без потери выбранных ближайших/крупных/дальних уровней и происхождения. Пример потолка: 2 компактных записи × 120 запусков × 7 дней × 8192 байта = 13762560 байт полезного JSON, без SQLite/D1 индексов и служебных расходов. Сроки hot-хранения и сжатой истории — предложение, не выполненная очистка данных. Старую свечную память 30–60 дней этим модулем не меняли.

Полные исследовательские ответы хранятся в отдельном evidence-архиве. Для постоянного архива можно рассмотреть R2 в пределах бесплатных квот, но его наличие/настройка не заявлены. При отсутствии архива система не должна ложно обещать полный 60-дневный raw replay.

Тяжёлые декодирование и SDK-расчёты размещаются в существующем Node-runner, а не в бесплатном Worker с малым CPU-бюджетом. GitHub-репозиторий проверен как public; стандартные hosted runners для public бесплатны, но artifact storage и общий ресурс всё равно ограничены. Сырые ответы платформа-провайдеров не следует публиковать в открытом репозитории без проверки прав на распространение.

## Как встраивается в один отчёт

HTX-отбор → admission по оставшемуся бюджету → discovery/чтение → native verification → проверка времён/units/схем → отдельные provenance-слои → один ограниченный liquidation context → canonical analytical result → существующие manual/Telegram.

Правила включения: NEW_SOURCES_SHADOW_ONLY сначала; существующие веса, Hard Gates, формат, подписчики Telegram и расписание не меняются. Ни наличие карты, ни крупная сумма не создают ENTRY. Cross-venue цена остаётся родной цене площадки, пока не закрыт identity/quote/basis-контракт с HTX. Инструменты типа kPEPE требуют доказанного множителя; совпадение строк тикера недостаточно.

Следующие незакрытые точки: реальная проводка к существующему runner и canonical consumer; проверка защищённого ByK payload; global/shared quota и D1 reservation; перевод нативных уровней в допустимый HTX-контекст; candidate CI полного проекта; controlled smoke без Telegram; проверка обеих настоящих форм выдачи. Затем — один совместимый candidate-пакет, не запуск старого incomplete installer.
