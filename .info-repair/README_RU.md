# «Мой отчёт 2»: Telegram Informational Repair R7

Пакет исправляет подтверждённый сбой R3 `RESERVATION_CONFLICT_WITHOUT_ROW`. Причина: R3 пытался записать категорию `FINAL_CHAIN_CANDIDATE`, которой нет в `CHECK` существующего журнала D1. `INSERT OR IGNORE` скрывал нарушение ограничения и превращал его в ложный конфликт без строки.

Кандидат использует только разрешённые категории существующей схемы и отдельное пространство идентичности `info:*` / `INFO_*`. Добавляется только индекс чтения lifecycle. Таблица, её ограничения и старые записи не переписываются.

Защитные свойства:

- информационные сообщения имеют явную надпись «НЕ ТОРГОВЫЙ СИГНАЛ»;
- финальная автоматическая цепочка выключена;
- live probability, validated signal, execution и automatic weight tuning выключены;
- веса 35/30/20/15 не меняются;
- stale, future, partial и malformed данные закрывают отправку;
- направление LONG/SHORT обрабатывается симметрично;
- точная Unicode-идентичность, без угадывания alias;
- атомарная дедупликация, 30-минутный cooldown и отсутствие автоповтора при неопределённой доставке;
- максимум одна информационная отправка за цикл;
- пространство журнала `info:*` ограничено 1024 строками, после чего отправка закрывается;
- D1 preaction envelope ограничен 1536 reads / 4 writes и сохраняет точное состояние Telegram-gates даже при budget-block;
- D1-индекс применяется только после read-only проверки схемы, бюджета и cardinality;
- Worker и зашифрованный runtime не меняются.

`R7_FINAL.command` содержит пакет внутри себя. Запускать нужно одну команду, указанную в финальном сообщении. Установщик сам проверяет SHA, создаёт backup branch, выполняет remote preflight, no-send validation, одну подтверждаемую тестовую информационную отправку, no-send rehearsal, exact-head promotion, no-send production smoke и три естественных цикла. При неизвестном результате сети он останавливается и ничего не объявляет успешным.

R6 безопасно откатился после двух успешных естественных циклов: второй цикл вошёл в штатный D1 budget-block и поэтому не напечатал отдельную диагностическую строку `TELEGRAM_OUTPUT_LAYER`, хотя финальный результат содержал безопасный `telegram_output`. R7 принимает оба эквивалентных доказательства только при одновременных `enabled=true`, `info_enabled=true`, `final_chain_auto=false`, `network_send=false` и `ok=true`; разнесённые по несвязанным строкам маркеры не принимаются.

Owner-проверки помечаются отдельным `isolated_telegram_validation`. Только для этих трёх проверок отключаются посторонний manual smoke R8.20 и дорогой discovery-recall observer, а единственная разрешённая тестовая отправка выполняется до необязательных shadow-sidecars, пока её D1 envelope гарантированно доступен. Плановые production-циклы и обычные ручные запуски сохраняют оба observer и прежний порядок исполнения.

На момент сборки production находится на rollback-коммите `06456805eded133965324b1e5786daf1ad783575`, дерево которого байт-в-байт совпадает с прежним безопасным production `f12d7c12441c3ddd710b2fd333d90ab402fa6785`. R7 ещё не запускался. Запуск `.command` является отдельным явным действием владельца и может изменить `main` только после прохождения всех gates.
