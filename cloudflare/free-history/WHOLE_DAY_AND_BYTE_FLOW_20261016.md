# Фактический расход и суточный поток хранения

## Устранённые пробелы учёта

Почасовой `worker-entry` ранее сохранял результат, но не native стоимость DATA_DB/ARCHIVE_DB. Теперь наблюдаются ровно те же SQL/параметры и ответы: first использует all для получения metadata без нового запроса. Отдельная журнальная квитанция включает оба рынка, no-op и последние DELETE/INSERT run-log. finally записывает её и при ошибке run-log, сохраняя исходное исключение; потерянная native metadata оставляет total null. Квитанция имеет уникальный invocation_id, исходные часы и отдельные subtotal/unknown для двух bindings. Она не объявляет суточный итог и не добавляет новый SQL writer.

В сборщике ошибка claim/cleanup могла возникать до существующего collection catch. Теперь точный native subtotal/unknown записывается один раз до повторного проброса исходной ошибки; новых запросов/попыток финализации нет. Итоговая invocation-квитанция finally включает и поздний отказ финализации. DATA_DB разбит на вложенный private-price source и collector-excluding-private-price, чтобы эти расходы не сложились дважды с PRIVATE_PRICE.

Офлайн-проверка сравнивает с точным сохранённым старым hourly entry: SQL, параметры, обе bulk HTTP и все строки/исходные часы архива совпадают побайтно. Проверяются no-op, отсутствующая metadata, missing source и отказ последнего run-log INSERT. Нативные значения в fixture — контрольные, не рабочие квитанции.

## Ограниченный выпуск наблюдения

Отдельный workflow `current-hourly-native-observer-repair.yml` имеет execute=false по умолчанию, не имеет D1/source/Telegram credentials и не вызывает Worker вручную. Он проверяет текущий main/lease/fence, полный exact-main cloud, квалификационные hashes и dry-run bundle. Immutable version загружается отдельно от активации; bindings, runtime limits, crons и байты проверяются через version-bound reader. Прежняя версия сохраняется для отката; чужая активация не перезаписывается. Лишь последующий обычный часовой запуск сможет дать новую рабочую native квитанцию. Для сборщика используется уже существующий точный bounded repair.
