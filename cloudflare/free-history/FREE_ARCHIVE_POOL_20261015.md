# Бесплатный архив: второй пакет, пока без активации

## Что делает код

Пять точных мест: прежний `LEGACY` и созданные A1–A4 из реестра ресурсов.
При записи сначала ищется та же публикация и хеш во всех доступных местах.
Если копии нет, выбирается первое место с измеренным native `size_after`
и запасом до прежнего рабочего предела 400 000 000 байт.
Пустой ответ без native размера не считается свободным местом.

Декодер читает ровно место из маркера; другие базы для чтения не перебираются.
Старые маркеры без суффикса продолжают читать LEGACY. Все исходные поля,
точные байты, неизвестные столбцы и source clocks восстанавливаются полностью.
Положительный кеш заполняется только проверенной native копией; отсутствующие
ревизии не кешируются. Суммарный D1 учёт включает каждое место один раз.

Ручной/плановый Node, основной сборщик, резервный сборщик и архивный Worker
подготовлены к адресному чтению. Установка новых Worker bindings выполняется
отдельно после проверки схем и активной версии, с сохранением всех старых
переменных, секретов и расписания. Еженедельный rollout сохраняет уже
установленные точные архивные bindings.

## Что пока выключено

`REPORT2_CANONICAL_ARCHIVE_POOL_ENABLED` по умолчанию `false`.
Новый request установки схем имеет `execute: false`. Автоматическая ротация
и прежние flags очистки не включаются этим пакетом. Новые базы не считать
используемыми по факту создания ресурсов или прохождения тестов.

Инициализация разрешает только две фиксированные DDL схемы в A1–A4,
не меняет LEGACY и не переносит тела из основной базы. Отдельная одна
инициализация в сутки учитывается в том же native дневном ledger:
5000R/80W, плюс защищён следующий полный отчёт 59000R/920W;
неизвестные завершённые расходы блокируют admission. Максимум 16 HTTP к
архивам, 4 к bridge и 32 к GitHub внутри общего 164. Это не дополнительная
очистка: четыре потраченных UTC15 слота RETAINED_HISTORY остаются потраченными.

## Ограничения приёмки

Два обслуживания по 48 строк дают максимум 96 переносов в сутки.
36 полных циклов × 2 финалиста × два вида полных тел дают 144 строки;
с прежним запасом до 47 полных циклов — 188. Нужны как минимум четыре
**полных** обслуживания для положительного арифметического запаса. Это
предложение, существующий предел два не повышен. Фактические ограничения
выборки, защищённых ссылок, bridge и native расходов могут снизить скорость.
Четыре номинальных запуска не являются доказательством устойчивости.

Ещё нужно: native установка схем после дневного admission; точное внедрение
bindings; подтверждение всех consumers, включая старые Hub fetch routes;
исправление/квалификация ограничений reference census, body response и cursor;
полный native суточный расчёт; согласование достаточного обслуживания;
измеренное освобождение основной базы; естественный полный отчёт по обеим
монетам. SQL и переносы текущий offline lease не разрешает.

Одновременная запись в разные базы не является общей транзакцией. При гонке
возможна лишняя неизменяемая копия, но ни одна исходная ревизия не заменяется
другой. Дедупликация уже известных ревизий проверяется перед выбором ёмкости.
