# Бесплатная почасовая история

Отдельный Cloudflare Worker `my-report-2-free-history` запускается в 35-ю минуту часа. Он читает уже закрытый снимок HTX linear perpetual из `DATA_DB`, делает по одному публичному bulk HTTP-запросу на спотовые тикеры HTX и Gate за час, а раз в два часа — один точечный запрос KuCoin для RAVE. Результаты, часы источника, SHA-256, пропуски и итог каждого запуска хранятся отдельно в `ARCHIVE_DB` (`report2-free-hourly-history`). Полный отчёт, Telegram и торговое решение этим Worker не запускаются.

Цели: 104 линейных контракта утверждённого манифеста; для HTX spot и Gate spot — пары всех 104 монет, если они есть. Gate возвращает общий список одним запросом, поэтому расширение с 15 до 104 целей не увеличивает число запросов. Внешние пары Gate остаются **неподтверждёнными по идентичности актива** и не разрешены для общего вывода. Spot ticker — срез последней цены и 24-часового объёма; это не закрытая свеча и не отдельная сделка. `history-read.mjs` возвращает историю ограниченными запросами до семи дней за раз и не разрешает decision use. `relative-pattern.mjs` описывает только фактически совпавшие по часу изменения монеты, BTC и ETH на одной бирже и одном рынке; до проверки на реальной истории он не участвует в отчёте и оценке.

Границы: D1 400 MB для отдельной базы, удержание не более 270 дней; два HTTP запроса/час постоянно и третий KuCoin раз в два часа, максимум 60/день; одна попытка каждой биржи/час без повторного обращения при ошибке. Gate RAVE помечен конфликтным: его свежая цена расходилась с HTX futures на 29,4%, в то время как Bitget и KuCoin spot были близки к HTX futures; Bitget ответил HTTP 403 из облачного Worker, поэтому выбран KuCoin. Это **один почасовой срез**, а не полная лента сделок, минутных свечей или всех пятиминутных снимков. Если база приблизится к пределу, новые записи прекращаются. Удаление старых строк выполняется перед проверкой размера. Если физический файл D1 не сожмётся после удаления, архив остановится до безопасного обслуживания. На бесплатном аккаунте D1 допускает 500 MB на базу и 5 GB суммарно; R2 здесь не используется.

Применённая схема — `001_hourly_archive.sql`. Настройка Worker — `wrangler.json`. Бесплатный Cron ограничен 10 мс CPU на запуск, поэтому после первой реальной записи проверять `report2_archive_run_v1` и отсутствие ошибок исполнения. Перед повторным deploy сверить актуальные `main`, lease, D1 IDs, действующее расписание и тесты `node --test cloudflare/free-history/*.test.mjs`; сохранять результат проверки с реальной записью и точным commit SHA. Не внедрять внешние цены в отчёт по одному тикеру без официальной привязки актива и совместимого времени.
