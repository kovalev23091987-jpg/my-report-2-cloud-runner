# Бесплатная почасовая история HTX

Отдельный Cloudflare Worker `my-report-2-free-history` запускается в 35-ю минуту каждого часа UTC. Он читает уже закрытый снимок HTX linear perpetual из `DATA_DB` для 104 утверждённых монет и делает **один** публичный bulk HTTP-запрос к споту HTX. Результаты, исходные часы, SHA-256, пропуски и итог запуска хранятся отдельно в `ARCHIVE_DB` (`report2-free-hourly-history`). Полный отчёт, Telegram и торговое решение этим Worker не запускаются.

В первом фактическом облачном снимке сохранены фьючерсы 104/104 с квалифицированной ценой и спот HTX 89/104 с найденной парой, из которых 88 прошли проверку котировки. Пары, которой нет на HTX, Worker не подменяет другой биржей. ACE присутствует на споте HTX, но не прошёл проверку котировки в первом снимке. Спотовый тикер — последняя цена, стаканные bid/ask и 24-часовой объём на часы пакетного ответа, а не закрытая свеча или часы отдельной сделки.

Ранее сохранённая в D1 проба Gate и её ошибка Bitget остаются историческим доказательством исследования; новый код не обращается к этим биржам и не читает их строки. `history-read.mjs` принимает только HTX, проверяет SHA-256 и исходные часы, ограничивает чтение семью днями и не разрешает торговое решение. `relative-pattern.mjs` описывает динамику монеты против BTC и ETH только на одном рынке и в совпавшие часы. Пока нет достаточной реальной истории и цепочки до consumer, этот анализ не влияет на отчёт, Telegram, score или вход.

Границы: D1 до 400 MB в отдельной базе и удержание до 270 дней; один HTTP-запрос к споту HTX за час, не более 24 попыток за UTC-день, без повтора после ошибки; для фьючерсов ноль дополнительных запросов к бирже, потому что используется закрытый снимок существующего сборщика. Общий лимит полного отчёта 164 не меняется. Если база приблизится к установленному пределу, запись остановится. Удаление старых строк выполняется перед проверкой размера; если физический файл D1 не сожмётся, потребуется обслуживание. R2 и платное хранилище не используются.

Перед изменением Worker проверять свежий `main`, lease, D1 ID, расписание и `node --test cloudflare/free-history/*.test.mjs`. Для признания регулярной работы нужен следующий естественный почасовой запуск с D1 readback; первый снимок подтверждает данные, но не надёжность длинной серии. Не выдавать сохранение истории за её использование в финальном отчёте.
