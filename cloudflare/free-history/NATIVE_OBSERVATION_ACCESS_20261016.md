# Проверка рабочих квитанций без SQL и новых снимков

В существующем workflow `current-hourly-native-observer-repair.yml` режим `inspect_only=true` отключает сборку и выпуск. Он читает только метаданные двух существующих Workers и их уже сохранённые native строки журнала за два часа. Предел — 64 события на Worker, один запрос на Worker, 12 Cloudflare + 28 GitHub HTTP, прежний ручной резерв 24. Ошибочные запросы не повторяются. Worker вручную не вызывается; настройки журналирования не меняются.

Настройки постоянного журналирования читаются через отдельный `GET /script-settings`, предусмотренный [Cloudflare API](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/settings/methods/get/). Отсутствующее поле остаётся неподтверждённым; явное отключение даёт отдельный отказ. Для событий используется ограниченный dry [telemetry query](https://developers.cloudflare.com/api/resources/workers/subresources/observability/subresources/telemetry/methods/query/), без сохранения результатов запроса в Cloudflare. Доступ repository token к telemetry ещё требует фактической проверки.

Точная строка привязывается к имени Worker, scheduled/cron, immutable версии, времени, event ID и неизменному deployment до/после. Дубликаты invocation не складываются, конфликтующие ревизии исключаются. Native subtotal и unknown сохраняются; вложенный private-price источник отделён от остатка collector. Оценочная sampling статистика не превращается в точный расход или суточный итог. Полный UTC день этот ограниченный просмотр не закрывает.

Почасовая квитанция теперь отдельно записывает scheduled и фактические execution часы. Запоздалый запуск не относится автоматически к старому дню. При переходе через полночь точное распределение по дням остаётся неподтверждённым. SQL, параметры, исходные часы рынков, archived bytes и запросы источников не меняются; сравнение с точным старым entry сохраняется в общей проверке.

Режим не разрешает третий UTC16 перенос, повышение 2/day, возврат резерва, автоматическую ротацию или сброс unknown. После него всё ещё нужна приёмка пропускной способности хранения, полной стоимости и естественного полного отчёта с двумя сохранёнными монетами.
