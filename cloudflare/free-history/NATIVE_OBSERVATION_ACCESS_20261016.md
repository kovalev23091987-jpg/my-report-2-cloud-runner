# Проверка рабочих квитанций без SQL и новых снимков

В существующем workflow `current-hourly-native-observer-repair.yml` режим `inspect_only=true` отключает сборку и выпуск. Он читает только метаданные двух существующих Workers и их уже сохранённые native строки журнала за два часа. Предел — 64 события на Worker, один запрос на Worker, 12 Cloudflare + 28 GitHub HTTP, прежний ручной резерв 24. Ошибочные запросы не повторяются. Worker вручную не вызывается; настройки журналирования не меняются.

Настройки постоянного журналирования читаются через отдельный `GET /script-settings`, предусмотренный [Cloudflare API](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/settings/methods/get/). Отсутствующее поле остаётся неподтверждённым; явное отключение даёт отдельный отказ. Для событий используется ограниченный dry [telemetry query](https://developers.cloudflare.com/api/resources/workers/subresources/observability/subresources/telemetry/methods/query/), без сохранения результатов запроса в Cloudflare. Доступ repository token к telemetry подтверждён запуском38883143100; пригодные сохранённые native события в нём не найдены.

Точная строка привязывается к имени Worker, scheduled/cron, immutable версии, времени, event ID и неизменному deployment до/после. Дубликаты invocation не складываются, конфликтующие ревизии исключаются. Native subtotal и unknown сохраняются; вложенный private-price источник отделён от остатка collector. Оценочная sampling статистика не превращается в точный расход или суточный итог. Полный UTC день этот ограниченный просмотр не закрывает.

Почасовая квитанция теперь отдельно записывает scheduled и фактические execution часы. Запоздалый запуск не относится автоматически к старому дню. При переходе через полночь точное распределение по дням остаётся неподтверждённым. SQL, параметры, исходные часы рынков, archived bytes и запросы источников не меняются; сравнение с точным старым entry сохраняется в общей проверке.

Режим не разрешает третий UTC16 перенос, повышение 2/day, возврат резерва, автоматическую ротацию или сброс unknown. После него всё ещё нужна приёмка пропускной способности хранения, полной стоимости и естественного полного отчёта с двумя сохранёнными монетами.

## Если сохранённые журналы не дали квитанций

Ограниченный фактический запуск 38883143100 прочитал правильные активные версии, но не подтвердил постоянное журналирование и вернул 0 пригодных событий. Доступ repository token к telemetry работает; это не подтверждение нулевого D1 расхода. Оба telemetry запроса были sampled (`abr_level=1`), их собственные `statistics.rows_read` относятся к Observability, а не к SQL рабочей D1; их нельзя складывать с native D1.

Дополнительный режим `inspect_only=true, tail_collector=true` создаёт один временный [Worker Tail](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/tail/methods/create/) только у существующего Hub. Это не отдельный Tail Worker и не запуск сборщика. Фильтр требует текущую immutable версию и точную метку native квитанции. Клиент подключается один раз по `trace-v1`, ждёт максимум 330 секунд, 16 frames / 256 KiB, завершает чтение после первой пригодной штатной cron-квитанции и удаляет только собственный tail. Нет повторного подключения или запуска источников.

Версия и deployment проверяются до и после; указание версии в tail payload не выдумывается, а способ привязки явно указан. Чужой Worker, старое событие до подключения, неверные часы, обрезанный или противоречивый результат не принимаются. URL временного доступа и посторонние журналы/исключения не экспортируются. Cleanup выполняется и при позднем отказе guard; неподтверждённое удаление остаётся отдельной ошибкой. На весь stream требуется минимум 10 минут собственной аренды, прежние HTTP пределы и ручной резерв сохраняются. Полный суточный расход и восстановление отчёта этот просмотр не подтверждает.

Код завершился и записал итог10:08:45UTC, но WebSocket удерживал Node; задание остановлено и always-artifact сохранён. Исправление проверяется настоящим локальным WebSocket, который не подтверждает close: после финального сохранения и попытки удалить только собственный tail процесс явно завершает работу. Ошибка cleanup сохраняет ненулевой exit code, URL доступа не печатается. Короткий прогресс с не секретным tail ID позволяет проверить создание/удаление даже при отмене задания.
