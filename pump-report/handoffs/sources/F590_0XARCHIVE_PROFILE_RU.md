# F590 — точный профиль 0xArchive

Подготовлен документированный профиль будущей карты и автоматического подключения провайдера к550. Код, тесты и фактические вызовы отсутствуют. F589/F588 сохранены без изменения.

Закрыто по новым первичным документам:
- Core: GET /v1/hyperliquid/liquidations/{symbol}/levels.
- HIP-3: GET /v1/hyperliquid/hip3/liquidations/{symbol}/levels.
- Профиль одного снимка: range_pct=1,buckets=10, без at/side;1 кредит REST. Каталоги instruments/symbols также стоят1 кредит за запрос.
- Free включает эти маршруты. REST требует существующий API-ключ; MCP — OAuth без отдельного API-ключа. Наличие существующей действующей сессии/ключа и остаток кредитов UNKNOWN.
- Карта — EXTERNAL_MODEL Hyperliquid, USD-оценка по ценовым корзинам. Расчёт около5min, базовое состояние обычно старше на30–65min. Часы нельзя объединять или выдавать за свежие позиции BingX.

[Credits](https://docs.0xarchive.io/core-concepts/credits), [маршруты и часы](https://docs.0xarchive.io/rest-api/liquidation-levels), [Free limits](https://docs.0xarchive.io/rate-limits), [MCP/REST auth](https://docs.0xarchive.io/).

Осталось UNKNOWN: точная схема запроса/ответа/пагинации общего /v1/symbols; полнота фактического каталога; каноническая идентичность пересечения550; текущая авторизация и баланс; дополнительные обращения и общий расход кредитов MCP-обёртки. Endpoint reference вернулся только с навигацией, два точных поиска дали пустой результат. Все6чтений и2поиска потрачены; новых чтений по ним не будет.

Один профиль провайдера → полный каталог один раз → локальный пакетный join550 с точной идентичностью → выборочный параметризованный снимок только готового кандидата. Совпадение тикера не является join. Поддерживаемый символ не доказывает наличие именно будущей карты. Таблица550 F589 переиспользуется; новые фактические статусы по всем строкам остаются UNKNOWN/NOT_CHECKED.

Отдельное предложение ROOT: максимум2 MCP-вызова — get_instruments({}), затем условный get_liquidation_levels для одного точно сопоставленного кандидата. Документированный расход соответствующих REST-операций1+1; общий верхний расход MCP пока UNKNOWN, поэтому2 нельзя объявлять полной верхней границей или автоматическим допуском. При неполном каталоге/неверной идентичности/авторизации второй вызов не выполнять. Полный профиль, входные условия и точные stop-условия находятся в JSON пакета.

Исправления ROOT имеют приоритет над F589: LOOKUP —10 запусков в сутки, все10 уже потрачены; это не10SQL. Сегодня банк1кандидат/час+carry;2/час — будущая модель. Никаких новых аккаунтов, ключей, оплаты, nativeSQL,Telegram,Worker/deploy. Все прежние расходы/unknowns/резервы/caps,9пауз и2OWNERdeferrals сохранены. Отсутствие карты не блокирует основную пригодную карточку.
