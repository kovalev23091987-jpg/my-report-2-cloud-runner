# F556: наблюдаемые позиции Hyperliquid, подключённые к getLiquidations

Новый источник встроен в createPumpSources.getLiquidations. Если пригодного Swole route нет и ROOT явно передал Hyperliquid route, вызывается ограниченный producer через существующий broker.request с methodPOST/json_body. URL фиксирован api.hyperliquid.xyz/info; body только clearinghouseState и точный явно допущенный account, optionaldex. Прямого fetch, discovery, поиска адресов, retry/fallback и account pagination нет. ROOT проверяет exact read-only template,4096B, bodySHA cache/coalescing, квоты и расход. SOURCE policy/admission не создаёт.

Сохранённые материалы прочитаны до двух разрешённых официальных страниц. Повторно используется имя метода и форма ответа. Старый recorder с directfetch, rotatingmethod, tickerjoin, receipt-as-sourcetime и zeroabsence не переносится. Новые primary literals подтверждают user accountstate/openpositions и поля coin/szi/liquidationPx/positionValue/root time; не доказывают полный рынок, валюту каждого dex или BingX asset mapping. Независимые unit/side/currency/underlying/pricebasis доказательства должны быть явно переданы ROOT, никакая готовая canonical qualification на новые539 не копируется.

Без конечного admitted_accounts список не придумывается: NOT_CHECKED и0HTTP. Максимум2 аккаунта/2 response pages, каждый account один state response без курсоров. Текущий source hardmax и профиль карты остаются1: при двух admitted аккаунтах читается только первый, второй явно unchecked. Это не обход бюджета. Мапа всегда наблюдаемый subset, не marketcensus. Одна account/coin oneWay позиция даёт стабильный position_id через непрозрачный account_ref; duplicate targetposition в одном ответе отклоняется, размеры не складываются.

Зона — точечная текущая расчётная liquidationPx, basisOBSERVED_POSITION, venueHYPERLIQUID. Валюта и positionValue сохраняют исходную единицу, например USDC, только при независимом подтверждении; никакого выдуманного USDT или суммы size×liquidationPx. Если unit суммы неизвестен, magnitude=null с причиной. Для переноса цены в BingX нужны exact independently reviewed same-underlying, canonicalflag, точный pricebasis и quoteconversion, свежие event/expiry. Без этого зона остаётся native/unusable, multiplier=null; нет скрытого коэффициента1. LONG/SHORT требуют отдельно квалифицированной signed szi семантики; невалидный/нулевой size или отсутствующий liquidationPx не превращаются в нулевую ликвидацию.

Время берётся только из payload.time, Unixms. Это clock состояния аккаунта, не доказанный момент изменения позиции. NativeTTL равен observed_positions120s. ConvertedUSDTzone живёт не дольше nativeexpiry, mappingexpiry и mappingevent+priceTTL; исходный nativeexpiry сохранён отдельно. Общий deadline10s передаётся всему запросу, поздний результат не обновляет возраст. Спent/unknown не возвращаются, отказ бюджета и timeout явные. Основной план не зависит от карты.

Один новый connected case проходит через getLiquidations и фактический consumer selectZones. Итог1PASS0FAIL42.592833ms. Ранний вариант того же нового case1PASS49.990667ms; при review найден конкретный TTL-дефект, исправлен и проверен только этот case. Старые Swole/T3/F551/F553 не запускались. Тестовые адреса синтетические, nativeIO0; существующая registry13 не изменена.
