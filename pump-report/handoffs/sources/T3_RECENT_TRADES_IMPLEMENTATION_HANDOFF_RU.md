# T3 — producer последних сделок в общем формате v1.2

Реализован конкретный путь `getOptional → ROOT broker → GET /openApi/swap/v2/quote/trades?limit=100&symbol=<verified native symbol> → parseRecentTrades → facts.trades`. Общий контракт — `pump-report-contract-v1.2-quote-notional`, точный Git blob `e1fdc83afdf72b803806370d32f8d42c92630cd6`. SOURCE working HEAD остаётся `4b44d48836b9c26b1c9c8bb0830055ee279a608a`; source-коммит/main/PR этим чатом не создавались. ROOT принимает точные локальные файлы из манифеста.

Новый `sources/recent-trades.mjs` нормализует `trade_id`, `event_ts`, `price`, `notional_quote`, `aggressor_side` и явные причины невалидных полей. `notional_quote` берётся только из документированного `quoteQty` этого recent-метода для независимо проверенного USDT-контракта. Единица — `USDT_PRICE_QUOTE_NOTIONAL`. `qty` не читается, BASE и multiplier неизвестны; деления суммы на цену нет. Исторический метод не используется и эти доказательства на него не переносятся.

ID требуется фактический: безопасное неотрицательное целое число либо каноническая десятичная строка целого ID. Строковые большие ID сохраняются точно; небезопасные JS numbers, отсутствующие и произвольные текстовые ID получают null. Синтетические execution IDs не создаются. В сохранённом native-примере ID не показан, хотя официальный reference его документирует: если реальный endpoint не вернёт ID, соответствующие строки останутся непригодными для направленного вывода. Native admission этого пакета не было.

Выбран точный native-descriptor `isBuyerMaker`. При единственном boolean-поле `true` означает SELL агрессора, `false` — BUY. Только `buyerMaker`, наличие обоих полей даже при равенстве, строковые boolean, отсутствие поля и несовпадающий row.symbol дают UNKNOWN. Расхождение названий в двух первичных документах не скрывается fallback-алиасом. Первичные доказательства повторно использованы без скачивания и без выполнения JS: `T3_RECENT_TRADES_PRIMARY_PROOFS_V1.json`, SHA256 `64240dd64eaac3e8940c364b27dcfabffb12f1b1cd8305c78207d0a77a5abe1d`.

Все возвращённые строки, включая невалидные, повторные и конфликтующие ID, остаются в массиве. SOURCE не удаляет дубликаты до аналитики; consumer должен сначала выявить конфликты, затем выбрать один и тот же квалифицированный набор для сумм и реакции цены. Счётчики `qualified_before_dedup` явно относятся к этапу до consumer dedup. Время факта — последнее исходное время полностью квалифицированной строки, TTL — исходное время плюс30s; receive/cache read не освежает возраст. Свежая строка без ID/с неоднозначным maker не омолаживает старые пригодные исполнения. Будущее/seconds вместо ms не принимаются.

Покрытие всегда `LATEST_RETURNED_BOUNDED_SAMPLE`, `complete:false`, `full_window_coverage:false`, начало/конец полного окна null. Не обещается полный пяти минутный tape, рынок целиком или абсолютная полнота. При пригодных отдельных строках fact может быть USABLE; это пригодность ограниченной выборки. При пустой/полностью непригодной выборке сохраняется INCOMPLETE с исходными причинами. Факт не создаёт причинных выводов о поглощении, намерениях участников или относительной силе.

Стоимость описания — максимум один новый broker-запрос сделок на eligible инструмент, без retry/fallback/pagination. У `getOptional` остаётся общий предел2: trades занимает первый слот, оставшийся получает квалифицированный OI, либо funding, когда OI не квалифицирован. Третий GET не создаётся. Даже отклонённая/ошибочная попытка занимает внутренний слот; расходы и UNKNOWN не возвращаются. Когда оба прежних показателя квалифицированы, funding получает `NOT_CHECKED/OPTIONAL_BUDGET_SLOT_NOT_AVAILABLE`. Индивидуальные `optional_trades/open_interest/funding` в SOURCE_HTTP_PLAN — альтернативные максимумы внутри `optional_total_max=2`, не сумма3. Caps/profile/общий ledger не изменены.

BTC/ETH возвращают три NOT_CHECKED с `OWNER_ASSET_DELIVERY_EXCLUDED` и не вызывают optional broker. Поле market_context целиком отсутствует; benchmark-запросов, расчётов и резервов нет. Независимый registry/identity gate сохранён. Практический scope550 из U3 не превращён этим патчем в runtime registry: нынешние13 записей, включая2 owner-excluded, не доказывают readiness всех550. Проверки units/core/свежести и фактических квот отдельны.

Одна новая связанная wire-проверка плюс изменившийся NoComparison-case: **6PASS/0FAIL**, `duration_ms80.041041`, журнал `T3_RECENT_TRADES_AFFECTED_TESTS_V1.log`. Проверены реальный вызов producer через mock broker, точный URL/limit/receipt/TTL, direct quoteQty, maker ambiguity, ID/clock/amount/identity faults, сохранение конфликтов, cache/original age, общий upper2/denied attempts и owner BTCETH/no comparison. Старые R/A33/97+7/фабрика/U3 и полный проектный набор повторно не запускались. Нормализованный исполняемый пример в `T3_SYNTHETIC_NORMALIZED_EXAMPLE_V1.json` явно SYNTHETIC; это не рыночный/native результат и не статистика.

Новые market HTTP/search/SQL/WS/TG/deploy0; общие contracts/profile/runtime/схемы/настройки/registry не менялись. Предыдущие frozen manifests и снимки сохранены. Отдельная локальная квитанция `T3_SAVED_PREPATCH_DIGEST_CORRECTION_V1.json` фиксирует действительный SHA исторического prepatch-пакета вместо оставленного в старом remote release placeholder; старые remotelease/receipt не переписывались и не оживлялись.
