# F555: CCXT, единицы стакана и fillId

Ровно два полных файла получены через GitHub connector по commitd3159f7036f93db086cd0414642132fba5401710. Git SHA1 обоих blobs пересчитан по полным UTF8-байтам и совпал с разрешёнными значениями. Новые SHA256 и диапазоны девяти полных методов находятся в F555_FULL_BLOBS_AND_LITERAL_INDEX_V1.json. Общий размер874861B относится к исходным файлам; transport wire не измерялся. Скачанный код не исполнялся.

**Стакан.** fetchOrderBook выбирает обычные bids/asks, а не bidsCoin/asksCoin. Общий parseOrderBook читает price[0]/amount[1], сортирует стороны и добавляет symbol/time. В этом пути нет применения contractSize или пересчёта единиц. parseMarket задаёт linear contractSize=1, сохраняет native baseId и не использует native size для этого значения. Для APT native baseId=APT, для1000SHIB —1000SHIB; цена и количество не пересчитываются на1000. Это статический разбор потребительского кода, без обращения к рынку.

Официальный depth literal b4354f42... подтверждает только название quantity(coin) у Coin-полей. Он не связывает generic/Coin amounts с единицей каждого native price base. CCXT использует другой набор полей, поэтому не закрывает этот пробел. Новые единицы и старые13 не менялись. Для ordinary APT подготовлен конкретный вопрос владельцу об ограниченной CCXT-конвенции STANDARD. До решения и ROOT review она не активирована. Масштабированный1000SHIB остаётся UNKNOWN независимо от такого решения.

**Сделки.** parseTrade включает fillId в ID lookup [id,t,fillId,tradeId]. Shared safeTrade не заменяет ID. quoteQty передаётся напрямую как cost; contractSize участвует в вычислении cost только при отсутствии прямого cost. Кандидаты времени не включают ts. Это подтверждает наличие consumer mapping для фактического fillId, но не гарантирует стабильность или глобальную уникальность ID у BingX. safeStringN импортирован из файла вне двух разрешённых blobs; malformed/multifield policy по догадке не переносится.

Минимальное предложение ROOT: отдельно рассмотреть точный fillId для public recent USDT-M, сохраняя исходную строку, отклоняя конфликты id/fillId и передавая все дубликаты/invalid rows consumer до фильтрации. Автоматических t/tradeId, выдуманного ID, qty→BASE или ts→time нет. F553 не переразбирался и остаётся frozen INCOMPLETE. Если ROOT примет proposal, достаточно одного нового focused alias/conflict case без повтора старых шести или рыночного вызова.

Это проверка сохранённых доказательств, не native qualification. Исходники, общий контракт, runtime и профиль не менялись.
