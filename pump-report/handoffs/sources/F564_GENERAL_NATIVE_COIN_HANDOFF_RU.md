# F564 — общая нативная единица Coin

Сочетание двух первичных оснований позволяет семантическую квалификацию обычных точных инструментов BingX: сохранённый дескриптор depth называет bidsCoin/asksCoin количеством монет, а переданный ROOT официальный общий гид §§3.3–3.4 определяет размер позиции в базовой валюте и среднюю цену как стоимость в USDT, делённую на количество. Связь этих определений с точным нативным asset — явный ограниченный вывод, а не утверждение о всех полях API.

Обзор содержит все550 точных tuple.541 обычный tuple признан применимым к общему правилу; это11 ранее квалифицированных инструментов выбранного scope, APT и529 новых кандидатов на семантическую квалификацию ROOT.9 конкретных неоднозначных упаковок остаются UNKNOWN:1000000BABYDOGE,1000000MOG,10000NEX,10000SATS,1000BONK,1000CAT,1000CHEEMS,1000PEPE,1000SHIB. Их коэффициенты не выводились из названия, size, precision или соотношений количеств; из universe они не удалены.

Числа и язык не являются фильтрами.0G,1INCH,2Z,4,4STOCK остаются допустимыми обычными нативными обозначениями; BNLIFE сохраняет китайское display name. Для единицы внутри точного инструмента BingX не требуется проектная или межбиржевая canonical identity. Это не даёт переносить такую идентичность на другую площадку.

Исполняемое предложение состоит из sources/native-coin-unit-reviewed-data.mjs и sources/native-coin-unit-review.mjs. Первый хранит конечный точный перечень с хешами решений, второй применяет его лишь при полном совпадении tuple/native_contract_id/native_base/семейства и уже независимо принятой VERIFIED_CRYPTO identity. Старые orderbook qualifications сохраняются. Новые/изменённые tuple не получают общего разрешения. Source index и чужие файлы не менялись.

Точное подключение ROOT — F564_ROOT_NATIVE_EXECUTION_ADOPTION_PROPOSAL_V1.diff: импорт reviewer в registry/native-execution-qualifications.mjs и вызов его вместо прежнего return entry для не-APT tuple. Прежняя отдельная APT-ветка остаётся. После принятия ROOT должен честно обновить сводные счётчики: семантика541/550, новые529, неизвестная упаковка9, фактически свежие стаканы по этому обзору0. Перечень сам по себе не является новым каталогом или нативным охватом.

Одна новая связанная проверка прошла1PASS0FAIL после исправления ошибочного reference equality в тесте; первый0PASS1FAIL сохранён. Проверен путь точный обзор→независимый ROOT resolver→настоящий createPumpSources/getCore→Coin parser→measureLiquidity. Синтетическая 1INCH-фикстура доходит до ликвидности; противоречивые STANDARD массивы не используются. Missing Coin/T и неоднозначный1000PEPE остаются непригодными; изменённые identity/USDC/COIN-M блокируются. Старые принятые тесты не повторялись.
