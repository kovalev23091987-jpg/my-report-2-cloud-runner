# Вопрос владельцу через ROOT

Принимаете ли для точного APT-USDT (BingX USDT-M, contractId100164) ограниченную конвенцию pinned CCXT: считать amount из обычных bids/asks количеством native price base APT и использовать price×amount как USDT при проверке ликвидности?

Код CCXT задаёт linear contractSize=1 и передаёт обычные bids/asks без преобразования. Это доказывает поведение потребителя. Независимой гарантии BingX об единице generic quantity в сохранённых материалах нет. Официальный literal называет Coin-поля quantity(coin), однако CCXT их не использует.

Без решения новая квалификация остаётся отсутствующей. При принятии потребуются ROOT review точного tuple, отдельный фактический допуск и проверка реального ответа, исходных часов, TTL15s, двух сторон и видимой ёмкости. Основание должно явно называться CCXT_CONSUMER_CONVENTION; independent_vendor_guarantee_claimed=false.

1000SHIB и другие масштабированные инструменты в это решение не входят: связь Coin/generic/native basket/underlying остаётся UNKNOWN. Старые13, стратегия, пороги, позиции и бюджеты сохраняются. Пакет не активирует политику и не разрешает исполнение CCXT/loadMarkets.

Вопрос выделен по прямому условию поручения F555: единственное основание в виде CCXT-конвенции требует решения владельца. ROOT получает конкретный предмет рассмотрения; отдельное сообщение владельцу из SOURCE не отправлялось.
