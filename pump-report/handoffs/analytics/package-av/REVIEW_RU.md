# AV — статический review накопительного pacing и runner

**Конкретных P1/P2 в четырёх замороженных файлах не обнаружено.** Проверены точные SHA из задания ROOT; исходные файлы не изменены. Imports, tests, native market/RPC/SQL/TG/Worker/deploy/CONTROL — 0. Девять PASS — результат ROOT, AV их не повторял.

Банк задаёт ёмкость, не обязательное число анализов. Runner сначала выбирает реального пригодного кандидата из очереди; пустая очередь не вызывает CORE. DISCOVERY сохраняет базовую дневную allocation даже при отсутствии кандидатов. Формула текущего максимума — N×число начавшихся часов минус места, выданные до текущего часа. Поэтому0 в первом часу даёт2N во втором; при N=2 это4. Поздние часы ещё недоступны. Текущее выданное количество отдельно ограничивает следующую выдачу. Выдача перечитывает и проверяет состояние внутри atomic CAS; дешёвый отказ/ошибка/новая инвокация место не возвращает.

Сохранённые plan/allocation/buckets проверяются по версии, integer/range, времени/концу окна и накопленному числу выданных мест. Новый UTCday использует другую запись. Окно10–20Москва целиком лежит внутри UTC07–17, поэтому пересечения дня в рабочем окне нет. Guard по AUTO-окну сохранён.

Базовое N ограничивается остатком automatic plan80%, фактическими сохранёнными day/month counters, fixed reserves и будущими обзорными запросами. Перед каждым кандидатом остаются отдельные project/provider/month/future проверки, а перед каждым HTTP — minute/second/backoff и атомарный charge. Весь кандидат —12HTTP:10BingX+1Telegram+1непривязанный map; runner передаёт общий12 и карту затрат провайдеров. Существующие unknown2 не очищаются. Накопленный банк не даёт отдельного native/provider admission.

Отказ квоты без analysis записывается в result.deferred и останавливает кандидатный цикл. Он не попадает в unsafe r.analysis.ready; итоговый ready count использует optional chaining. Run сохраняется; finally освобождает только executor со своим owner.

Предел вывода: это узкий статический review, не повтор выполнения и не полная приёмка live/day/month. Существующий futureDiscoveryHttp считает будущие слоты текущего московского рабочего дня даже при until_ts=конец месяца. Проверка monthly cap использует текущие месячные расходы, но этот пакет не доказывает защищённую ёмкость всех будущих календарных дней и всего аккаунта. Поведение helper не изменялось этой правкой; нового P1/P2 по нему AV не заявляет.

Проверенные диапазоны и основания сохранены в static-review.json; точные входы — frozen-input-receipt.json. ROOT может использовать этот результат для собственного решения об интеграции. Разрешение на deploy/native этим пакетом не выдаётся. Старый отчёт,9пауз,2OWNERdeferrals, исходные расходы и резервы сохранены.
