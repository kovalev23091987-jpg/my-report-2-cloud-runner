Пакет реализует consumer опубликованного ROOT `contracts/relative-context.mjs` на main `cd32febb6be71e804b63f30e0299b6468a9c6dcd`. Изменены только context/index в analytics. Новые fixtures/test — в своём prefix; contracts/profile/runtime/SOURCE не менялись. `explainOptionalFacts` получает явный четвёртый аргумент instrument от analyzePump и вызывает ROOT qualifyRelativeContext с as_of_ts и profile.freshness_ms.market_context. Старый label-only путь удалён. Проверяются версия BINGX_CLOSED_RETURN_CONTEXT_V1, OBSERVED price basis, точный candidate/benchmark identity, цены и return arithmetic, одинаковые закрытые окна и исходные часы. ROOT профиль задаёт90s; contract/profile побайтово совпадают с опубликованными зависимостями. Ни нового threshold, ни локального обхода квалификатора нет.

При valid `optional_context.market_context.value` сохраняет полные qualified legs ROOT, общий start/end, BTC_AND_ETH либо ONE_BENCHMARK, partial и independent_venue_count=1. Fact provenance сохраняет instrument_id, source/primary provider/venue/origin, event/received/expires/evidence_ref. Внутренние поля каждого leg не урезаются. При одном BTC или ETH отсутствующий ориентир не достраивается0, текст явно говорит «один ориентир, контекст неполный». Несколько BINGX legs не объявлены независимыми площадками.

RELATIVE_RETURN описывает наблюдённые доходности за совпадающее окно и остаётся возможной второй причиной в неизменённом P/Q selector. Он не создаёт сигнал по BTC/ETH, направление покупки из индекса, score, causation или уверенность. Запрет новых отчётов BTC/ETH сохранён. Знак доходности ориентиров не является новым gate.

Непригодный/устаревший/неверный schema/value, wrong role/identity/return, асинхронные окна и malformed legs не дают relative claim или пригодный optional context. `relative_context_diagnostic` содержит valid=false, reason, null start/end/coverage и пустые returns. Обёртка ловит исключение квалификатора на malformed leg как RELATIVE_CONTEXT_MALFORMED, чтобы optional не ломал готовый основной план. Непригодность всего Fact instrument binding по прежнему относится к существующему общему assertInput; этот контракт R не менялся.
