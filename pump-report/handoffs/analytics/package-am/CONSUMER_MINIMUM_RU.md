PREPARATION_ONLY: frozen F573 manifest/SHA от ROOT ещё не получен; новые источники не оценивались. Прочитаны только contracts/index.mjs и analytics/context.mjs по main `2d9ac1be2058e95e355c973ddcc628dac41f30b8`, без импортов/тестов/изменений. Это описание существующих полей, не новый формат.

| Вход | Минимум действующего consumer | Чего нельзя вывести/подставить |
|---|---|---|
| Общая оболочка | fact_id/instrument_id/kind/source, venue/origin/status; значение/единица; event_ts/received_ts/expires_ts. factUsable требует USABLE, непустое значение и реальные пригодные source/receive/expiry clocks; optional usable дополнительно event≤received и возраст≤существующего TTL. Для provenance отдельно необходим evidence_ref, хотя constructor допускаетNULL. instrument_id связан с исходным BingX instrument; реальную cross-venue identity доказывает SOURCE, не совпадение строки. | Receipt/fetch/auth/account-update не заменяют generation/event clock. Незнакомые quantity/quote и отсутствующий source ID остаются UNKNOWN; native venue/quote не переименовываются. |
| Optional funding | unit=RATE_FRACTION_PER_ACTUAL_PERIOD, value={rate,period_ms}; rate и rate×100 finite, period_ms>0 и≤86400000. Текст показывает rate×100 процентов за фактический период. Оригинальные source/venue/origin/clocks сохраняются. | Годовая APR/APY/annualized estimate не является этой интервальной ставкой. Нельзя выбирать период или делить на365/8760 без первичного определения фактической rate/period/annualization. Snapshot не доказывает направление будущей цены. |
| Optional OI | value — finite scalar≥0, unit строго CONTRACTS/BASE_ASSET/USDT. Сохраняются source/venue/origin и исходные clocks. Это один срез; изменения/стороны позиций не заявляются. | USDC/USD notional не становится USDT; CONTRACTS не BASE без доказанного contract size. Для delta нужны отдельные сравнимые срезы/единицы/часы, для направления — отдельные факты. Нельзя выдавать snapshot за long/short build-up. |
| OPEN positions / карта | Эти два файла не содержат raw-OPEN-position normalizer. explainMapPlan работает только с уже пригодными map.zones_up/down (zone_id/lower/upper) и связывает пересечение с существующими entry/exit областями; структурные уровни плана сохраняются. contracts.emptyMap лишь задаёт status/zones/coverage, не квалифицирует данные. | Публичный endpoint/схема wallet positions не создаёт готовую future map. До существующего map consumer нужны отдельные source ID/OPEN/side/liq-price/units/coverage/clocks/asset и venue-price-basis proofs. Прошлые liquidation events, OI и book уровни не заменяют OPEN позиции; новый clock/zone контракт AM не вводит. |

optional_context/findings — дополнительное объяснение, без новой стратегии/весов/процентов или обязательности источника.
