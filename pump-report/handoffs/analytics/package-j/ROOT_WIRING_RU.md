# J — наблюдаемый рост за 24 часа и объяснение ручного отказа

Пакет изменяет только собственные `analytics/**`, `tests/analytics/**`, `handoffs/analytics/package-j/**`. Интеграция runtime, CLI, источника, бюджетов, публикации и статистического журнала принадлежит ROOT.

## Подключение

`analyzePump(input, profile)` принимает дополнительный факт `input.facts.growth_24h` в опубликованном ROOT формате `GROWTH_24H_UNIT = USDT_CLOSED_ROLLING_24H`. `consumeObservedDayGrowth` проверяет identity/asset/venue/market, единицу, источник, исходную квитанцию и часы, ровно 1440 закрытых минут, отсутствие пропусков, обе границы, согласованность coverage и derived_from. Время основано на принятой владельцем семантике CCXT; независимая гарантия поставщика не утверждается. Количество в суточных свечах не используется.

Суточное окно использует `first.open → last.close`. Минимум периода и заявленный процент ticker не заменяют начальную цену. Пригодный новый факт имеет приоритет в суточном окне. Отсутствующий или непригодный дополнительный факт не отменяет независимо пригодное короткое окно, полный день core-свечей либо прежний положительно квалифицированный ticker fixture path. Непригодный ticker не повышается до квалифицированного.

`day_growth_diagnostic` содержит пригодность, причину и ID принятого факта; это диагностическое поле, а не новый обязательный gate. `growth_windows[].fact_ids` и сохранённая qualification ссылаются на действительный суточный факт, когда окно получено из него. При одинаковом конце суточного и core-окна расхождение цены исключает дополнительный суточный факт; независимый короткий план сохраняется.

Новая cohort-версия `pump-analytics-v2-growth24h-20261025`. Профиль и пороги прежние. Сохранённая qualification, исходный импульс, ID, создание и истечение предыдущей волны не пересчитываются по новым границам. Выбор исходной опубликованной карточки остаётся в прежнем `selectOutcomeAnchor`: новый анализ J не меняет её t0, P0, target или прежнюю rules_version.

## Ручной ответ

Результат получает `manual_text`. Для READY это прежний `card_text`. Для отказа это обычный русский текст с доступными проверенными ценой, ростом по границам окон, отношениями активности и текущей двусторонней ликвидностью, затем конкретной причиной отсутствия плана. Неподтверждённые значения называются неизвестными; абсолютное количество native-объёма не выдумывается. Отношение к исходному импульсу и отношение самого импульса к фону названы отдельно.

Ликвидность может быть объяснена отдельно по пригодному стакану даже при отказе движения; это не меняет `ready`, `plan`, `card_text` или обязательные gates. Для NOT READY `card_text` остаётся null. Formatter ничего не сохраняет и не отправляет. ROOT может вывести `analysis.manual_text` в CLI/ручной ответ; отказ не должен проходить через enqueue Telegram или создание READY origin/outcome.

Пример — `manual-refusal-artificial.txt`, только искусственные данные. Он не доказывает пригодность рыночного источника.

## Граница доказательств

Тесты J и выбранные проверки затронутого поведения — только искусственные офлайн-проверки. Связный тест использует настоящий SOURCE loader с подставным in-memory broker, без сети. Старые полные батареи A–I и окончательная E не повторяются. Новых native HTTP, SQL, Telegram, deploy или cron в работе ANALYTICS нет. Первый native-снимок и SENT240 не пересоздаются. Их точные hash-ссылки сохранены отдельно.

Итог J: 20 PASS, 0 FAIL. В первой выбранной проверке старых случаев было 7 PASS / 1 FAIL: старый тест ожидал `CURRENT_ACTIVITY_NOT_CONFIRMED` при нулевом фоне, хотя сохранённая I уже возвращает более точную причину `VOLUME_BASELINE_ZERO_OR_UNKNOWN`. Контроль на неизменённых I index/movement подтвердил прежнее поведение. Исправлено одно ожидание в текущем `tests/analytics/analysis.test.mjs`; прежние байты сохранены в локальном baseline. Повторён только исправленный случай — 1 PASS. Это 8 разных старых случаев с итоговым PASS, а не новая полная батарея. Исходный неуспех и диагностика сохранены в TAP/JSON; отказ READY и отсутствие плана не изменялись.

Состав, SHA256, pinned зависимости, фактические результаты и освобождение собственной аренды — в `qualification.json` и `authority.json`. Копии исходного кода `baseline/**` нужны только локально для проверки преемственности; ROOT не должен публиковать эти дубли в основной пакет.
