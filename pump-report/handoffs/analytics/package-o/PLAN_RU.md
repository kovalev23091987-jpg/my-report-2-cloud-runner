# O — зафиксированный план новой статистики ценового сценария

Основание — §15 ТЗ v2, строки672–680; ROOT прямо разрешил чистое добавление после frozen N и освобождения прежней аренды. Это расчёт по уже переданным исходному plan и свечам/точкам **того же исходного четырёхчасового окна**. Никаких новых опросов, TTL, readers, anchors, entry-followup, ордеров, позиций и реальной прибыли. Две OWNER deferrals не затрагиваются: старое сопровождение входа и native storage-capacity испытания не запускаются. При выявленном пересечении остановится только затронутое действие.

## Пять scalar fields

Новый объект `scenario_outcome.entry_area_excursion`:

1. `area_floor_price`: нижняя граница однозначно выбранной достигнутой области исходного плана, либо null. Это не цена фактического входа.
2. `contact_confirmed_by_ts`: рыночное время, к которому наблюдение гарантирует касание этой области. Для свечи — её закрытие, для точного price point — время точки. Это не точное время касания внутри свечи и не время получения ответа.
3. `post_confirmation_low_observed`: минимальная пригодная наблюдаемая цена строго после точки подтверждения либо из целиком последующих свечей; null, если таких наблюдений нет.
4. `below_area_pct_lower_bound`: `100 * max(0, 1 - low / area_floor_price)`, либо null. Это **только наблюдаемая нижняя оценка** ухода ниже границы области. Пропуски и неизвестный путь в свече касания могут скрывать более глубокое снижение; точный максимум не заявляется даже при полном наборе минутных свечей.
5. `reason`: явная причина null либо `OBSERVED_LOWER_BOUND_AFTER_CONFIRMED_CONTACT`. Нулевое значение появляется только при существующих последующих наблюдениях без наблюдаемого снижения ниже границы, а не вместо отсутствующей истории.

## Контакт, границы и порядок

- Цена хотя бы одной реально наблюдаемой OHLC-компоненты полностью находящейся внутри исходного окна закрытой свечи либо точного price point должна лежать внутри области. Одно пересечение min/max диапазона с областью без такого наблюдения не доказывает контакт: `RANGE_TOUCH_ONLY`, null.
- Выбирается первая однозначно подтверждённая область. Если до момента её подтверждения другие entry areas могли быть достигнуты в том же баре/раннем диапазоне и порядок неизвестен — `FIRST_ENTRY_AREA_ORDER_UNKNOWN`, null. При нескольких entry areas и неполной истории до подтверждения — `FIRST_ENTRY_AREA_HISTORY_INCOMPLETE`, null.
- Весь первоначальный бар касания исключается из post-confirmation low: его low мог быть до касания. Используются только целиком последующие закрытые бары (`open_ts >= contact_confirmed_by_ts`) и точки `event_ts > contact_confirmed_by_ts`.
- Свечи, пересекающие исходные t0/deadline, не доказывают контакт или новый минимум внутри точного окна. Их возможный контакт может оставить неизвестную область/время; крайние low не попадают в расчёт. Точные точки внутри исходного окна пригодны.
- Ничто после исходного deadline/as_of не используется. Гапы после подтверждения не отменяют положительное наблюдение, но результат остаётся нижней оценкой. Без последующих наблюдений low и lower_bound null с `NO_POST_CONFIRMATION_OBSERVATIONS`.

Главные HIT/MISS/UNKNOWN, цель1.10*P0, исходные t0/P0/deadline/rules и остальные старые поля outcome не изменяются. Объект добавочный и необязательный для старых consumers. `execution_proven=false`, `user_profit=null` сохраняются.

## Ограниченная проверка

Два новых affected случая с вариантами: (1) контактный бар с глубоким low не выдаётся за post-entry DD; последующие бары/точки дают bounded observation, gaps сохраняют ограничение; (2) несколько областей/unknown intrabar order, boundary-only/range-only/нет последующих данных дают null/reason. Для тех же небольших fixtures старый outcome из сохранённого baseline сравнивается со всеми прежними полями нового — без повторения старых тестовых батарей.
