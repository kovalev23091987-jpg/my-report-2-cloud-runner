# BY1 — точная причина сохранённого отказа, статический разбор для ROOT

Вывод: `PLAN_INVALIDATED / CANCELLED` арифметически соответствует фактам выбранного холодным поиском импульса. На этом input не доказана ошибка выбора среди текущих кандидатов или ошибка инвалидации. Разница с прежним READY DOOD — поздний холодный старт без сохранённой первой волны. Это допустимое различие по действующему профилю и данным; оно одновременно оставляет положительную цель coldstart→готовая карточка недоказанной. Discovery исправна: настоящий runner сам создал очередь и выполнил проверку.

## Одно точное условие

В установленном72 `analytics/movement.mjs:176–177`:

```js
const invalidation=previous?.invalidation_price??impulse.low;
const observedCancel=price<invalidation||rows.some(r=>r.open_ts>=Math.max(impulse.end_ts,continuityStart)&&r.low<invalidation);
```

В BY previous=null, поэтому граница равна low выбранного нового импульса. Уже первая часть `price < impulse.low` истинна. Дополнительно17 закрытых минутных свечей после конца этого импульса имеют low ниже этой же границы. Любой из этих двух наблюдаемых признаков достаточен для отмены; это не фиксированный запрет на глубину отката в процентах. `movement.mjs:196–207` устанавливает CANCELLED, active=false, automatic_eligible=false и reason PLAN_INVALIDATED. `analytics/index.mjs:114` возвращает REJECTED до построения плана. Позднее обогащение manual-представления сохранило liquidity=USABLE; это не прохождение ветки создания готового плана.

Точные цены/low, интервалы каждой нарушившей свечи через исходные rows и полные исходные границы доступны ROOT только локально в ignored `.private/BY1_EXACT_BOUNDARIES_PRIVATE.json`, SHA256 `a05abc7718b57a38dd3d904e12ae330589af50dd1d396eda1fa5dac7c775ce64`. Private не предназначен для Git/сообщений.

## Почему выбран иной импульс

`movement.mjs:142–148` ищет положительные 5мин окна с volume ratio≥2 только за последние `wave_search_ms=3600000`, затем выбирает максимальное отношение; пригодный previous имеет приоритет. В данных BY ровно1 такое окно: 26 октября12:13–12:18 МСК,37мин до конца закрытого хвоста12:55. Арифметический пересчёт volume/baseline/ratio/low/end совпал с уже сохранённым engine output; других неотменённых кандидатов в этом60мин окне0. Поэтому предположение «максимальный ratio заслонил другой пригодный текущий импульс» здесь не подтвердилось.

Прежний DOOD.previous_wave сохранял импульс11:32–11:37 МСК,78мин до конца хвоста: он вне холодного60мин поиска. Его created=11:56:43.471, covered_until=12:28, expires=15:56:43.471 МСК. Сохранённая граница первой волны текущей ценой не нарушена; после её retained covered_until нарушений0. `usablePrevious` (`movement.mjs:127–131`) и выбор previous (`:148`) позволяют продолжить её с исходной базой и сроком без нового импульса. Это прежний warm-контекст, а не тот же самый холодный input.

В старой памяти база —12 сопоставимых5мин окон. Из нынешних125 свечей до старого импульса восстанавливаются только8: прежняя полная база на этом хвосте не воспроизводится. Простое расширение lookback не восстановит утраченные данные и не даст права объявить новый холодный READY. Все факты BY, as-of и отсутствие previous оставлены неизменными.

## Решение для review ROOT

Исправление инвалидации по BY не обосновано: отключение low-проверки или READY при отменённом импульсе ослабило бы смысл сценария. Фильтр «выбрать следующий неотменённый импульс» также не исправит этот конкретный кейс: в текущем окне другого кандидата нет. Порог роста, объём, liquidity, potential≥10%, cross-instrument priority и profile не менять ради отправки.

Если ROOT отдельно принимает требование восстановления пригодной старой волны при позднем coldstart, минимальная новая работа — ограниченное восстановление происхождения её раннего импульса и полной допамповой базы из настоящей истории на том же as-of с исходными clocks, qualification/lifetime и проверкой всего пути до текущего момента. Нельзя просто переносить historical previous в пустой проект или увеличивать срок от каждого refresh. Такой путь требует отдельного контракта/источниковой достаточности/бюджетного review; он не является доказанным бесплатным однострочным исправлением BY. Готовность восстановленной волны потребует отдельного допуска и affected проверки после review. Сейчас кодовых правок нет.

Q и AIN в этом разборе не анализировались. Причину BY нельзя переносить на них без их собственных сохранённых фактов и волн.
