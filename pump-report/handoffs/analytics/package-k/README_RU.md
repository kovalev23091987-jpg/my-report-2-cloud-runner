# K — native-relative история и исход исходной v1 карточки

Три новых искусственных интеграционных сценария проверяют настоящий SOURCE-фасад `getOutcomeHistory` с custom in-memory broker, `evaluateOutcome`, ROOT runner/journal и materialized summary в настоящем `MemoryStore`. Производственные модули и зафиксированный J не изменяются.

Пробел до K: I18 передаёт искусственные native-relative строки прямо в `evaluateOutcome`; I22 соединяет SOURCE только с текущим core-анализом; J18 проверяет суточный источник, J19 сохраняет исходный anchor при новой версии правил. E использует подставной `getOutcomeHistory` с пустыми строками. Ни один из этих тестов не проходит весь обновлённый мост SOURCE history → ROOT исход → журнал → компактная сводка. Они не повторяются в K.

K01: ровный 240-минутный и смещённый на 123 мс 241-минутный охваты дают MISS по старому P0. Вторая версия анализа J имеет другую цену: неправильная подстановка её P0 дала бы ложный HIT. Исходные t0/P0/target/rules и v1 cohort сохраняются. При смещённых границах MISS основан на полном охвате соседними закрытыми свечами; просадка остаётся неизвестной.

K02: high первой граничной свечи превышает старую цель, но не доказывает HIT внутри периода. Через реальный loader и ROOT остаётся UNKNOWN; в зрелой сводке нет HIT, наблюдение сохраняется для дальнейшей истории.

K03: повтор latest J анализа и уже разрешённого исхода одной волны не удваивает ни исход, ни cohort. Существуют два сохранённых анализа v1/v2, но одна независимая волна с исходной v1. Повтор runner после MISS не загружает историю второй раз.

Исходная v1 карточка в тесте — явно искусственный сохранённый снимок, построенный из искусственной формы анализа с исторической rules_version. Старый движок и батареи I/J/E не запускаются. Публикация SENT существует только как искусственная строка MemoryStore; транспорта Telegram нет, попытка enqueue/send завершит тест ошибкой. Сводка остаётся ARTIFICIAL, вероятность не рассчитывается.

Проверяются null абсолютных объёмов, исходная decimal-строка native количества, принятая временная семантика и исторические часы без live-expiry. Private SENT240 не читается: допустимы только уже сохранённые hash-ссылки на неизменённые артефакты. Native HTTP/SQL/TG, deploy, cron, старые ENTRY followup и storage capacity не затрагиваются. Точные SHA, pinned зависимости, guards и результаты находятся в `qualification.json` и `authority.json`.

Итог: 3 PASS, 0 FAIL, 0 SKIP; 123.259917 мс. При первом запуске во fixture был нечисловой `message_id`; действующий контракт правильно отнёс такую публикацию к UNKNOWN. Fixture исправлен на искусственный числовой ID 424242, существующий только в MemoryStore. Первичный 0/3 результат оставлен в `test-results-initial-fixture.tap`. Изменений поведения в production для исправления теста не было. Остальные старые тесты не запускались.
