## Изменения

- `analytics/anchors.mjs`: чистый выбор исходной карточки по принятой политике ROOT; API и обязательные предпосылки ниже.
- `analytics/context.mjs`: объяснения по пригодной выборке сделок, OI, funding и синхронным окнам относительной доходности. В производные признаки попадают только проверенные поля. Старые/будущие строки сделок, будущие окна, неизвестные единицы и произвольные дополнительные поля не используются.
- `analytics/index.mjs`: подключение объяснений к фактическому тексту, конкретные основания входа/выхода, контекст пересечения плана с картой. Совпадение с зоной карты не меняет готовность или цены плана. Верхняя зона до области фиксации показывается как дополнительный контекст, без утверждения об обязательной остановке цены.
- `analytics/movement.mjs`: подтверждённый возврат относится только к области вокруг возвращённого уровня. Остальные области не получают эту отметку из-за общего состояния волны. Указаны конкретные прежние вершины/минимумы и ближайшая структурная вершина для фиксации всей позиции.

| Блок ТЗ | Использование в ядре | Ограничение |

Нативный маршрут сделок источниками пока не квалифицирован |
| 3. Ликвидность | Двустороннее исполнение для пяти согласованных размеров, ограничение позиции; самостоятельная пригодность плана | Текущий стакан не гарантирует будущего исполнения |

| 5. Относительная сила | Только один и тот же закрытый интервал монеты и BTC/ETH, явные доходности и источник | Предложенный опциональный формат ниже; живой маршрут не настроен, полезность не измерена |

Дополнительные блоки влияют на фактическое объяснение, а не создают новые запреты или численную вероятность. Отсутствие любого из них сохраняет прежние требования к обязательному ядру.

## Адаптер исходной карточки

Прямой импорт: `selectOutcomeAnchor` из `analytics/anchors.mjs`.

```js
selectOutcomeAnchor({
  analyses: [{analysis_id, analysis_sha256, recorded_ts, features_known_ts, origin}],
  publications: [{event_id, analysis_id, event_ts, recorded_ts,
    state: 'SENT' | 'UNKNOWN' | 'FAILED', possible_send, message_id, receipt_ref}],
  wave_expires_ts, terminal: null | {state: 'CANCELLED' | 'EXPIRED' | 'COMPLETED', event_ts, recorded_ts},
  frozen_anchor: null | previouslySavedAnchor,
  as_of_ts
})
```

`origin` — уже принятый нормализованный вход пакета Б: instrument_id, asset_id, wave_id, signal_id, t0, reference_price, rules_version, profile_version, mode, map_mode (`NO_MAP`/`PARTIAL_MAP`/`MAP`), evidence_class, ready. На один вызов — одна пара instrument_id+wave_id и один asset_id. `analysis_sha256` — вычисленный ROOT SHA-256 неизменяемых полных байтов сохранённого анализа, включая признаки/план, а не только P0. Адаптер проверяет формат и неизменность заявленного хеша, но сам не читает хранилище и не подтверждает подлинность содержимого.

`features_known_ts` вычисляется ROOT как максимальное время доступности использованных фактов/подтверждений, включая карту. Оно не позднее t0. Учитываются использованные данные, а не игнорируемые будущие факты во входном пакете. Действительная неизменяемость raw, происхождение P0, соответствие SHA-256 сохранённым байтам и полнота журнала — ответственность ROOT; флагов «подтверждено хранение» адаптер не выдаёт.

Для выбора исходной карточки используется первое известное событие SENT либо UNKNOWN после возможной отправки. FAILED не становится якорем. UNKNOWN обязан явно иметь possible_send=true; неясная возможность отправки попадает в карантин. Некорректный SENT без пригодной квитанции сохраняет статус UNKNOWN и не превращается в UNSENT. Более поздняя квитанция разрешает UNKNOWN только при связи с той же сохранённой карточкой. В журнал нельзя задним числом подставлять более раннее время попытки вместо времени наблюдения соответствующего состояния; обе временные оси должны быть честными.

Событие выбирает сохранённый анализ. **t0/P0 берутся из этой карточки, а не из времени ACK, нового draft или поздней цены.** Для исхода используются исходная цель 1.10×P0, исходные четыре часа, версия правил и сохранённый план именно выбранного analysis_id.

При отсутствии возможных/подтверждённых отправок выбирается первый READY, но `summary_origin` остаётся null и eligible=false, пока волна активна. По завершении/истечении срока — eligible=true и UNSENT. Опубликованный либо терминальный UNSENT якорь имеет immutable=true; ROOT сохраняет его и передаёт обратно через frozen_anchor. Изменение исходной карточки, её хеша или пропуск исходного журнала приводит к QUARANTINED; автоматического сброса P0 нет. Одновременные неразличимые первые события не разрешаются удобным выбором ID.

В `summarizeOutcomes` передавать **только eligible=true**. ROOT создаёт каждый immutable record_id отдельно, recorded_ts — фактическое время сохранения конкретного исхода/состояния. Не перезаписывать одну строку под тем же record_id и не подавать каждый raw draft как самостоятельный origin. Последующие записи той же волны используют один и тот же origin. UNKNOWN/SENT/UNSENT, AUTO/MANUAL, карта/неполная карта/без карты, версии и классы происхождения разделяются существующим summary. Численная вероятность остаётся null.

## Предложенный нормализованный относительный контекст

Без изменений общего contracts и без нового источникового маршрута. При дальнейшем подключении ROOT и SOURCES должны согласовать идентичность и семантику этой опциональной формы:

```js
facts.market_context = createFact({
  // тот же инструмент; корректные source/venue/origin/часы/срок и статус USABLE
  kind: 'market_context', unit: 'RETURN_PERCENT_SAME_WINDOW',
  value: {returns: [
    {role: 'CANDIDATE', return_pct: 12, start_ts, end_ts},
    {role: 'BTC', return_pct: 1, start_ts, end_ts},
    {role: 'ETH', return_pct: -1, start_ts, end_ts}
  ]}
})
```

Нужен один кандидат и хотя бы один однозначный benchmark с точно теми же start/end. Окно закончено и доступно в момент анализа. Неизвестные/будущие поля не копируются в производные признаки. Это контрактное предложение и проверяемая интерпретация, а не утверждение о рабочем живом источнике.
