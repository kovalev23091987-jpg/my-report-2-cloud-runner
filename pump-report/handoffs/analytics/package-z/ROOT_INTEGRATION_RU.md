# Z — bounded saved-store reader действительно вызывает W

Готовый owned export: `analytics/saved-capsule-audit.mjs:auditSavedCapsules({records,read,as_of_ts,split_plan})`. ROOT runtime передаёт не более10 уже сохранённых summary rows и `read:key=>store.get(key)` из своего admitted exact reader. Нет scans/global inventory/provider fallback/latest substitution. Сам reader ничего не пишет. ROOT sourcepage/route/budget/native admission остаются отдельными.

Bounds экспортированы как SAVED_CAPSULE_AUDIT_BOUNDS:10 records,262144B входных records;90 фактических read calls,524288B отдельного readback,2000000B total read и отдельно2000000B cumulative hydrated evidence;64 analyses/64 publications каждого journal. Key length512, state namespaces allowlisted по точным ROOT formats. Повторные ключи кешируются только на время этого вызова. Byte bounds проверяются после возвращения точечного read — это не SQL byte filter/admission и не доказательство physical capacity. ROOT учитывает реальные SQL ACK/unknowns отдельно. Ошибка read и overflow останавливают весь вызов; сообщение read не передаётся наружу, private bodies не выводятся.

Реальные ключи: `pump:summary-capsule-link:v2:<summarySHA>` → wrappers feature/outcome, original analysis/input, protected refs; actual `pump:signal:<instrument>:<wave>` и `pump:journal:<instrument>:<wave>`; selected actual publication card и SENT receipt. Проверяются hashes/protected no-GC metadata, signal origin/plan/deadline/original refs, один matching journal analysis и immutable frozen anchor. `selectOutcomeAnchor` заново применяется к прочитанному journal на **исходном row.recorded_ts**, поэтому будущая publication не подменяет историческую.

Card readback сверяет source_input_key, полный исходный analysis без добавленного source_input_key, immutable text, raw text hash и фактическую формулу card ID. UNKNOWN требует существующий selected event и past send_started_ts; possible_send_ref указывает на реальный card field. Поздний текущий SENT не переписывает прежний UNKNOWN row/capsule. SENT требует actual saved card receipt, positive matching message_id, recipient/card/text binding, confirmed_ts<=row.recorded_ts и фактическое SENT event в журнале. Родной signal.publication может стать новее; reader не использует его как замену исторического summary publication.

Затем resolver отдаёт именно W format `{link,feature,outcome,saved_analysis,anchor_meta}` в существующий `auditCohortSample` с явной feature_schema_version v2. Нет новых forecast/model/training records в actual writer — reader их не ищет и не создаёт: NOT_CALIBRATED/null, feature_usefulness_proven=false/publication_allowed=false. Результат содержит только W analytic output и безопасные reader counters/codes, а не raw input/card/provider payload. `required_references_resolved` описывает чтение требуемых refs, не native authentication, качество модели или весь source history. `source_history_complete=false`, global reference closure=false, TTL=null/delete=false.

## Конкретный actual-store gap и предложение ROOT

UNSENT с настоящим journal.terminal поддержан: state/event_ts/known(recorded)_ts копируются, evidence_ref — адрес реально прочитанного `journalKey#terminal`. Если закрытие произошло лишь по wave_expires_ts и terminal не сохранён, reader возвращает explicit SAVED_CAPSULE_UNSENT_TERMINAL_RECORD_REQUIRED через W, не выдумывает closure clocks. Это подтверждено новой интеграцией Z03 через actual journal.

`ROOT_UNSENT_EXPIRY_TERMINAL_PROPOSAL.diff` — минимальный точный proposal в ROOT-owned outcome-journal, НЕ применён и НЕ выполнен. Он сохраняет actual EXPIRED terminal перед первым freeze/summary, только если ещё нет terminal и frozen anchor. Уже frozen исторические originals не получают timestamp задним числом и остаются unbound при отсутствии реального proof. Исходные summary hash/P0/t0/rules/outcome не меняются. Новую atomic запись ROOT должен учесть в своём native envelope до применения. Это одна конкретная несовместимость actual format, а не общий запрос менять policy.
