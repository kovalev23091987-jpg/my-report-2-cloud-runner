# N — минимальное исправление после полной сверки M

ROOT прямо разрешил исправление подтверждённого M-G01 и небольшой UI-пробел M-G07 после фиксации полного реестра. L/M не переписываются. Производственные изменения ограничены четырьмя собственными модулями; добавлен один новый affected test.

## Первая квалификация живой волны

Новая `RULES_VERSION = pump-analytics-v4-first-qualification-20261025`. Если manual создал живую волну с `qualification=[]`, первое позднее подтверждённое окно +20%/24ч или +10%/5/15/60м фиксируется один раз. В `next_wave.qualification_known_ts` сохраняется время первого знания положительной qualification. Это отдельные часы, а не новое время создания волны.

Проверяется `created_ts <= qualification_known_ts <= current analysis_ts` и `q.end_ts <= qualification_known_ts` для каждой сохранённой qualification. Для прежней положительной qualification без нового поля совместимый fallback — её прежний `created_ts`; сама qualification не меняется. Пустая ещё не квалифицированная волна хранит null. Несогласованные/будущие часы дают `WAVE_QUALIFICATION_CLOCK_INVALID`, false READY/automatic eligibility и null card с понятным ручным объяснением.

`wave_id`, `created_ts`, `expires_ts`, исходная impulse/baseline и прежняя положительная qualification не меняются при первом позднем пересечении, последующем откате или повторном росте. Новое окно не продлевает lifetime. При observed cancellation первая qualification не добавляется. CANCELLED/EXPIRED не оживают от старого импульса; новое независимое движение после их окончания не запрещается прежним механизмом.

Это исправление согласованного наблюдения, не новая стратегия. Auto20/10, min gross10, размеры/ликвидность, карта, статистическое +10%P0/4h и purpose-фильтр сохраняются. Первое ручное наблюдение само по себе не запускает автоматическое сопровождение: общая очередь/повод AUTO остаются ROOT.

## Пользовательский текст

`growthProofLine` больше не выводит внутренний fact_id/evidence_ref. Сохраняются подтверждённый процент и длительность окна, исходные часы, отметка прежнего пересечения, MODE/TEST и отдельное будущее статистическое событие. Полные `growth_proof.fact_ids`, evidence_ref, source/source_event_ts и original qualification остаются внутри анализа.

## Проверки и передача

Четыре новых случая — 4 PASS,0 FAIL,0 SKIP,126.036417 мс:

- N01: manual-empty → первое AUTO → откат → повторное пересечение; marker/qualification фиксируются один раз, часы/база/ID/lifetime сохранены.
- N02: CANCELLED и EXPIRED не получают позднюю квалификацию из старого движения.
- N03: future/before-origin marker и end после marker отклонены; прежняя положительная qualification совместима и неизменна.
- N04: Unicode/native-план с тремя входами и шестью зонами не показывает внутренний ID; все цены/происхождение внутри сохранены, текст <=4096 и well-formed.

Native HTTP/SQL/TG/deploy/cron=0. Старые E/F/H/I/J/K/L батареи и M diagnostic после ремонта не переисполнялись. L-образец в N04 читается только как искусственная зафиксированная форма, с проверкой SHA из manifest, и не изменяется. M описывает состояние до repair; его JSON/Markdown не генерировать заново на v4. Для сведения с ROOT используется отдельный `audit-repair-delta.json`: закрываются в коде M-G01/M-G07, остальные семь пробелов полной сверки сохраняются. Code closure не является native/production приёмкой. Исторический240, его P0/t0/цель/rules/receipt и acceptance-purpose не затрагивались.
