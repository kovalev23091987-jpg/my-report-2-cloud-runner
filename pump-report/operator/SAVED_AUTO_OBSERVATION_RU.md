# Чтение сохранённого результата первого AUTO

Этот оператор подготовлен для приёмки реальной автоматической отправки. Он не запускает анализ, не обращается к рынку, не отправляет Telegram и не расходует CONTROL или четвёртый стартовый MANUAL.

`node pump-report/operator/observe-production-once.mjs --describe` показывает план без сети, credentials или SQL. Сам файл оператора не является разрешением на выполнение.

Перед будущим `--execute` ROOT должен получить свежий main/guards и собственную bounded CAS-аренду, подготовить отдельный положительный `PUMP_PRODUCTION_OBSERVATION_ADMISSION_V1` и свежий FULL readback действующего артефакта. Допуск содержит status `ADMITTED_NOT_SPENT`, maximum_attempts1, authority_main, fresh_all4_own_CAS_FULL_verified=true, provider_whole_native_admitted=true, own_lease, expires_ts не далее15минут и не позже own lease, новый run_id, текущий implementation_sha256, full_readback_file/full_readback_sha256, native_query_cap16, market_HTTP0 и Telegram0. `card_after_key` необязателен, относится только к префиксу `pump:card:`. Подготовленный шаблон с ложными или отсутствующими полями не допускает IO.

Актуальный артефакт берётся из ROOT_BUSINESS_SCHEDULE_ADMISSION.json, сверяется его SHA и pin. Модули для native governor извлекаются из этих точных байтов в private-копию, чтобы локальное отставание checkout не меняло учёт. API-форма D1 POST/query соответствует установленному официальному Wrangler; используется его существующий OAuth. Истёкшие credentials нужно обновить до запуска оператора; секреты не печатаются.

Режим — существующий LOOKUP, максимум10 таких резервов за UTC-сутки. Shared native governor до чтения проверяет общий day ledger, unknowns, старые выданные обязательства, будущие сканы и ручные резервы. Выделение500R/30W сохраняется даже при меньшем фактическом расходе; SQL-метаданные и finalization читаются обратно. Оператор дополнительно ограничен16 SQL API attempts, 8MiB на ответ и12MiB суммарно. В бизнес-состояние он ничего не записывает: меняется только существующий ledger допуска/финализации. При неизвестном исходе автоматического повтора нет.

Читаются только executor, его последний сохранённый run, одна индексированная страница максимум20 карточек, затем одна выбранная AUTO/PRODUCTION/SENT карточка и её immutable original. Неполная страница не означает отсутствие сигналов во всей истории или полноту проверки рынка. Карточка и original с другим implementation pin не объявляются доказательством текущей сборки.

Проверяются original hash/input/режим/OBSERVED/pin, тот же анализ и текст, recipient/message_id/text_hash, исходная expiry, фактический fetch-start и parsed ACK. Допуск обязательно содержит expected_recipient_sha256, полученный из заранее одобренного назначения/прежней подтверждённой квитанции, а не из проверяемой карточки: одно совпадение card↔receipt не доказывает нужного адресата. ACK может прийти после expiry, если fetch начался до неё. Неизвестная отправка и несовпавшая связь не становятся SENT. Это чтение квитанций; независимая проверка источников и плана выполняется двумя вспомогательными чатами по сохранённым данным.

Attempt и полный ответ сохраняются отдельными `wx` файлами0600 внутри `pump-report/.private/observations/`. В stdout выводятся только статус, стоимость, hash и путь. Применение возможно после появления фактического AUTO результата или карточки, с отдельным точным допуском; один `--execute` по отдельному допуску завершён: 7 SQL / 10R / 4W / unknown0, market0/TG0, без AUTO/SENT в прочитанной области. Старый отчёт, расписания, caps/unknowns/reserves/9пауз/2OWNERdeferrals не изменяются.
