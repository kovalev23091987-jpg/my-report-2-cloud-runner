# МОЙ ОТЧЁТ 2 — ОБЯЗАТЕЛЬНЫЙ КОНТРАКТ ЗАПУСКА

Статус: текущая обязательная инструкция. Старые отчёты, черновики, доказательства и архивные версии не являются инструкциями запуска.

## В каждом новом чате

1. Сначала прочитать `REPORT2_CURRENT_GENERATION.json` из `main` репозитория `kovalev23091987-jpg/my-report-2-cloud-runner`.
2. Продолжать только если `latest_only=true`; использовать только указанные в нём workflow, runtime overlay и этот контракт.
3. Ручную команду «создай / запусти мой отчёт 2» отправлять один раз через `manual-requests/run.json`: новый уникальный `nonce`, сообщение коммита с префиксом `[manual-request]`.
4. Не подменять ручной результат плановым. Результат принимается только при точной связи `command_id → manual run → run_id → report2-run-result`.
5. Дождаться завершения соответствующего `run-report2` и читать новый артефакт `report2-run-result`.

## Обязательные 17 блоков

- Внутренний аудит обязан перечислить N01–N17 и сохранить статус каждого блока.
- Блок считается проверенным только при фактическом обращении к источнику, повторном использовании действительного кэша или подтверждённой проверке основного конвейера.
- Статусы «нет точной привязки монеты», «нужен ключ», «отложено лимитом», «отключено» и «не реализовано» не считаются проверкой.
- Полный ручной отчёт разрешён только когда для каждого выбранного кандидата подтверждено `17 из 17`.
- Если подтверждено меньше, результат обязан быть `PARTIAL_DATA_UNAVAILABLE` с фактическим числом; выдавать его за полный отчёт запрещено.

## Утверждённый внешний вид

- Ручной отчёт берётся только из сохранённого канонического `manual_text`, сформированного `manual-report-approved-layout-v1-20260927`.
- Короткая техническая сводка не может подменять утверждённую форму.
- Внешний вид Telegram остаётся без изменений и формируется существующим каноническим Telegram-форматтером.
- Картинки запрещены.

## Стратегия и фильтры

- Фиксированный фильтр движения 5% удалён и не должен возвращаться.
- Раннее наблюдение остаётся включённым по одной оценке 70; полный план входа для раннего сообщения не требуется.
- Защита от дублей сохраняется, но новая волна после подтверждённой паузы может быть отправлена повторно.

## Защита от старых версий

- Файлы в архивах и старые проверки сохраняются только как история и доказательства.
- Исполняемыми являются только пути из `REPORT2_CURRENT_GENERATION.json`.
- Нельзя удалять проверяемую историю или называть локальное изменение внедрённым без успешной облачной приёмки.
