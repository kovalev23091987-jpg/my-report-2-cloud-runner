1. Сначала прочитать `REPORT2_CURRENT_GENERATION.json` из `main` репозитория `kovalev23091987-jpg/my-report-2-cloud-runner`.
2. Продолжать только если `latest_only=true`; использовать только указанные в нём workflow, runtime overlay и этот контракт.

4. Не подменять ручной результат плановым. Результат принимается только при точной связи `command_id → manual run → run_id → report2-run-result`.
5. Дождаться завершения соответствующего `run-report2` и читать новый артефакт `report2-run-result`.

- Статусы «нет точной привязки монеты», «нужен ключ», «отложено лимитом», «отключено» и «не реализовано» не считаются проверкой.

## Стратегия и фильтры

- Автоматический полный анализ выполняется не чаще раза в 40 минут; двадцатиминутный триггер проверяет срок и очередь ручных команд. Публичные рыночные снимки собираются каждые пять минут независимо от анализа.
- В полном цикле допускаются две лучшие готовые монеты; в отдельной ручной проверке — только указанная монета. Облачный Worker сохраняет прежний предел; две проверки исполняет допущенный Node runner в GitHub Actions.
- Зарезервированы три ручных полных отчёта (до двух монет каждый) и пять отдельных анализов в сутки. Месячный резерв источника для ручных команд — 1 705 единиц; плановые запросы не могут его израсходовать.
- Суммарный HTTP-предел 164 не увеличивается. Фактические лимиты записи и чтения базы проверяются для всего цикла; служебное обслуживание старых записей выполняется порциями.

- Автоматический отбор рассматривает фьючерсы HTX с суточным оборотом от 100 000 USDT.
- Кандидаты ранжируются по свежим рыночным данным; готовность справочника не заменяет лучшую монету удобной для источников.
- Для монет вне точного справочника основной отчёт получает адрес токена из официального справочника HTX. Применяется только единственная однозначная поддерживаемая сеть и адрес; несколько вариантов, собственная монета сети или отсутствие адреса сохраняют причину пропуска. Результаты поиска DEX не становятся подтверждённой привязкой автоматически. Справочник адресов не является рыночным сигналом.
- Фандинг — дополнительный бонус до 5 баллов при подтверждённом направлении: отрицательный для лонга, сильно положительный для шорта. Отсутствие фандинга не исключает монету.

- Фиксированный фильтр движения 5% удалён и не должен возвращаться.
- Раннее наблюдение остаётся включённым по одной оценке 70; полный план входа для раннего сообщения не требуется.
- Защита от дублей сохраняется, но новая волна после подтверждённой паузы может быть отправлена повторно.

Модель разрешена только при свежих официальных данных HTX: цена, открытый интерес, оборот и измеримая волатильность; дополнительно используются финансирование, траектории цены и открытого интереса, суточный диапазон, шаг цены, доступные ступени плеча и закрытый профиль объёма. - После базовой модели выполняются доступные проверки: `HYPERLIQUID_NATIVE`, `BYK_TRACKED_HL_BANDS`, `LIGHTER_NATIVE`, `GMX_NATIVE`, `GTRADE_NATIVE`, `BYKARANTELI_FUTURE_MAP`, `COINLOBSTER_FUTURE_MODEL`, `OXARCHIVE_HL_BUCKETS`.

### Неизменяемая форма отдельного ликвидационного блока

- Пользователю выдаётся только сохранённый канонический `report_text` точного артефакта соответствующего запуска.
- Запрещено заменять его пересказом чата, короткой технической сводкой, новой таблицей или другой компоновкой.
- Обязательный порядок: заголовок `ЛИКВИДАЦИОННЫЙ БЛОК`; монеты наблюдения; углублённая проверка; сильные зоны выше; сильные зоны ниже; шкала размеров; покрытие и время снимка; сведения дополнительных источников; число источников; боковой объём; предупреждение, что это наблюдение, а не подтверждённый вход.
- В пользовательском тексте всегда показываются ровно до четырёх сильнейших разнесённых зон выше и до четырёх ниже. Уровни, полный диапазон которых укладывается в три процентных пункта, объединяются в один ценовой диапазон и не повторяют одну и ту же подпись размера.
- Для соседних ячеек одной расчётной модели HTX объёмы внутри объединённого диапазона складываются, после чего заново определяется размер: небольшая, средняя, крупная или огромная. Пересекающиеся объёмы разных поставщиков не складываются.
- Полная карта остаётся во внутреннем машинном результате. Пользовательский текст не сообщает число скрытых уровней и не выводит служебную фразу вида `ещё N уровней`.
- Исправление данных, источников или расчётной модели не даёт права менять утверждённую форму без нового прямого решения владельца.
