Основание: пользователь требует сначала полезный фактический результат всех 15 блоков на всех доступных криптоактивах HTX, затем базу реальных ликвидационных уровней по восьми внешним источникам, затем совместную проверку и только после этого Telegram. Акции, валюты и остальные традиционные активы исключены. Прежнее требование обязательного расчётного HTX liquidation fallback отменено новой прямой инструкцией владельца. Старый монитор не включать.

Ветка `autonomous/remaining-block-facts-20261004`, база main `4e7492f6dab3a531c8532b31aa3f4964373308ca` (PR99 уже принят). Этот пакет не означает приёмку MAIN, 15/15 полезных фактов на каждой монете или доставку.

### Реализовано

- N01: строгие первичные документы APT/NEAR с точной собственной монетой. Проверяются реальные числовые якоря документа Aptos; NEAR — опубликованное заявление о полностью разблокированном предложении. Документы являются контекстом: это не измеренные транзакции, не актуальный календарь последующих изменений и не торговый вес. Другие активы сохраняют `STRUCTURED_TOKEN_SCHEDULE_REQUIRED`, а не получают чужой документ. Общий существующий лимит OFFICIAL_EVENTS.
- N03: контекст финализированного перевода на нулевой адрес без утверждения о сжигании supply или buyback; контекст фактического уменьшения totalSupply между двумя точными финализированными состояниями. Причина и влияние на цену не придуманы. Solana balance diff больше не называется доказанной инструкцией mint/burn.
- N03/N04: насыщенный 256-block журнал сужается до последних 16 финализированных блоков. Исходное широкое окно не объявляется полным; повторно насыщенное остаётся открытым. Резерв максимум четыре HTTP, общий дневной/месячный лимит не увеличен.
- N07: валидная точная официальная лента без свежих событий даёт только ограниченный факт об этой ленте. HTTP error/неверный издатель/неизвестный формат не дают факт. Остальные каналы не объявляются проверенными.
- N08: точное HTX isolated open=1 даёт нейтральный факт об отсутствии ограничения открытия в этом ответе. Cross margin не выводится из isolated; двойного положительного веса N08/N09 нет.
- N10: только уже закрытый первичный сценарий той же монеты и snapshot передаётся в канонический полезный контекст. Никакого нового target/entry или ликвидационного target.
- Универсальный фильтр: действующая криптомонета не ограничивается тестовыми тикерами. По полному сохранённому ответу HTX обнаружены четыре FX исключения с пустыми tradfi_labels; EURUSD/GBPUSD/USDJPY/USDBRL исключены по точной первичной классификации. Все остальные HTX stock/tradfi labels и неизвестная классификация исключаются как раньше.

### Проверки

Локальная полная `node current-generation/validate.mjs` завершилась CURRENT_GENERATION_VALIDATED; целевые тесты 46/46. Неизменные golden fixture bytes сверены. Изменение hash canonical adapter явно внесено в историю разрешённого владельцем обслуживания; worker guard обновлён до точного нового SHA, не ослаблен. Сохранены оригинальные сжатые primary HTML и HTX wire fixture с SHA256 и указанием исторического происхождения. Контролируемый scenario тест не является реальным рыночным результатом.

Облачный push workflow проверяет точную сборку и прежние integration/runtime controls. Отдельный bounded source probe получает свежий полный активный каталог, один общий HTX risk ответ для всех криптоконтрактов, два официальных vesting документа и одну официальную BTW ленту. Максимум восемь transport, только существующие quota/cache записи, ноль deep/canonical/Telegram. Матрица различает реальные общие факты и маршруты, которые в этом probe не исполнялись. Облачный результат ещё требуется.

### Нерешённые требования

Нет утверждения, что все 15 дают факт по каждому активу. Все 15 назначены каждой допустимой монете, но невозможный/непроверенный источник не красится зелёным. Нужны фактическая облачная приёмка нового пакета, расширение точных источников остальных активов и совместный fresh MAIN. Полноценный 24h signed HTX raw flow остаётся незакрытым; свечной оборот его не заменяет. Текущий runtime рассчитан на USDT perpetual; остальные виды HTX crypto futures требуют явной проверки поддержки, не объявляются автоматически покрытыми.

После приёмки первого этапа: восемь внешних будущих liquidation routes, внутренняя per-asset/per-source база с еженедельным обновлением. Покрытие >=1 настоящего числового источника; использовать все доступные, физически общий upstream дедуплицировать; uncovered не запрашивать и расчётный HTX model не сравнивать. MAIN сохраняет две лучшие монеты и проверяет каждую отдельно. Standalone сразу сообщает наличие покрытия. На этом этапе ликвидационная логика ещё не изменена.
