## Выпуск изменения

- В допущенном GitHub Node runner полный цикл проверяет две лучшие готовые монеты; отдельная ручная команда — только точную монету. Cloudflare Worker сохраняет прежний предел 50.
- Автоматические попытки полного анализа ограничены интервалом 40 минут; неудачная попытка тоже расходует интервал. Пятиминутный сбор публичной истории продолжается независимо. Ручная очередь проверяется до ограничения планового цикла.
- Бюджет рассчитан на 36 полных циклов по две монеты, три ручных отчёта по две монеты, пять отдельных анализов и три дополнительных проверки в сутки. Худший месяц: 13330 единиц при рабочем пределе 13500; SQL защищает резерв ручных команд 1705.
- Общий HTTP-предел остаётся 164; Node распределяет его 96/56/12 между основными, дополнительными и статистическими обращениями. Допуск каждого глубокого анализа резервирует его стоимость.
- Суточное планирование базы: до 47 аналитических запусков, предел каждого 54000 чтений / 840 записей. Расход дополнительно проверяется фактически.
- Служебные удаления используют прежние сроки, но порции не больше восьми строк. Это предотвращает расход сотен записей за один глубокий анализ. Свежие строки сохраняются.
- Отбор не заменяет лучшую монету монетой с удобным справочником. Фандинг остаётся дополнительным бонусом до пяти баллов, отсутствие фандинга не исключает монету.
- N13 и N17 удалены; все 15 оставшихся блоков должны иметь честный фактический статус. Неполный отчёт не считается полным.
- Источники, модель и пользовательская форма ликвидационных данных не изменены. Обслуживание старых строк не является изменением модели.

Локальные проверки кода и тесты прошли. Облачная приёмка двух кандидатов и всех блоков ещё НЕ подтверждена. Telegram отложен по последнему указанию владельца до приёмки основного отчёта.

Это подтверждает исполнение двух кандидатов и устранение прежнего превышения бюджета, но НЕ приёмку полного отчёта: USELESS проверены семь блоков, PUMP — пять. Выявлена ошибка повторного использования общего свежего ответа HTX внутри одного строгого ручного запуска: второму кандидату возвращался `ALREADY_RESERVED_NO_REDISPATCH`. Исправление разрешает переиспользование только ответа из того же `run_id`, с живым временем источника, с отдельной точной проверкой каждого контракта; следующий ручной запуск заново обращается к HTX.

Отдельные ограничения остаются: нет подтверждённых адресов и официальных лент для выбранных монет, свежая шестичасовая история пока не накоплена. Нельзя считать такие блоки проверенными, выдать предположения за факты или утверждать, что отчёт готов целиком.

## Официальная привязка адресов для основного отчёта

Новый маршрут читает публичный `/v2/reference/currencies` HTX и хранит компактный справочник на шесть часов. Реальный ответ без ключа содержит 1699 валют, из которых 820 имеют единственный поддерживаемый токен-адрес. Это справочник валют HTX, а не утверждение о покрытии всех 370 фьючерсов. PUMP и PEPE привязаны точно; USELESS отсутствует; NEAR требует отдельного маршрута собственной сети.

Настроенная точная привязка имеет приоритет. Несколько разных адресов, смешение собственной монеты и обёрнутого токена, неподдерживаемая сеть, неизвестная валюта, ошибка источника или лимит не дают автоматического подтверждения. Адреса из поисковых DEX-ответов остаются кандидатами. Основной маршрут больше не тратит запросы на такой неподтверждённый поиск; отдельный ликвидационный режим сохраняет прежнее поведение. Один общий ответ HTX обслуживает обе выбранные монеты; максимум восемь запросов справочника в сутки, общий HTTP-бюджет не увеличен.

Секторный источник также больше не ограничен только категориями Oracle и DeFi. При точном адресе и символе монеты принимается категория, одновременно подтверждённая метаданными монеты и единственной записью справочника CoinGecko. Сравнение по-прежнему требует свежей цены этой монеты и как минимум трёх свежих независимых монет сектора. Широкая принадлежность к сети, дубли и устаревшие котировки не заменяют сектор. Дневной и минутный лимиты источника, ограниченный вес и пользовательская форма сохранены.

Это исправление запуска маршрутов и точной привязки данных. Оно не создаёт отсутствующие официальные ленты событий, не обещает поддержки всех собственных блокчейнов и не означает приёмку 15/15. Новая облачная проверка ещё требуется.
