## Порядок входа нового чата

1. Прочитать `AGENTS.md`, свежий main ref, `checkpoints/CLOUD_PHASE_STATE_20261004.json` и `audit-fixes/source-optimization-20260930/execution-lock.json` одним пакетом. Проверить owner/lease/fence; перед действиями получить и прочитать обратно собственный ограниченный CAS lease.
2. Читать три рабочие записи из `AGENTS.md`: правила, `checkpoints/CURRENT_PROJECT_STATUS.json`, `checkpoints/OWNER_REVIEW_RESUME_POINT_20261010.json`. В больших JSON сначала читать `active_working_state`, `current_task`, `next_action`; старые `latest_*` и `history` — только доказательства своего времени. Три последних immutable evidence receipt перечислены в `checkpoints/ACTIVE_WORKING_WINDOW_20261012.json`.
3. Читать `REPORT2_CURRENT_GENERATION.json` для точного runtime, полный реестр только для незакрытых требований, затем целевые исходные доказательства и код. Не запускать старые установщики и не применять WIP patch целиком.
4. Выполнять один крупный пакет с общей проверкой, сохранять в GitHub статус, phase, register, resume и точную следующую точку. Исторические файлы сохранять. Не объявлять новый источник пригодным по каталогу или HTTP 200.
