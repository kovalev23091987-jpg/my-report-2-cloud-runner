# Исходные часы N10: итоговый факт и потребитель

Только offline-предложение координатору. Общие production-файлы не изменены.
Рабочая ветка начинается от main `0080851276223fdd6c7dfa111bbaf2efe3f5cb87`;
двухфайловый patch подготовлен **поверх центрального runtime
`05ce093e9e4428ffec5e15d5bc677044346a2f53`**, уже содержащего 519 и silent TTL.
Этот head принадлежит выполненной центральной проверке 39230121599, а не новому
native запуску. Её общий failure из-за K01 не объявляется успехом всего workflow.

Найден новый конкретный разрыв: worker сохраняет `trajectory.available_ts` после
завершения четырёх параллельных компонентов. Это консервативная граница доступности
результата, не время первого сетевого байта. `buildHtxPrimaryTechnicalReceipt`
не передаёт её итоговому 15m факту, и `buildEvidenceV2` назначает
`first_known_ts=now` при поздней сборке. Source timestamp при этом остаётся концом
закрытого окна. Новый optional аргумент сохраняет исходную доступность; проверяется
`source_ts <= first_known_ts <= observed_ts`. Истечение по старому закрытому окну
не продлевается. При отсутствии acquisition metadata прежний консервативный
assembly timestamp остаётся как legacy fallback, без утверждения о точном
получении оригинала. Неверная явно заданная граница не подменяется новым временем;
отдельный пригодный диапазон закрытых свечей сохраняется.

Второй разрыв — проекция: 12 точных N10 квитанций STRK/WLD из 39164519816 и
龙虾/CT из 39220988644 содержат source/observed, но не first-known/expiry.
Полный canonical по коду сохраняет evidence в `canonical_json` целиком;
runner сознательно делает компактный artifact без metadata. Поэтому это
**не доказанная потеря полного evidence в базе**. Нативные полные тела этих N10
и их acquisition clocks в компактных ZIP отсутствуют и не реконструировались.

Patch добавляет `original_clock` только к подтверждённым N10 фактам и техническим
квитанциям их реального отображения. Поля пересчитываются из актуального exact
canonical evidence при текущей проверке потребителем; сохранённый supporting
clock не становится авторитетом. Нет нового admission, causal ACK, автоматического
refresh или продления срока. Времена остальных блоков и состав представленных
N12 origins/composite helper из 519 сохранены.

## Проверка

Один новый affected набор из восьми случаев: исходно **7 PASS / 1 FAIL**, затем
**только отказавший случай 1 PASS / 0 FAIL**. Первая ошибка была в Telegram
фикстуре без пригодного направления; явно controlled OBSERVE display задан только
в этом случае, без заявления о source-role admission/ENTRY/SENT. Runtime patch
между этим запуском и повтором не менялся. Первые два входа остановились до
семантических случаев: URL с пробелом и шесть отсутствовавших inherited imports.
Оба исходных журнала сохранены. Семь прошедших случаев не повторялись; старые
419/425/426/427/431/432/514/519 и другие принятые suites/probes не запускались.

Локальная проверка использует exact central override files и шесть inherited
модулей по сохранённому manifest/overlay. Это замыкание импортов для affected
проверки, **не полный расшифрованный production runtime**. Все inherited hashes
перечислены отдельно. Получение ключа/payload/установка не выполнялись.

CONTROLLED CT пример использует OHLC и source/decision clocks сохранённой строки,
но более раннюю доступность и raw envelope задаёт явно. Разница
35589 ms поэтому является контрпримером кода, не измеренным опозданием native
получения CT. Actual producer → canonical builder → `JSON.stringify` → mock
INSERT/SELECT → consumer проверены. Два mock SQL вызова не являются native SQL
или доказательством durable readback.

Проверенный текст ручного отчёта и approved V5 Telegram: **0 байт изменения**.
Для двух N10 строк в двух audit-поверхностях добавилось **1032 UTF-8 байта**.
Прошедшие source/firstknown/expiry/window/policy metadata не заменяют исходные
часы и не входят в текст. Последующие native R/W, persistence multiplicity,
wire size, CPU/heap, суточная ёмкость и стоимость не измерены; резерв не уменьшать.
Сохраняются score/порог 70/стратегия/веса/формы/паузы и общие caps.

## Центральное применение

Применять только `shared-original-clocks.proposed.patch` к соответствующим
двум файлам после проверки before hashes. Не перезаписывать файлы целиком,
не трогать silent TTL/terminal/reconciler/sidecar и overlay registration.
При новом head сверить только затронутые строки; соседние 519 изменения сохранить.

Для одной будущей центральной affected-проверки использовать
`original-clocks.test.mjs` с `REPORT2_CLOCK_BASE_RUNTIME=<exact05/src>` и
`REPORT2_CLOCK_RUNTIME=<new assembled/src>`. Повтор старых test modules не нужен.
Локальные build/verify helpers не активируют runtime. `.runtime` удалён из
публикуемого пакета.
