# Минимальный контракт для координатора и anomaly lane

Текущий `runner/htx-compact-4h-history.mjs` выводит price-only rows, а исходные `*.raw.json.gz` уже содержат native `trade_turnover`. Не заменять существующий формат и не менять его `volume_qualified:false`. Ввести отдельную явно историческую проекцию только для разрешённого offline replay/statistics потребителя после peer review.

Вход существующего аналитического потребителя: `contract`, `period=4hour`, `quote_currency=USDT`, `open_ts/end_ts`, OHLC native lexemes, **native `trade_turnover` lexeme**, raw body SHA + row index, original response `source_ts`, original receipt `first_known_ts` и его ограничение. Преобразование quoted turnover в используемый потребителем decimal/number — отдельная явная операция с контролем диапазона; исходная лексема остаётся в evidence. Сохранённый архив уже привязан к exact USDT-M execution instrument, но не доказывает project/onchain identity или spot availability.

Конкретный существующий вход — `anomaly-research/observer/observer.mjs: detectClosed({instrument,timeframe,alignment_offset_ms,bars,provenance,known_ts,mode})`. Его `validBar` уже требует OHLC+`volume`, что и было missing input в price-only projection. Минимальное соответствие для третьего исполнителя: `timeframe='4h'`, offset0; `start_ts=open_ts`, `end_ts=end_ts`, OHLC из исходных лексем и `volume=Number(native_lexemes.trade_turnover)` после явной finite/range проверки с сохранением exact lexeme рядом. Instrument: HTX / HTX upstream / exact `contract` / FUTURES / quoteUSDT / `price_unit=USDT_PER_BASE` / **`volume_unit=QUOTE_USDT`** / multiplier1 / native endpoint+raw ref как binding_ref. `asset_id` должен обозначать именно HTX-native instrument, без crossvenue project binding. Это сравнение quote turnover с quote turnover того же инструмента и периода, а не coin/contract volume.

Provenance: exact original raw gzip path + **uncompressed body SHA** (не gzip SHA), `source_as_of_ts=native.source_ts`, `received_ts=native.first_known_ts`, `evidence_class='RETAINED'`; `known_ts=native.first_known_ts`, `mode='REPLAY'`. Сохранить caveat receiptclock. Такой вызов даёт только BACKFILLED-геометрию и не доказывает своевременную регистрацию до ценового движения. Source worker этот observer не запускал: изменения/qualification его поведения принадлежат третьему. Для 1d/1w требуется отдельная явно derivedUTC маркировка и source refs, не переименование native4h в native1d/1w.

Если нужен daily/weekly baseline, использовать только `derived_utc` complete buckets с исходными 4h row indices и **max original first-known**. Состав и ширину baseline выбирать в anomaly lane по реально имеющимся complete buckets каждого контракта. Наличие20week buckets само по себе не даёт prospective performance/accuracy, не покрывает partial contracts и не создаёт samples, независимые от backfilled history.

Потребитель не должен: импортировать архив в online N05/N10/N12 автоматически, конструировать15m из4h, датировать первое знание candle close, заменять неизвестное нулём, выводить taker direction/buy/sell, делить both-sides turnover на2, суммировать `amount/vol/trade_turnover` между собой, присваивать score/ENTRY/admission. Raw/native/fullbody ACK и текущая source freshness остаются отдельными непройденными границами.

Этот пакет не содержит shared patch: доступного saved raw→historical volume DTO достаточно для конкретного потребителя третьего исполнителя, который владеет anomaly/statistics. После принятия координатор может перенести **этот source-specific adapter** в согласованный offline путь и связать с существующим исследованием; отдельную архитектуру и production activation пакет не предлагает.
