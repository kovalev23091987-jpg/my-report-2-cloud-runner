# Минимальный контракт для координатора и anomaly lane

Текущий `runner/htx-compact-4h-history.mjs` выводит price-only rows, а исходные `*.raw.json.gz` уже содержат native `trade_turnover`. Не заменять существующий формат и не менять его `volume_qualified:false`. Ввести отдельную явно историческую проекцию только для разрешённого offline replay/statistics потребителя после peer review.

Вход существующего аналитического потребителя: `contract`, `period=4hour`, `quote_currency=USDT`, `open_ts/end_ts`, OHLC native lexemes, **native `trade_turnover` lexeme**, raw body SHA + row index и original response `source_ts`. Legacy поле source DTO `first_known_ts` следует читать только как **`original_recorded_receipt_ts`**, с признаком `BODY_COMPLETION_UNCONFIRMED`: старый collector ставил его после headers, до полного body-read. Это не доказанное время первого знания всего тела. Значения `original_body_completion_ts` и `original_true_first_known_ts` остаются `NULL`. Архив и его original clocks не переписываются.

Конкретный существующий вход — `anomaly-research/observer/observer.mjs: detectClosed({instrument,timeframe,alignment_offset_ms,bars,provenance,known_ts,mode})`. Его `validBar` уже требует OHLC+`volume`, что и было missing input в price-only projection. Минимальное соответствие для третьего исполнителя: `timeframe='4h'`, offset0; `start_ts=open_ts`, `end_ts=end_ts`, OHLC из исходных лексем и `volume=Number(native_lexemes.trade_turnover)` после явной finite/range проверки с сохранением exact lexeme рядом. Instrument: HTX / HTX upstream / exact `contract` / FUTURES / quoteUSDT / `price_unit=USDT_PER_BASE` / **`volume_unit=QUOTE_USDT`** / native endpoint+raw ref как binding_ref. `asset_id` обозначает HTX-native execution instrument, без crossvenue project/onchain binding или spot availability.

`multiplier=1` допустим **только как identity unit-conversion coefficient** для уже выраженных в USDT turnover и USDT-per-base цен: исходные значения не умножаются и не делятся. Это **не native contract size, face value, lot size или исторический contract epoch**; они здесь `UNKNOWN` и не нужны для raw `trade_turnover`. Если consumer трактует свой `instrument.multiplier` как contract size, этот mapping применять нельзя до явного разделения смыслов. Proposal не разрешает подставлять1 в native contract registry. Сам source DTO multiplier не содержит.

Для функционального `known_ts` требуется отдельный **conservative verified-body known-by** marker: фактически зафиксированное время **после** полного чтения exact original body, сверки его SHA и завершённого parse. Либо нужен независимо сохранённый поздний marker, который доказуемо относится к такому завершению именно этого тела. Его provenance обязан содержать `verified_at_ts`, основание часов, original raw ref + **uncompressed body SHA**, ref/hash сохранённого verification receipt и явные full-read/hash-match/parse-complete результаты. Нельзя автоматически взять время headers, candle close, file mtime, дату начала проверки, сегодняшнее `Date.now()` без завершённого чтения или local Git commit timestamp как доказательство native completion. У этого documentary исправления такого нового actual marker нет: **`verified_body_known_by_ts=NULL`, `known_ts=NULL`, вызов observer не выполняется**, пока consumer не сохранит допустимое доказательство.

После такой фактической проверки consumer может передать `known_ts=verified_body_known_by_ts`, `mode='REPLAY'`, `evidence_class='RETAINED'`, `source_as_of_ts=native.source_ts`, а `provenance.received_ts` — тот же **момент проверенного получения сохранённого тела consumer-ом**, не новое время provider acquisition. Original recorded receipt остаётся отдельным полем/ref вместе с `BODY_COMPLETION_UNCONFIRMED`. Marker не должен быть раньше source/recorded clocks или представленных свечей. Source freshness, native clocks и old DTO не обновляются. В resulting historical card имя `first_known_ts` обозначает только эту консервативную **known-by границу**, не истинное исходное первое знание; сохранить эту оговорку в связанном evidence. Только BACKFILLED, без своевременной регистрации события/exante performance/native delivery ACK.

Если нужен daily/weekly baseline, использовать только `derived_utc` complete buckets с исходными 4h row indices. Их сохранённый `first_known_ts` также является максимумом **recorded receipt clocks**, не подтверждением полного знания bucket. Functional known-by — максимум подтверждённых verified-body markers всех представляющих bucket оригиналов; если хотя бы одного нет, значение `NULL` и observer не вызывается. Состав baseline выбирается по реально имеющимся complete buckets каждого контракта. Наличие20week buckets само по себе не даёт prospective accuracy, не покрывает partial contracts и не создаёт независимых samples. Для1d/1w нужна явная derivedUTC маркировка, не переименование native4h в native1d/1w.

Потребитель не должен: импортировать архив в online N05/N10/N12 автоматически, конструировать15m из4h, датировать первое знание candle close, заменять неизвестное нулём, выводить taker direction/buy/sell, делить both-sides turnover на2, суммировать `amount/vol/trade_turnover` между собой, присваивать score/ENTRY/admission. Raw/native/fullbody ACK и текущая source freshness остаются отдельными непройденными границами.

Этот пакет не содержит shared patch: доступного saved raw→historical volume DTO достаточно для конкретного потребителя третьего исполнителя, который владеет anomaly/statistics. После принятия координатор может перенести **этот source-specific adapter** в согласованный offline путь и связать с существующим исследованием; отдельную архитектуру и production activation пакет не предлагает.
