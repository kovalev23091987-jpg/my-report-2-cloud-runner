# Сохранённые HTX 4h: native quote turnover

Новый source-only proposal извлекает уже присутствующий `trade_turnover` из 37 сохранённых оригиналов HTX. Принятый price-only normalizer раньше сохранял только OHLC и фиксированное 90-дневное окно. Его код, файлы, статусы и результаты не меняются. Новый адаптер использует весь сохранённый ответ, поэтому часть пакетов содержит почти 200 дней закрытых 4h-свечей.

Источник состава — frozen PR531 / `cc69eb7c09df8cb29ce92eff78703d9d249ce10a`, раздел `HTX_4h_actual_manifests.records`. `cohort-inputs.json` содержит точную копию только этого раздела с original paths/bytes/SHA. Это повторное использование готовой inventory; новая проверка относится к ранее отсутствовавшей проекции объёма и её потребителю, а не к повторной acquisition/inventory qualification.

Для точного `linear-swap-ex/market/history/kline`, `contract_code=…-USDT`, `period=4hour` [официальная CN-документация HTX](https://huobiapi.github.io/docs/usdt_swap/v1/cn/) определяет `vol` как объём контрактов, `amount` как объём монеты, `trade_turnover` как сумму стоимости сделок с учётом размера контракта и цены. Поля описаны как учёт обеих сторон. Адаптер сохраняет нативный USDT turnover без деления на два, перевода через текущий contract registry, выбора исторического face-value epoch или реконструкции buy/sell. Поля `amount`, `vol` и `count` также сохраняются, но не подменяют quoted turnover. Это aggregate traded turnover, не направленный taker flow N05/N12.

`htx4h-native-turnover.mjs` — чистая offline-функция для конкретного сохранённого flat JSON-формата этого endpoint. Она сверяет exact request/channel/contract/period, original bytes/SHA, исходные request/response/receipt clocks, OHLC, числовые границы, сетку и порядок. Дубликаты ключей и строк отвергаются. Неподдерживаемый формат требует отдельного конкретного оригинала и изменения proposal. Это не новый collector, validator registry или runtime framework.

Каждая строка сохраняет **исходную числовую JSON-лексему**, в том числе экспоненту и дробные разряды, `source_row_index`, границы свечи с исключающим правым краем. Указатель поля — `/data/{source_row_index}/{field}` в теле с указанным SHA. Точная decimal-арифметика используется только для явно производных сумм; нативные строки не округляются. Значения отрицательные, нечисловые, с чрезмерной величиной/экспонентой, неверные clocks, index/mark endpoints и незакрытые OHLC отвергаются. Нулевая native trade-свеча допустима только из exact trade endpoint; пропуски не заполняются нулём.

В архив попадают свечи, закрытые на **исходный HTX response `ts`**, а не на время сегодняшней обработки. Forming-строка исключается с сохранением её индекса и причины. Дыры остаются явными. `first_known_ts` у исторических строк равен original `receipt.received_ts`, а не давней границе свечи. В старом acquisition-коде этот timestamp устанавливался после получения headers, до полного чтения body. Мы сохраняем именно записанный receipt clock и явно **не** выдаём его за точное время завершения загрузки/первой обработки, wire ACK или prospective causal proof. Уточнённого timestamp оригинал не содержит. Нет исторического admission «в момент свечи».

Дополнительные DAY и WEEK_MONDAY — **производные UTC** buckets из 6/42 последовательных закрытых 4h строк. Это не ответы native day/week endpoint и не 15m. Только полностью представленные календарные buckets получают OHLC и точную сумму native turnover; неполные перечислены отдельно. Первое известное время производного bucket — максимум original first-known всех строк (здесь один receipt на контракт). Отдельные контракты/пакеты нельзя суммировать как независимые источники, а оба volume-поля/стороны нельзя повторно добавлять к turnover.

`qualified-cohort.json.gz` содержит полный связанный результат с original file hashes. `qualification-summary.json` — размер, SHA compressed/uncompressed, все 37 контрактов, полнота и ограниченные примеры. Старая cohort `27 COMPLETE +10 PARTIAL` остаётся именно старой 90d price-only оценкой; новое количество календарных buckets оценивается отдельно, без объявления current105 coverage.

Проверка запускается **один раз** новым `qualification.test.mjs`: весь actual cohort → original hash/lexeme/clock → 4h → derivedUTC + controlled adversarial deltas. Старые450/455, acquisition, native inventory37, source normalizers и прежние suites не импортируются и не запускаются. Полный новый TAP сохраняется. Для проверки повторяемости архива достаточно SHA/gzip headers; принятую suite не нужно перезапускать без нового дефекта.

Нет production imports, новых HTTP/SQL/WS, schema/deploy/MAIN/manual/TG, score/ENTRY, изменений лимитов/unknown/резервов или deferred ENTRY/physical-storage работы. Этот пакет не доказывает runtime delivery, native cache ACK, стоимость production persistence/CPU/heap или текущую пригодность источника.
