# Связанный пакет первичных данных и истории BingX

Подготовка исправляет конкретные несовместимости существующей цепочки: общий каталог содержит USDC, старый Worker распознаёт ответы HTX вместо BingX, история требует отдельной идентичности инструмента и исходных часов. Новые данные не переименовывают историю HTX.

`USDT_M` здесь является именем семейства маршрутов swap API. Расчётная валюта внутри него остаётся отдельным полем: USDC не преобразуется в USDT. COIN-M не объединяется с ними. Фактический каталог содержит 1278 записей, из них 984 со status=1; это ещё не число допустимых криптовалютных бессрочных контрактов.

ROOT связывает три готовых предложения: адаптер фактической формы ответа SOURCE, обработку истории 636 и преобразование наблюдения в типизированную строку THIRD. Новый LAST_REFERENCE является только наблюдением, требует оригинальные часы и отдельный момент решения; верхняя граница его возраста — 5 минут. Это новое ограничение контекста цены, а не изменение отложенных ENTRY-followup/recheck/TTL или разрешение входа. LAST не заменяет стакан, исполнение или единицы объёма.

Если выбран BingX, незавершённый DeepCheck обязан остановиться до старых запросов HTX. Внутренний reader может дать частичное наблюдение и предложение строки истории. Это не постоянный provider-допуск, не запись в D1, не переключение production и не готовый отчёт. Отсутствие установленного reader/реестра остаётся явной ошибкой подключения.

BTC-реестр в этом пакете — отдельная исследовательская когорта одного инструмента. Полный криптовалютный N неизвестен. Привязка к первичным документам описана в BTC-venue-identity-review.json; текущая открытая страница правил вернула навигационную оболочку. Вывод о margin отдельно отмечен как вывод, не native readback. Независимая проверка хеша не является native admission. Остальные 1277 записей этим реестром не допускаются.

Все исходные семь API-запросов уже выполнены по разовому разрешению. Их тела остаются в защищённом tmp; этот пакет не повторяет запросы. Новая проверка кода использует явно контролируемые входы. Прежние принятые проверки не запускаются повторно. Общая проверка начинается только после фиксации всех конечных модулей, импортов и независимых ожидаемых привязок; фактические возвращённые и частичные результаты сохраняются перед следующими утверждениями и компонентами.

Пока открыты постоянный общий/provider-допуск и его D1-затраты, полная классификация каталога, native units, целевой collector, частота полного обхода, исполнение стратегии, Telegram и отдельный блок аномалий. Два отложенных владельцем направления и независимый аудит сохраняются.
