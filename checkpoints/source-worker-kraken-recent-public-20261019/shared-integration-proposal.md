# RECENT_PUBLIC fallback: конкретная граница интеграции

Новый `normalizeKrakenRecentPublicN12` принимает `contract`, `window_plan={plan_id,known_ts,window_end_ts}`, три carrier `{body_utf8,receipt}` для HTX currencies/Kraken AssetPairs/RECENT_PUBLIC Trades и `now`. Каждое исходное тело сверяется с wire receipt, после parse отдельно сохраняется payload SHA. Только DOT/ATOM native pilot имеет проверенные исходные тела; расширение других native активов требует собственного exact reference/input, не каталожной заявки.

1. Если в разрешённом source path **уже имеется** RECENT_PUBLIC page, сохранить body/URL/status/received/bodySHA и исходный window plan в private in-memory carrier. Статические HTX/Kraken references взять из уже имеющегося точного body/receipt, с исходным available clock и TTL; не читать БД или источники повторно ради этого эксперимента. Cold shared pipeline, где полного reference body нет, не получает будто бесплатный доступ из одного descriptor/hash: этот carrier тогда не закрыт.
2. Если page отсутствует, новая функция не делает HTTP fallback сама. В сегодняшнем `collectKrakenFlow` запросы являются SINCE history, так что предлагаемая схема **не доказывает0 дополнительных HTTP для текущего runtime**. Возможное получение RECENT_PUBLIC — централизованный новый source-order/admission пакет в прежнем5HTTP/caps, не замена доказанному полному N05 маршруту по умолчанию. В этой ветке source acquisition отсутствует.
3. Принятый strict505 SINCE/full240 result сохраняет приоритет. RECENT_PUBLIC нужен только как отдельно квалифицированный bounded факт, когда пригодного N12 Kraken факта ещё нет. Provider/upstream/metric family и physical root `KRAKEN_BOUNDED_SPOT_TRADE_SAMPLE:contract:lastID` совпадают с505: нельзя прибавлять его как вторую биржу, второй независимый голос или суммировать перекрывающиеся сделки/окна. Конфликтующий hash одного event identity не превращать в успех; сохранить точное противоречие/выбор trusted carrier.
4. Новый verifier `verifyKrakenRecentPublicN12` пересчитывает row по полному carrier в памяти. Изолированный compact persisted row без исходного carrier не получает такое же доказательство. Если будущему manual/archive reader нужен отдельный compact validator/receipt trust, это отдельная явная граница, которую надо реализовать и проверить; не подменять её digest alone или native cache ACK.
5. Общий N12 allowlist/formatter у координатора. Для этой carrier kind использовать нейтральный existing bounded trade формат с именем Kraken; сохранить оба source/received clocks, conservative firstknown policy, saturated/whole-window-false, все IDs и единицу USDT. Значения — raw price*base amount sums, не native quote-volume field. Стратегический direction/score/ENTRY и LIQ targets не создаются.
6. Firstknown на историческом положительном примере консервативно1791648709892, после max required paired receipt1791648650537. Это сохранённый completed marker результата, не первый вызов decision predicate. Старые DOT/ATOM SINCE380662 до proof qualification не получают позднюю ссылку задним числом. Новая producer entry не имеет права назначить firstknown ранее необходимого reference или заменить source time временем чтения.

## Уточнение N10 archive cohort guard

`n10-owner15-scope.proposed.patch` применим к frozen504 `kraken-n10-price-path.mjs` с baselineSHA изn10-guard-proposal.json. Меняются начальная причина отказа approved-contract guard, комментарий о списке и explicit `runtime_input_qualified:false` в отказе после inspection. Сам raw inspection и весь fresh exact HTX spot reply block остаются прежними; последний проверен byte-exact. Проверяется новая изолированная proposed copy, не frozen источник. Список15 не удаляется из N15 history contracts. Общие N05 collectors/runtimeimports/registry и working routes остаются без изменения.

Перед центральным объединением правки нужно заменить в тесте504 прежнее ожидание `OWNER_EXTERNAL_SPOT_NOT_ALLOWED` для всей archive cohort на отсутствие runtime admission без exact raw/spot inputs; unknown106 по-прежнему отказывается approved scope. Это исправление предмета gate, а не разрешение выдавать неподтверждённый спот15 монет за пригодный. N15/hourly запрет сохраняется.

Одна последующая общая интеграционная проверка должна связать разрешённый исходный carrier → новый normalizer → выбор единственного N12 Kraken факта → manual/Telegram payload. Native request/DB cost/current105 coverage/SENT остаются неподтверждёнными до фактического центрального exact run. Source worker не выполняет такую acquisition и не меняет общие файлы.
