## Конкретная граница

Принятый kernel требует caller-owned admission перед SQL. Отдельный kernel CONTROLLED result не даёт Worker живой reservation/day/HTTP capability. Простая передача boolean allowed либо prepared без durable ORIGIN позволила бы новую карточку/knownclock при повторной обработке старого события. Финальный root contract: Worker передаёт только logical_event_id и pure synchronous prepare_from_origin. THIRD владеет одним bounded existing bundle ORIGIN reader/verifier/resolver; source не дублирует SQL. Этот runner closure владеет SAME instrumented env.DATA_DB и действительным parent context. Новые runtime-файлы source не добавляет.

Normal initial/state-only revision path = ORIGIN + WRITE + READBACK, три SDK RPC. Exact already-retained observation = только ORIGIN; duplicate не объявляется новой durable observation. Число SQL templates/внутренних trigger operations не равно числу RPC/native rows. Новое ORIGIN чтение имеет реальную ненулевую цену, текущая native цена/plan неизвестны.
