# HTX empty same-run envelope and existing positive cache

This protocol precedes the callable. No source module, test, SQL or provider is executed by the source worker.

The actual worker always supplies a `same_run_htx_trades` object. A missing, failed or wrong-contract payload can therefore return an empty reconciliation before the collector's existing exact cache validation. This is a code counterexample, not a claim that a particular natural run lost a qualified fact.

The proposal changes only TEXT for the existing `src/htx-large-trades-evidence.mjs`. A completed same-run check, including a genuinely empty fresh sample, and every useful partial same-run market retain the original zero-SQL path. Only an unusable, empty plain envelope may consult the existing cache reader. Arrays retain the legacy result. The caller's existing source-health admission must allow the existing N12 500-read projection, with zero projected writes. This is conservative headroom modelling, not an actual native cost bound or a new grant.

The fallback performs at most ONE existing indexed cache SELECT, creates no schema, and returns before every provider/day/whole reservation or transport path. It may reuse only a positive `CLOSED_BOUNDED_SAMPLE` accepted by the unchanged exact cache validator. Missing, negative, foreign, stale, future or malformed cached material never becomes a zero fact or triggers HTTP. Admission refusal, missing admission, pre-existing unknown usage and absent DB stop before this read. A read failure preserves the original same-run refusal plus a technical failure diagnostic and every native unknown. A valid fact already returned by a read remains available if that read's native accounting becomes unknown; no subsequent SQL or transport is authorized.

Original evidence IDs, market, units, source/observation/first-known/expiry clocks, original cache receipts and selection policy remain unchanged. Reuse has zero current HTTP and `check_completed:false`; it is never a new strict-manual fresh check or body-completion ACK. Original same-run refusal receipt statuses remain in the technical fallback diagnostic. No score, weight, threshold, form, source quota, manual reserve, shared envelope or admission policy changes.

ONE export `runHtxEmptyEnvelopeCacheConnected({runtime_root,baseline_runtime_root,repo_root})` will be prepared, not registered or executed. Both runtime roots must be distinct actual assembled FULL `src` trees. The baseline differs only by the actual old collector; exact source pins are checked before module imports. The case will use actual collector, existing cache reader, route accounting, block consumer and manual/approved Telegram renderers. Controlled cache/fetch/counter fixtures are explicitly separate from the retained canonical rendering template. No native cost, native occurrence, current source coverage or delivery is qualified.

Twelve prepared CONTROLLED groups:

1. Usable full/partial futures/partial spot and genuinely empty same-run responses preserve the original zero-SQL result.
2. Empty objects, null market wrappers and foreign market wrappers recover only the exact positive cache.
3. Failed or unusable same-run payloads recover that exact positive cache without a new provider fallback.
4. Cache absence preserves the original refusal.
5. A cached negative/failure cannot replace a missing fact with zero.
6. Foreign-asset cache is refused.
7. Expired cache is refused.
8. Future cache clocks are refused.
9. Missing/denied admission and pre-existing unknown usage perform zero SQL/HTTP.
10. A failed cache query preserves the refusal and native unknown without another query.
11. A valid positive cache remains available after that read reports unknown usage, without additional work.
12. Legacy omitted-envelope cache behaviour and source facts remain unchanged.

The positive recovery must pass through actual route accounting (`actual_http:0`), N12 block consumption and rendering with the original evidence IDs/clocks. The strict-manual audit must not treat reuse as a fresh acquisition. The new SELECT delta is declared separately from unchanged SQL templates, and native rows-read costs remain NULL. The accepted 556, 584 and all older cases are not invoked.

The coordinator explicitly permitted this existing guarded-read delta in a TEXT proposal and one unexecuted case. The source does not apply the runtime patch. Central review must approve the concrete read/admission scope before ONE future combined execution.
