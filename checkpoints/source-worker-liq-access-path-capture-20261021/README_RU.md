Координатор готовит три новые inline-функции в существующем runner. Они связывают разрешённый естественный scheduled запуск с исходным единственным input batch realized sidecar, сохраняют исходный результат и после projected sidecar могут сделать два отдельных чтения: определения текущей таблицы/индексов и EXPLAIN исходного SQL с теми же фактическими параметрами. Config selector сам не grant: требуются настоящий parent receipt/day admission, текущие counters, postCritical reserve и отдельный statistics HTTP admission перед каждым I/O. Эти реальные условия и размещение callsites принадлежат центральной интеграции; callable не импортирует runner/main.

Будущий сценарий получает BOTH ENDsrc у двух полных разных assembled trees: 615 файлов каждого parent, 614 одинаковых, различается только существующий runner. Closure передаётся явно: process, контролируемые Date.now И new Date, Buffer, crypto, memory fs, actual evaluateWithinRunReservation, Response. Полный parent runner не исполняется.

Исходные два SELECT извлекаются только в памяти будущего центрального процесса из unchanged hash-pinned private sidecar по двум известным SHA. Private module не импортируется и не вызывается, старый компонент600/599 не запускается. В Git нет исходного private SQL, actual native params/DDL/JSON/ZIP. Синтетические две event rows, schema и usage metadata созданы для новых checks. Actual RemoteD1 batch выполняет исходные SELECT один раз в каждой отдельной CONTROLLED fixture; затем new function делает не более двух отдельных all RPC через local bridge в actual Node LocalSQLite.
