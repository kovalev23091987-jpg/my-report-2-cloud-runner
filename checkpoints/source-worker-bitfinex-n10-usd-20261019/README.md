# Bitfinex XMR: новый сохранённый ценовой контекст USD

Найдена конкретная возможность N10, а не новый рыночный запрос: в сохранённом Bitfinex run38138608166 последние15 native1m свечей XMR присутствуют все и содержат322 реальные сделки. Открытие532,67→закрытие533,61 **USD**, high534,26/low532,51; окно `[1791720060000,1791720960000)`, исходное final received1791720977667. OPEN/CLOSE/HIGH/LOW каждой выбранной минуты совпадают с first/last/max/min фактических execution prices. `native-price-witness.json` сохраняет новый результат воспроизведения.

Текущий `htx-technical-structure.mjs:deriveN10ReusedVenuePathEvidence` возвращает для этого input пустой список: BITFINEX отсутствует в `VENUE_PRICE_ROOTS`, а существующая ветка предназначена для `quote=USDT` и сравнения с HTX. Этот отказ безопасен для прежнего контракта. Потеря полезности — отсутствие отдельного ограниченного контекста цены **внутри Bitfinex/USD**. Новый код не ослабляет старую USDT-ветку и не считает USD равным USDT.

Важная особенность оригинала: за4h сохранено232, а не240 native candles. Существующий N05-контракт сверяет наличие свечи и реальных сделок в каждой из240 минут;8 минут без сделок не становятся ценовыми барами. Новая модель требует именно15 последовательных **реально возвращённых** свечей в конце окна, без заполнения/переноса цены. Никакого утверждения о240 native OHLC строках нет. Другие сохранённые Bitfinex примеры не объявлены пригодными N10.

Новый pure `bitfinex-n10-price-path.mjs` читает уже собранный payload существующего N05 (`version/observed_ts/catalog/candles/trades/trade_receipt`), проверяет исходные часы, expiry, точный рынок/актив/USD, bounded raw trades и соответствие N05 descriptor пересобранному из raw. Пересборка — необходимая привязка входа **нового** ценового consumer, а не повтор старой квалификации N05. Дополнительно проверяются фактические OPEN/CLOSE всех15 минут, которые прежний flow-контракт отдельно не доказывает. Объём свечи остаётся native base volume; source-native quote-volume не появляется.

Исходные тела и receipts — уже сохранённые originals38138608166 и catalog38138499328. В тесте из них собирается **CONTROLLED existing-cache envelope**; payload hash вычисляется из фактического parsed body тем же способом, что текущий producer. Это не фактический D1 read/write ACK. Исходный first-known не меняется при переиспользовании. Новый helper не читает БД, не выполняет HTTP и не даёт runtime admission.

`comparison_status=WITHIN_BITFINEX_USD_ONLY`, `htx_comparison:null`, `exact_price_usdt:null`, FXfalse, score0, direction/riskNULL, coverage0, entry/targetfalse. Нет нынешнего охвата105, текущего HTX spot, native crossvenue agreement, изменения стратегии, общей формы или фактической доставки. Старый STRK/Backpack отрицательный поиск и принятые qualification/runtime suites не повторялись.

`shared-integration-proposal.md` описывает конкретные producer/N10/formatter changes для координатора. Production imports отсутствуют, shared-файлы не изменены. Одна новая affected-проверка запускает только `bitfinex-n10-price-path.test.mjs`, плюс происхождение/scope/syntax. Old69/40/connected25+1/Bitfinex suites/probes не запускаются. Проверка не измеряет native CPU/heap/cost/day capacity. Полный TAP и хеши сохраняются рядом; дальнейшее внедрение — отдельный центральный пакет.
