# Конкретное предложение координатору

Добавить только отдельный нейтральный within-Bitfinex/USD контекст, сохранив прежнюю N10 USDT crossvenue-ветку и её4 SQL groups. Новый pure helper уже работает с конкретным историческим XMR input; его runtime integration остаётся false.

1. В `bitfinex-native-flow-collector.mjs` сохранить ссылку на уже созданный `{version,observed_ts,catalog,candles,trades,trade_receipt}` в private nonenumerable capsule **возвращаемой копии** компонента. Точка — после `components.push({...component,...})` и создания payload, перед optional native-cache write. Скопировать actual original observed/expires; не класть capsule в payload/serialized component. Для старого cache HIT использовать только существующие `cache_observed_ts/cache_expires_ts` после удаления wrapper полей. Несовпадение clocks даёт отсутствие нового price-контекста, не потерю принятого N05. Native-cache payload, INSERT и число старых SQL/HTTP не менять. Проверка этого предложения в native runtime здесь не выполнена.
2. В начале `loadN10ReusedVenuePaths` отдельной memory branch, **до** группировки прежних4 SQL groups, передать capsule+component в `inspectBitfinexN10CachedPricePath`. Не добавлять Bitfinex в `VENUE_PRICE_ROOTS`: существующий контракт сравнения USDT должен остаться прежним. Новая branch требует существующего approved105 scope и отдельно уже полученного свежего точного HTX spot input; его отсутствие/устаревание не даёт runtime-подключения. Архивный owner15 список не расширять до нового глобального запрета. HTX input подтверждает допустимость существующего spot-маршрута, а не USD/USDT FX или согласие цен. Для исторического XMR нынешний HTX input UNKNOWN.
3. Использовать отдельный N10 metric, например `CLOSED_15M_BITFINEX_USD_PRICE_CONTEXT`, с root `BITFINEX_OFFICIAL_SPOT_CANDLES`, `quote/unit=USD`, исходными source/first-known/expiry и producer-receipt trust. Consumer проверяет через точные raw/capsule либо отдельно согласованный compact producer validator. Данный helper проверяет только полный вход; не выдавать digest дескриптора за независимый native ACK. Общая source allowlist и accounting меняются координатором только вместе с этим consumer; score/coverage/directional vote/target/ENTRY остаются0/false.
4. `block-result-context.mjs`/существующий formatter: добавить одну описательную строку «Цена за15минут наBitfinex: … USD; данные этой площадки, без пересчёта вUSDT и сравнения сHTX; баллы/цели/вход этим не меняются». Текст чисел берётся только из valid new DTO. Не добавлять HTX close gap, direction agreement или сумму объёмов разных валют. Это предложение строки существующего дополнительного контекста, не изменение утверждённой общей формы отчёта. Перед объединением нужна одна общая новая проверка именно затронутой producer→consumer→manual/TG цепочки.

Новых provider calls/SQL эта memory-схема не требует относительно уже собранного N05, но фактическая native стоимость/CPU/heap/wire и достижение consumer/SENT пока не измерены. Нельзя занимать пятый SQL group, вытеснять старые факты, продлевать TTL или скрывать unclosed native usage. Сохранять первичные N05/N12 факты при позднем optional-cache failure. Старые native qualification suites повторять только при конкретном изменении затронутого пути.
