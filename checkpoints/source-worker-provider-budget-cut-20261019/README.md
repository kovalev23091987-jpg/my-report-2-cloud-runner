# Сохранение уже возвращаемых локальных budget cuts

В existing live path есть полезные скаляры, которые сейчас теряются до completion493. `provider-reference-cache.mjs` уже читает `usage.attempts` для дневного preflight и, у CoinGecko, `rolling.units` для минутного preflight. `reserveProviderMinuteUnits` уже возвращает `rolling_units/cap/reserved_units/allowed` после своих существующих SQL. Успешный minute reply затем отбрасывается, а reader summary оставляет общий `PER_TRANSPORT_RESERVED`.

Это **локальные project ledgers**, а не остатки аккаунта провайдера. Day preflight, day reservation reply, minute preflight и minute reservation reply имеют разные cut/смысл и не складываются. Конкурентные callers могут изменить состояние между SQL. Фильтр `query_window_end_ts` — существующий `readTs`, переданный в запрос, не точный момент native исполнения; новый `captured_ts` фиксирует только последующий локальный приём скаляра. `returned_allowed` описывает старый вызов и не даёт нового допуска.

Предлагается один текстовый patch пяти существующих targets. Optional synchronous callback сохраняет только разрешённые скаляры из **уже выполненных** операций CG/CP sector reader. Данные идут в invocation-local runner memory и отдельное техническое поле existing completion context. В source collector/cache/canonical/evidence/fingerprint и аналитический вывод они не добавляются. Callback throw не меняет прежний return, transport/reservation или SQL. Никаких новых чтений, резервов, refunds и provider HTTP.

Это carrier успешного existing completion493. Если invocation упал раньше записи completion или был перезапущен, in-memory observations не считаются сохранёнными: нет новой durable ingress/failed-run записи или reconstruction через cache.

Capture допускает только два source id (`COINGECKO_SECTOR`, `COINPAPRIKA_SECTOR`) и exact root run при чтении. Сохраняются максимум16 событий, каждое до1024UTF8bytes; целая проекция до16384bytes, overflow/invalid/foreign-run явные. Это ограничения сериализованной диагностики, **не** полный JS RAM/CPU/native-wire/daycapacity bound. Переполнение диагностическое: исходные факты, reservations и запросы не удаляются и не меняются. Частичное покрытие имеет `all_run_observations_complete:false` даже без overflow.

Новые поля не включают URL/body/API keys/SQL strings/params/errors. `reference_key` — уже существующий hash ключ, `route`/status — ограниченные коды. Cache HIT не создаёт текущих budget observations и не наследует старый cached admission как новый срез. Отсутствующие/нечисловые counters остаютсяNULL, а не measured0. Неизмеренный native unknown count остаётсяNULL: прохождение существующего `nativeSourceUsageUnclosed` guard само по себе не делает отсутствующий usage instrument измеренным нулём.

**Не меняютсяNULL** в `provider_day_month_rolling60s_headroom`, `manual_provider_reserve_headroom`, provider account balances, month headroom и actual manual-held reserve. CG configured32 protected attempts и cap224/256, CP monthly module bounds/official20k — policy, а не текущие held/account balances. Новый carrier не объединяет CP sector с identity role или иных consumers и не покрывает все providers/day/month/manual. CP sector path здесь не выполняет minute ledger: такие поля не досоздаются. Никаких caller grants из111 logical slots,0SQL metadata или старых потраченных резервов.

Сохранённые оригиналы задают границу, а не ретроспективный выдуманный budget. В historical391236 receipt реально присутствует HTX minute helper reply1/1/cap6; это не текущийCG/CP счётчик. В actual392406 completion provider/month/manual поляNULL, numeric CG/CP cuts не сохранены. Восстановить их этим patch нельзя: он сохраняет только будущие уже возвращаемые observations в том же invocation. Exact refs/hashes/pointers и ограничения — `saved-budget-witnesses.json`.

Одна новая affected qualification использует CONTROLLED DB/helper replies и оба exact reader варианта: original/proposed. Проверяет равенство payload/summary/SQL/params/HTTP/reservations, отказы/unknown/cache hit и cache-write bytes, callback exception, nullable/invalid/overflow/privacy/root binding. Это не реальные SQL/HTTP и не native CG/CP account balance. Старые493/31/18/52/12/2084 suites/probes не запускаются. Временные runtimes удаляются после проверки; production/shared checkout не изменён.

Shared integration и дальнейший actual acceptance — у координатора. `central-entry-plan.md` описывает ровно этот affected delta. ENTRY idea-followup и physical-storage tests остаются отложенными до отдельной прямой команды владельца; этот пакет относится только к активному направлению budget/source diagnostics.
