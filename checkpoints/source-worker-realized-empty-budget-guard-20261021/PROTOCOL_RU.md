# Проверка бюджета в пустой ветке realized-LIQ

Протокол записан до нового proposal и callable. Координатор прямо поручил этот отдельный пакет после статического контрпримера по уже разрешённому фрагменту `a56b7b9f…`.

В исходном модуле пустой нормализованный результат возвращается со статусом `CLOSED_NO_REALIZED_EVENTS` до общей проверки расходов. Новая логика должна применить к этой ветке те же три условия, что уже действуют после обработки выбранных контрактов: превышение `rows_read`, превышение `rows_written`, положительный `unknown_ops`. Пороговые значения, сравнения и расчёт дельты не меняются. При отсутствии снимка расходов сохраняется существующий `NULL`.

Единственный предполагаемый runtime target — `src/v3-realized-liquidation-sidecar.mjs`, 6995 байт, SHA256 `a56b7b9f2908648c19bfc4ff30f1d2f22bc202365eef1a1a7c858a20360e648a`. Исходные приватные строки и полный модуль не входят в этот пакет. Публичная часть содержит хеши target/якорей, новую ограниченную вставку и точный рецепт применения в приватной assembled-копии координатора.

Один новый export `runRealizedEmptyBudgetGuardConnected({runtime_root, baseline_runtime_root, repo_root})` будет подготовлен без регистрации и автоматического запуска. Оба runtime argument заканчиваются на `src`, относятся к разным полным фактически assembled деревьям после принятого kernel599 и содержат тот же parent runner. До application imports проверяются все файлы, исходный target и единственная разрешённая замена. Семантика предполагается только в одной будущей общей проверке координатора. Старые 16 групп, чтение четвёртого файла и принятые suites не вызываются.

Исходный полный after-SHA нельзя вычислить из ограниченного фрагмента. Его вычислит координатор из уже необходимой приватной assembled-копии. Новый callable независимо построит ожидаемые after-bytes из точного baseline и сравнит с candidate целиком. Это ограничение фиксируется явно, без дополнительной выгрузки исходного модуля.
