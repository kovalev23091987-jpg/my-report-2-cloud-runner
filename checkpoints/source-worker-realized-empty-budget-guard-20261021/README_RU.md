# Пустой результат realized-LIQ проверяет тот же бюджет

В исходном `a56b7b9f…` пустая ветка возвращает `CLOSED_NO_REALIZED_EVENTS` до существующей общей проверки расходов. Статический контрпример: два input SELECT вернули пустые данные, но измеренная дельта чтения составила3330 при лимите3200. Ветка возвращает `CLOSED` вместе с превышенной дельтой. Положительный `unknown_ops` проходит по той же ветке. Это бумажный контрпример, автор его не исполнял.

Предложение добавляет перед пустым возвратом те же три условия, которые уже действуют после непустой обработки. При отказе меняется только статус пустого результата на `BUDGET_ENVELOPE_EXCEEDED_FAIL_CLOSED`. Значения расходов и остальные поля сохраняются. Равенство лимиту допускается, как прежде. Отсутствующий или `NULL` snapshot сохраняет существующий `usage_delta: null`; это совместимость модуля, а не новый допуск родительского budget guard.

Публичный пакет содержит515байт новой вставки, target/anchor SHA и рецепт. Старой приватной строки, полного target, SQL/DDL из приватного чтения и исходного JSON/ZIP здесь нет. Полный before —6995байт/a56; ожидаемый after —7497байт. Полный after-SHA будет вычислен из реального приватного assembled baseline в центральной сборке. `connected.mjs` требует точного совпадения candidate со всеми сгенерированными after-bytes, включая хеш изменённого блока. Дополнительное чтение или выгрузка приватного модуля не требуется.

Единственный подготовленный callable:

```text
runRealizedEmptyBudgetGuardConnected({runtime_root, baseline_runtime_root, repo_root})
```

Оба runtime argument заканчиваются на `src`. Проверяются разные полные деревья по615файлов после принятого kernel599,614неизменённых файлов, parent runner14b6 и принятые producer/domain/migration pins. Синтетические таблицы нужны только для выполнения двух фактических input SELECT над пустыми данными в LocalSQLite. Сами SQL и bindings сравниваются между baseline и candidate. Счётчики расходов задаются контролируемо и не изображают native стоимость этих SELECT.

Проверка `status.startsWith('CLOSED')` воспроизводит чистое условие потребителя. Parent runner не импортируется и не исполняется. Полный pipeline, публикация, delivery, новый native admission и физическая ёмкость этим не квалифицируются.

При фактическом запуске coordinator получит один возвращаемый JSON и сохранит его до wrapper assertions или следующего компонента. Принятые16групп kernel599, прошлые suites и чтение четвёртого файла не вызываются. При ошибке сохраняются имена уже завершённых новых контролей; их нельзя механически переигрывать из-за поздней ошибки wrapper.
