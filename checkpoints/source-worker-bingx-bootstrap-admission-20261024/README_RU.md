# B01: допуск первого прямого снимка BingX

Конечная SOURCE-подготовка завершена. Проверены реальные функции общего D1/run/provider допуска и финализации. Исполняемый research-entry и affected callable пока не созданы: для него нет защищённой ROOT-конфигурации BingX, подлинного parent/run допуска и совместимого полного control-профиля. Это предусмотренная поручением остановка вместо fake boolean или подмены старого LIQ grant.

Первое найденное несоответствие ROOT уже принял: SQL=0 относилось только к capture/preparation scope. Полный будущий вход должен иметь отдельный положительный DB/admission/finalization budget до первого provider GET. Исходный план сохранён точными байтами; уточнение хранится отдельно.

Реальные reusable механизмы есть: общий daySUM с unknown/debt, native instrumented DB, generic daily/minute reservations, local wholeHTTP, bridge compatibility5+4GET и finalizeRunUsage. Но они не являются готовым разрешением BingX. Generic reserveRunBudget не делает atomic sharedSUM admission; generic daily/minute функции принимают имя/предел от caller. LIQ provider admission пишет LIQ allowance tables, host allowlist не содержит BingX, а старый research workflow запускает только PumpGlass/VIKE/Hyperperps. Их не переименовывали и не обходили.

Точный требуемый контракт ROOT — root-configuration-required.json, порядок входа — execution-order.json, исходная цепочка — existing-chain.json. Показаны actual signatures, ограничения и необходимые независимые привязки. Резервы всех families, unknown, nextfull59000R920W, manual24 и control40 остаются защищены.
