# Исходное время доступности составного N12

Новый неиспользуемый pure helper `n12CompositeFirstKnown` возвращает только число или NULL. Shared runtime не изменён: конкретный патч лежит в `shared-integration.proposed.patch`, основание — connected Kraken head `069447c2dadbf6361eb1fdfb59b4cd9ec749b78b`. Координатор применяет его отдельно. Frozen504/505/507/509/511 не менялись.

В текущем `block-result-context.mjs` `contextComponentOrigins` сохраняет исходные часы всех выбранных записей, а `consumeBlockResultContext` оставляет `source_ts`/`observed_ts` базовой строки. `validateEvidenceV2` отдельно отсекает `first_known_ts > decision_ts`, но максимума для всего составного текста нет. Это не доказательство look-ahead в текущем runtime.

В сохранённом NIL `S392:NIL-USDT:1792395207582` один N12 текст ссылается на3 evidence IDs, при2 валидных N12 фактах: базовый HTX first-known1792395162394 и два дополнения Bitget first-known1792395181364. Значит, полный текст известен не ранее1792395181364, на18970мс позже внешнего observed HTX. Все входы известны до кандидата. `nil-original-origins.json` — точное извлечение одной сохранённой manual receipt из ZIP frozen511; прежний69-case audit не выполнялся.

Единственное предлагаемое поле — `composite_first_known_ts`:

- Максимум **исходных** `first_known_ts` точного представленного набора. Даже одиночная представленная запись получает собственное исходное время.
- Входы: контракт, ожидаемые evidence IDs, соответствующие `component_origins`, явное исходное `decision_ts`. Нужна полная взаимно однозначная связь без лишних, пропущенных, повторных или чужих ID/контрактов; каждый origin имеет `EXACT_SELECTED_EVIDENCE`.
- Часы — положительные целые безопасные числа: `source <= first_known <= observed <= decision`; expiry не раньше observed и decision. Неизвестные/невалидные часы и просроченные входы дают NULL. Приведения строк, подстановки0, `Date.now()` и обновления TTL нет.
- Равенство expiry/decision соответствует границе общего `validateEvidenceV2` (`expires < decision` означает истечение). Helper не разрешает использовать факт: более строгая проверка конкретного поставщика и прежний отбор остаются обязательными.
- Метаданные считаются при исходном формировании/воспроизведении выбранного контекста. Историю читать с её сохранённым полем и исходным decision; пересчёт с сегодняшним временем не должен стирать историческое время или обновлять first-known.

Патч добавляет поле к N12 context fact и к manual receipt. Для Telegram оно вычисляется заново **после** существующего фильтра фактически представленных компонент: если текст оставил только HTX, field отражает HTX, а не скрытые Bitget дополнения. Внешние source/observed, component clocks/windows/expiry, счётчики фактов, strategy/weights/формы/паузы/70 остаются прежними. Поле не является ENTRY, admission, причинным ACK, доказательством фактической доставки или полноты рынка. Неполнота метаданных не удаляет существующий текст или факт.

Новая общая проверка запускает только `current-generation/tests/n12-composite-first-known.test.mjs`, затем проверяет применение и синтаксис предложенного shared patch в временной копии внутри этого checkpoint. Старые normalizers/runtime suites, audit69, connected25/target1 не запускаются. Применимость/синтаксис предложения не выдаются за фактическую runtime интеграцию или Telegram-доставку. Результат — `verification.json` и полный `new-helper.tap`; хеши файлов — `manifest.json`.
