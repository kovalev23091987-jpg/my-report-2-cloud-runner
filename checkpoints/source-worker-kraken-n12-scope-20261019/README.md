# Точный предмет owner15 и новый полезный Kraken N12 вход

В сохранённом решении N15/hourly history внешний спот15 монет запрещён явно. Применимость этого решения как нового глобального отключения обычных N05 маршрутов однозначно не установлена: исходный `owner_scope` говорит о почасовой статистике, `OWNER_N15_TO_N16.n15_scope` — о N15, routing design — об архиве. AGENTS содержит более общую фразу внутри N15 абзаца; all-active owner contract требует полезного spot/futures coverage и исключения источника лишь в блоке, где доказана бесполезность. Поэтому пакет ничего глобально не выключает. Точные выдержки/хеши сохранены в owner-scope-and-reachability.json.

PAXG имеет в действующем коде точную versioned Ethereum binding и структурный путь к внешним token venue collectors. Проверка этого пути не вызывает collectors/provider/D1 и не доказывает фактический запрос или нарушение разрешения. Историческая typed matrix содержит изowner15 лишь USELESS с externalDEFERRED/0фактов0HTTP; её старые83 публикации не переаудированы.

Связанное полезное продолжение — готовый pure Kraken N12 normalizer/validator. Уже сохранённые ALGO/XMR страницы дают2/27 сделок за последние закрытые5 минут. Прежний N05 producer не возвращает из них N12 evidence. Новый модуль связывает exact pair/native identity, три ограниченные history pages максимум, последовательные cursors, wire/body hashes, parsed payload hashes, старые часы и выполненную native240 reconciliation. Текущий open-minute хвост не включается. Нейтральный bounded USDT контекст сохраняет buy/sell/imbalance и исходные ID; coverage0/score0/directional NULL/targetfalse/entryfalse.

Входная cache оболочка в проверке CONTROLLED и содержит точные исходные native payloads. Это не native cache ACK. SHA wire body из принятого оригинала сверяется с точными сохранёнными gzip bodies; parsed-page hashes считаются отдельно. Реальный кеш сегодняшнего producer ещё не хранит mapped trade receipts: без изменения централизованного producer cache hit не позволяет выдумать новый N12 факт. [Конкретное предложение интеграции](shared-integration-proposal.md) включает запись этих receipt полей в тот же cache payload, consumer allowlist и formatter без дополнительных HTTP/SELECT и без доказанного native budget/grant. Новые байты и реальное source→consumer→manual/TG ещё требуют центральной проверки.
