# Следующий потребитель тех же Kraken данных: N12

Точная недостающая роль: `collectKrakenFlow` возвращает components/receipts, но не строит N12 evidence из уже полученных исходных страниц. N054h flow и N10 path не заменяют отдельное описание последних фактических сделок. Новый `kraken-n12-bounded-trade-sample.mjs` подготавливает такой факт за закрытые5 минут с исходными taker сторонами/USDT и неизменным first-known. Это нейтральный bounded context: coverage0, directional/risk NULL, score0, без цели/входа. Из ALGO/XMR оригиналов38135993119 получены2/27 последних5m сделок; нынешние источники/запросы не приобретались. Числа и digest — в new-input-witnesses.json.

Только координатор меняет общие пути. Конкретные действия:

- `kraken-flow-collector.mjs/get`: для успешной исходной Trades страницы добавить `payload_sha256=SHA256(JSON.stringify(parsedPage))` и `next_cursor=parsedPage.result.last` к существующему receipt. Сохранить исходные wire `body_sha256`, exact request URL и `received_ts`; не выдумывать эти поля при старом cache hit.
- После N05 reconciliation вызвать `normalizeKrakenN12BoundedTradeSample` с тем же component и payload `{version,observed_ts,instrument,candles,pages}`, а также соответствующими Trades receipts. На новом cache write добавить эти receipts в уже существующий payload без отдельного SQL. Сохранить прежний900000byte limit и key/version/source/expiry. Если optional cache write не удался, уже полученный текущий N12 fact сохраняется, без повторной acquisition/reserve. Для старого cache без mapped receipts честно вернуть недоказанный N12 вход, не повторять provider query ради дополнения.
- Cache hit: построить тот же component из старых raw и тот же N12 normalizer, используя ИСХОДНЫЕ `observed_ts` и receipts. `now` применяется только для срока годности; не обновлять source_ts/first_known. Отказ/unknown native usage прекращает дальнейшие новые операции по существующим правилам. Запросы поставщику0 дополнительных; новых cache SELECT0; сериализованные receipts/selected rows добавляют байты, поэтому actual artifact/Worker cost ещё надо квалифицировать централизованно.
- `candidate-evidence-v2-runtime.mjs`: добавить `KRAKEN_SPOT_TRADES` в точный allowlist уже возвращённых внешних N12 rows. Shared source/accounting не должен считать дополнительный provider call по числу N05/N10/N12 consumers. Корень везде один Kraken, не3 независимых источника.
- Общие source projection/`block-result-context.mjs`: маршрутизировать `ACTUAL_KRAKEN_SPOT_TAKER_TRADES_BOUNDED` через новый validator и существующий формат bounded trade контекста с названием Kraken. Применить те же правила составной N05/N12 строки и сохранения всех evidence IDs, без суммирования разных окон4h/5m. Не менять headings, weights, общий direction или Telegram форму. Manual/Telegram payload используют один проверенный факт; native SENT требует отдельного exact run/message_id.
- Compact stored-fact validation пересчитывает числа/ID/raw_hash по сохранённым recent rows и producer receipt. Это не независимый wire retrieval/durable cache ACK: полный исходный body digest отдельно проверен в локальном пакете и должен сохраняться в provenance. Нельзя объявлять актуальное подключение, кэш или all105 покрытие по новому тесту.

Запрет owner15 в сохранённых исходных договорах явно описывает N15 HTX-only hourly archive. Фраза AGENTS шире по виду, но находится в этом же N15 абзаце. Обычный global N05 запрет из этих записей однозначно не установлен; новых общих отключений нет. PAXG route reachability сохранена отдельно от разрешения и фактического запроса. Ни этот пакет, ни новая Kraken функция не переопределяют owner15/текущие admission: ALGO/XMR есть в сохранённом HTX spot bulk, реальная текущая доступность не обновлялась. Если нужен общий scope, его уточняет координатор по указанию владельца; не урезать основной отчёт расширительным толкованием.
