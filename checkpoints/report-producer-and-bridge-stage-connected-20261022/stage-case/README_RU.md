# Stage-only: версия подготовлена, рабочий трафик прежний

Текущий release CLI не может активировать c327: действующая Paid-привязка принимает только7011/06603. Этот пакет готовит отдельный путь получить реальный immutable ID новой версии через один version upload, сохранив active/deployment/settings/Paid. Он нужен для дальнейшей квалифицированной совместимой привязки; текущий пакет её не меняет. Приоритет — текущий отчёт и Telegram, а не новая разработка native anomaly.

`stage-control.proposed.txt` добавляет только `stageCorrelatedSQLBridgeOnly({plan,adapter,guard,save,clock})` в существующий CLI. Старый qualified prefix16040B сохраняется полностью. `tool-with-control.proposed.mjs` — точная control-only композиция для сверки, ещё без ROOT network stageMain. ROOT добавляет network adapter, mode entry и связывает SHA всего combined CLI перед FIRST. Старые функции/режимы остаются прежними. Новый workflow flag `execute_correlated_cost_stage` defaultfalse; все прежние modes исключают его. Mixed-stage сочетание явно отказывает до control steps. Новый stage artifact — `audit-output/bridge-correlated-cost-stage/`.

Сначала проверяются текущая аренда/границы, exact active7011/06603, старые settings/crons/etag Paid pin, полные runtime fingerprints и отсутствие чужого dormant latest. До upload сохраняется intent с operation UUID/head/owner/request annotations и их хешем. ROOT adapter дополнительно сохраняет SHA полного фактического upload metadata перед POST; хеш annotations не выдаётся за хеш всего metadata.

Успешный результат — только `STAGED_OWN_VERSION_VERIFIED_ACTIVE_UNCHANGED`: известный реальный upload ACK ID, exact native metadata/id и latest/content/latest bytes c327, полные staged settings/runtime/binding fingerprints и post snapshot прежней active версии/deployment/settings/crons/etag. Reader заранее кэширует bytes immutableOLD версии и не приписывает ей body нового dormant latest. Native created_on может быть NULL или иметь сдвиг часов; это отмечается отдельно, не используется как billing или ownership доказательство.

GET version/list не гарантируют readable annotations. При потерянном upload ACK выполняется только одно bounded observation; результат всегда `STAGE_ACK_UNKNOWN_OWNERSHIP_UNRESOLVED`, даже при совпавших хеше/времени и подставленных owner/annotations. Поля наблюдения не становятся собственным staged ID. Нет повторной загрузки, activation, DELETE, PATCH logging/settings, SQL, provider, invocation, MAIN/manual или Telegram. Остальные незакрытые случаи возвращают `STAGE_ONLY_NOT_CLOSED`; незакрытый post snapshot не выдаётся за сохранённое состояние.

Guard перед каждым методом задаёт30с минимальной аренды и CF/GH headroom24/28 до snapshot,16/20 до upload,10/12 до readback,5/6 до post snapshot. ROOT CLI отдельно требует10мин до начала, а каждый фактический CF attempt выполняет собственный guard/admission. Общие40CF/40GH, whole164 и manual24 не повышаются. Сырые settings/modules/secrets не сохраняются: proof ограничен16KiB и whitelisted fingerprints/identity/clock/status. Нет автоматической reconciliation или восстановления старого unknown1.

Один новый `runBridgeStageOnlyConnected({runtime_root,baseline_runtime_root,repo_root})`,7 групп/17 вариантов, автором UNEXECUTED. Аргументы — assembled ROOT618 pair,617 nonrunner равны; baseline уже SDKcab59/journaldc009, новый runner db6b — отдельный SOURCE пакет. До imports связываются полный inventory, unchanged old CLI prefix и exact core, production reader/metadata/Paid/helper pins. ROOT complete combined CLI SHA фиксируется внешним central scope; callable возвращает наблюдённый полный SHA.

Контролируемый CF adapter использует настоящие version-bound reader и metadata helper. В Git нет preimage реальных старых native settings для05120. Поэтому основной new control case компилирует точное actual core BODY с явно CONTROLLED ожидаемым Paid settings fingerprint; это только test dependency, не production override. Отдельно настоящий imported production export получает synthetic native settings и обязан отказать до upload. Test не заявляет, что synthetic fingerprints являются native Paid proof.

Новые группы: production pin refuses synthetic state; один known ACK/actual bytes/cache и NULL/skew clock; потеря ACK до/после upload с одним unowned observation; чужой dormant latest; drift code/full runtime/settings/deployment/latest; недостаток headroom/guard/save intent; workflow defaultfalse/exclusive условия проверяются как текст.
