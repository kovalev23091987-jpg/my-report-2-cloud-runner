# Доказательства полезного использования источников для 105 активов

Пакет связывает весь действующий реестр — 105 активов и 122 контракта — с сохранёнными фактами N05/N10/N12/N15/LIQ, реальными consumer-receipts и ручным текстом. Это конечная работа по новому поручению ROOT, отдельная от завершённого gate f55. Runtime, score, веса, формы, лимиты и исходные часы не менялись.

В 47 уже сохранённых отчётах найдены 93 разные аналитические публикации по 23 активам. Из них взяты 598 consumer-receipts: все 598 буквально присутствуют в ручном тексте того же кандидата; 597 связаны с evidence ID в его source-check. Один REMOVAL без block coverage исключён. Это датированные наблюдения, а не нынешнее одновременное покрытие 105 активов.

Строки для остальных активов не удалены и не помечены как «источников нет». В matrix105.json для каждого актива отдельно приведены native-контракты, статическая цепочка, исторические маршруты, ссылки на факты/публикации/ручной вывод и граница доказательства. Исторические 58 origins, 72/103 и старые окна104 не перенесены в текущее полезное покрытие. Для BTR/DOS/GPS/PIPPIN/SKR/UB сохранена утверждённая политика UNKNOWN/NULL без score или deep grant; текущая доступность не выдумана.

Как читать пакет:

- matrix105.json — полный реестр и связи по активам.
- consumer-manual-links.json — исходный path/member/JSON pointer, точные head/cloud run/business run/publication/snapshot, source/observed/first-known часы, evidence IDs и literal manual match. component_origins сохраняет явно присутствующие market/window/quote поля. Отсутствующие единицы, окна и первые часы остаются NULL; они не восстановлены из текста.
- retained-provider-facts.json — 79 строк с совпавшим asset binding из старых публичных CoinBoss/Swolecharts payloads. Это payload, а не независимая повторная нормализация или действующее подключение. У 22 других строк нет подтверждённой response identity, у четырёх CJK вернулся BTC; старые исключения переиспользованы и не названы новым дефектом. У CoinBoss «USD» отдельно помечен как контракт normalizer, а не выдуманное поле исходного тела. Модели не считаются реальными позициями или независимыми площадками.
- selected17-liq-mapping.json — все 17 сохранённых HTX event rows: 13 ZEC и четыре BTW, точные исходные часы, row hashes и реально возвращённые aggregate targets. Нативные числовые строки и SQL params в Git не перепечатаны. В исходном результате reference_price_closed=false; эти события не превращены в будущие уровни или доказательство ручного LIQ-вывода.
- source-priority-weekly.json — сохранённые очереди каждого кандидата отдельно от нынешнего health. Статический код сортирует альтернативы внутри прежней роли и сохраняет общий N05/N12 бюджет; это не экономия и не новый grant. Weekly не применён, MAGIC106 отложен, действующий реестр105/122 сохранён.
- chain-bindings.json — реальные текущие пути функций, строки-якоря и полные SHA source→consumer→manualformatter. Это статическая достижимость; её нельзя смешивать с фактом конкретной публикации.
- provenance.json и verification.json — входные полные file/raw hashes, fixed base, собственный scope и результаты проверки структуры документа, без semantic PASS.
- next-original-input.json — ровно один конкретный недостающий original envelope.

Новый дефект потери данных/fallback/priority по этим входам не установлен. У RLC N12 в публикации PUB:229ec5c80bf4fae38547b1319d1c16320d394ad0, run38707417112, ручная строка содержит EV2:2264f5fb4bf32135ea872e71126669ea7a0ac77ee656770212f1bad7c53632fd, но этот ID отсутствует во всех source-check того же сохранённого кандидата. Следующий необходимый вход — уже сохранённая исходная normalized EvidenceV2 row вместе с её producer receipt/body для этого ID, того же run/snapshot и исходных часов. Новый запрос к рынку или пересчёт старого наблюдения это доказательство не заменяет. Если оригинал не сохранился, результат остаётся «недоступен». Это закрывает только одну границу RLC, не все105 и не остальные отсутствующие source bodies.

Поэтому speculative patch, callable, framework или PR только ради отсутствия не создавались. Это полезный evidence package с одной точной следующей точкой. Повторные аудиты549/551/558/559/564 и исчерпанные CURRENT67/Gate/SQL counterexamples не запускались. Node/import/syntax/tests/appsemantics/SQL/SQLite/gitapply, provider/CF/native/MAIN/manual/Telegram — 0. Проверка хешей, JSON-связей и буквального сохранённого текста не исполняет formatter и не выдаётся за его тест.

Пакет подготовлен в собственной ветке и только в своём checkpoint prefix. ROOT получает immutable Git-объекты обычным чтением; заблокированная исходящая отправка не повторяется и не обходится. Общая проверка, интеграция, фактический новый отчёт и доставка остаются у ROOT. REPORT+Telegram FIRST, full5/full17, обе OWNER deferrals, Paid/cursor/unknown/reserves сохраняются открытыми.
