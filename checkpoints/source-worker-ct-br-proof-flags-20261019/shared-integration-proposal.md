# Предложение координатору: переиспользовать Kraken в N10

Готовый чистый provider-модуль: `current-generation/files/src/kraken-n10-price-path.mjs`. Production imports отсутствуют. Он не читает БД, не запрашивает поставщика и не формирует score/вход/цель. `inspectKrakenN10CachedPricePath` возвращает фактический путь цены на самой Kraken. `prepareKrakenN10RuntimeInput` дополнительно требует свежий уже полученный точный HTX spot reply для этого окна и сохраняет owner15 exclusions. Положительный ответ последней функции означает пригодный вход для общего конструктора, а не native admission или внедрение.

Сохранённые ALGO и XMR имеют 241 исходную строку OHLC: 240 закрытых минут и текущую незакрытую минуту. Последняя исключается явной границей окна, `result.last` остаётся курсором. Путь последних15 минут содержит соответственно2 и144 исходных сделок. Модуль заново связывает исходные свечи/страницы с принятым N05 component, проверяет count/base/VWAP и дополнительно OHLC каждой активной минуты по исходным ценам сделок. Холостая минута сохраняет предыдущую цену. При отсутствии сделок в последних15 минутах путь не допускается. Инструмент, native identity, USDT, 240 grid, старые часы, cache expiry и hashes обязательны.

В свежем main сохранённые HTX bulk rows для ALGO/XMR показывают существовавшие `algousdt`/`xmrusdt`; обе монеты отсутствуют в owner15. Это исправляет прежнее UNKNOWN только в части сохранённой политики/исторического наличия пары. Актуальная native доступность на19Oct неизвестна. Нельзя использовать старый bulk для runtime: модуль требует точный свежий `htx_spot_kline` с15 закрытыми минутами и активностью. В тестах этот HTX reply КОНТРОЛИРУЕМЫЙ. Реальная HTX свечная серия на окне Kraken и ACK записи N05 cache здесь не сохранены.

Конкретное объединение общих файлов, только после review координатора:

1. `htx-technical-structure.mjs`: включить KRAKEN в `VENUE_PRICE_ROOTS` как `KRAKEN_OFFICIAL_SPOT_CANDLES` и квалифицировать через существующий `qualifiedKrakenNativeComponent(c,KRAKEN_PUBLIC_TAKER_REFERENCE)`. В `loadN10ReusedVenuePaths` передать уже полученный `htx_spot_kline` вызывающего pipeline. Пропускать owner15 и отсутствие свежего spot до SELECT; не добавлять запрос spot ради этого маршрута.
2. Для группы Kraken сохранить source `N05_OFFICIAL_FLOW:KRAKEN`, key **`NATIVE_FLOW:${contract}:${end}`**, original `observed_ts` и `expires_ts=end+300000`. Пропустить через `prepareKrakenN10RuntimeInput`. Передать его15 raw price bars и проверенный240 grid в существующий общий конструктор N10. Не подавать native raw dict или241 open-inclusive row в старый parser, ожидающий240 arrays.
3. Общий конструктор/верификатор должны связывать выбранные15 bars, проверенный N05 component и полный cache payload hash из provider preparation, а также оригинальные часы/точный HTX spot presence. Compact receipt доказывает связность созданного факта, но не независимый durable cache ACK. Не принимать дескриптор, boolean `present` или один digest вместо повторного разбора сохранённого payload на producer boundary.
4. Межбиржевое сравнение разрешать только с **реальным существующим HTX futures `15m` window** при точном совпадении start/end и корректном OHLC. Без него полезный within-Kraken price path остаётся отдельным ограниченным фактом; `HTX_SAME_WINDOW_ORIGINAL_NOT_SUPPLIED` не превращается в agreement. Не конструировать HTX из Kraken в production.
5. В `block-result-context.mjs` добавить только `KRAKEN:'Kraken'` в map существующей строки `CLOSED_15M_INDEPENDENT_PRICE_PATH_CONTEXT`; сохранить утверждённую форму строки, нейтральные значения и действующий verifier. Проверить одну связанную цепочку реального cache→producer→context→manual/Telegram payload. В этом PR общий formatter/constructor не изменены, финальная доставка отсутствует.
6. Сохранить группировку по venue, порядок существующих компонентов, `slice(0,4)` cache-read ceiling и `nativeSourceUsageUnclosed` до каждого нового SQL/после чтения. Включение нового вида группы может добавить фактический SELECT внутри потолка4: **не объявлять0SQL и не считать это новым admission**. HTTP0 за счёт reuse, никаких новых source caps/reserves/retry/FX. При отказе сохранить уже полученные пригодные факты/исходные часы и продолжить только разрешённый fallback.

Ожидаемая новая полезность: ещё один независимый физический корень цены для точного native актива с HTX spot, когда уже квалифицированный N05 Kraken cache действительно существует и совпадает окно HTX. Сейчас доказан исторический raw путь двух монет; текущее all105 покрытие, фактический cache hit, межбиржевое agreement и Telegram этим не доказаны.
