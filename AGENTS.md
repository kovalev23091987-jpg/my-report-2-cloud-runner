## Перед любым изменением, тестом, deploy или live call

- Прочитать свежий GitHub `main` ref, phase и fence одним пакетом; затем текущие статус, точку продолжения и generation по тому же SHA. Чужой активный owner, lease или fence запрещает действия. Получить собственный ограниченный CAS lease на свежем main и прочитать его обратно. После работы освободить только свой lease. Не продолжать после истечения lease.
- Выполнять крупный связанный пакет и одну общую проверку затронутых цепочек. Сначала использовать сохранённые факты с исходными часами. Новые HTTP к источникам — только для рассчитанных отсутствующих фактов после admission; не повторять завершённые probes, тесты или MAIN без нового дефекта. Не сбрасывать и не обходить source caps, reservations, общий 164 HTTP/D1 budget и 40 минут полного отчёта / 5 минут сборщика.
- Различать каталог, структурный маршрут, полезный факт, участие в consumer, отображение, ненулевой вклад и точную фактическую доставку. HTTP 200 и две рыночные компоненты одной биржи не считаются двумя независимыми первоисточниками. Результат принимается по exact run/head/snapshot/source clock/artifact digest и фактическому пути источник → факт → consumer → ручной отчёт/Telegram. Не объявлять SENT без того же run и `message_id`.

## Текущий объём и ограничения

- Рабочий HTX crypto universe: 105 активов, 122 контракта, 17 inverse/delivery ограничений; старые 102 и 104 относятся к истории. Отбор 105 → до 24 → две монеты и обе формы отчёта проверять совместно. Наблюдение за обоими рынками нужно там, где это полезно; N11 — проверка именно фьючерсного стакана и освобождён от спотовой метрики. Если только одна сторона подтверждена, разрешён явно ограниченный информационный вывод, без придуманного общего согласия.
- Для спота и фьючерсов по всем применимым блокам сохранять исходное время каждого рынка. Стремиться к одновременным снимкам (ориентир 30 секунд); приблизительно 10 минут с допуском 30 секунд на технический разброс — крайний предел только для явно помеченного ценового контекста без сигнала, веса и разрешения входа. Старую архивную пару с разрывом около 10 минут маркировать как пару с задержкой, не как синхронную. Для последних сделок сохранять их собственную более строгую свежесть и неполную выборку, для свечей и потоков требовать совпадающие закрытые окна. При большем разрыве показывать факты обоих рынков отдельно без ложного спреда или согласия направлений. Две компоненты одной биржи не образуют два независимых первоисточника. Ликвидационные уровни существуют только для фьючерсов; спот даёт лишь ценовой контекст.
- При сравнении синхронных цен проверять также встречные bid/ask. Если котировки перекрываются, разницу их середин можно назвать только справочным числом; не объявлять спот или фьючерс достоверно дороже или дешевле по такой паре.
- Для новых LIQ-отчётов показывать не более трёх будущих уровней выше и трёх ниже в ручном отчёте и Telegram; размеры и тип каждого уровня обозначать честно. Внутренние исходные факты и сценарии сохранять полностью для статистики; старые опубликованные сообщения не переписывать. Если подтверждены только расчётные зоны, не выдавать их за фактические позиции.
- Новое указание владельца 13.10.2026: принцип LIQ распространить на **все действующие блоки**, не считая LIQ уже завершённым. Если нынешних источников недостаточно для широкого полезного покрытия, искать новые бесплатные маршруты и включать их только после проверки реальных данных для наших монет и роли в отчёте.
